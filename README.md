# 大阪房产软件 · 本地版 MVP

> 目标：**先把"取到数据 + 下载到本地"这条链路跑通**，其余（查询、推送、上云）在后面的事。
> 全部数据都留在你自己的机器上，不依赖任何云服务。

## 一、三步验证（你要测的三件事）

### 第 0 步：启动

```bat
:: 推荐：直接双击 start_mvp.bat（服务日志会写到 data\logs\server.log）
python serve.py
```

浏览器打开 **http://127.0.0.1:8765**

> 首次装依赖：`pip install -r requirements.txt`
> （用 Edge 的话不用再 `playwright install`，直接复用你电脑上的 Edge）
>
> **服务必须一直开着。** 运行服务的那个黑窗口一旦关掉，网页上点任何按钮都会失败。
> `start_mvp.bat` 已开启崩溃自动重启（最多 5 次），意外退出的完整堆栈会写进
> `data\logs\server.log`，方便定位。

#### 遇到「请求失败 / Failed to fetch」怎么办？

**结论先行：这不是你操作错了，是本地服务已经停了。** 浏览器连不上
`127.0.0.1:8765`，所以在网络层就失败了，压根没送到程序里。

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面顶部出现红色横幅「本地服务已停止」 | 服务进程已退出（黑窗口被关 / 被杀 / 崩了） | 双击 `start_mvp.bat` 重启，再按 F5；横幅会自动消失 |
| 弹窗写「本地服务已停止，连不上 127.0.0.1:8765」 | 同上 | 同上 |
| 启动时提示「端口 8765 已被占用」 | 服务其实已经在跑了 | 直接打开 http://127.0.0.1:8765 ；或换端口 `python serve.py --port 8766` |
| 启动就闪退 / 起不来 | 依赖缺失或代码异常 | 看 `data\logs\server.log` 末尾的堆栈 |

页面每 4 秒会打一次心跳（`/api/ping`）。服务恢复后红色横幅会**自动消失**，不用手动刷新。

## 一之二、🔴 怎么切到"真实抓取"（就是点四下）

默认是**离线演示模式**（内置样例数据，不连网，不碰 REINS）。切到真实抓取，在**仪表盘第一块**按顺序点：

| 序号 | 按钮 | 会发生什么 | 成功标志 |
|---|---|---|---|
| **①** | **切换到真实抓取** | 把 `config.yaml` 的 `app.mode` 改成 `live`（不用你手改文件） | 页面刷新后，模式显示"真实抓取（REINS）"，并多出 ②③④ 三个按钮 |
| **②** | **环境自检** | 不连 REINS，只验本机条件：Playwright 库、Edge 能不能被自动驱动、会话文件在不在 | 三个 ✓；"登录会话文件"第一次必然 ✗（还没登录，正常） |
| **③** | **重新登录** | **弹出 Edge 窗口 → 你自己输账号密码** → 登录成功后程序自动存会话（最多等 5 分钟） | 提示"✓ 登录成功，会话已保存"；`data/session.json` 生成 |
| **④** | **试跑（1 轮 / 最多 3 条）** | 真实连 REINS，**只跑 1 个查询轮、最多抓 3 条详情**——最小请求量 | 实时日志出现"✓ 会话有效，已进入検索条件入力页"→"结果 N 件"→"已入库" |

④ 通过后，再点「第二步」的 **▶ 手动更新** 跑完整一轮（`config.yaml → crawl.max_items_per_run` 默认 200 条）。

> **为什么要"试跑"**：真实抓取是**第一次在真机上跑**，选择器是按截图写的。先花最小代价确认
> "能登录、能查到、能落到本地"，比一上来全量抓稳妥得多——既省时间，也不至于因为异常行为惊动对方风控。

> **③ 是唯一需要你出手的一步，也是红线**：程序**绝不代输账号密码、不重试登录、不识别验证码、不换 IP**。
> 会话失效就停机告警，等人来处理。

**④ 如果报错**，大概率是"找不到元素 / 超时"，把日志里那行贴给我，我按真实页面校准选择器（这是预期内的第一次调试）。

每条房源之间的操作间隔默认 **1–2 秒**（`crawl.delay_range_seconds`，详见下方「抓取节奏」）；想更快可改小，想更稳可改大。

### 第 2 步：自动抓取一轮 → 数据落到本地

点仪表盘上的 **「▶ 手动更新（立刻抓一轮）」**。

一轮跑完，本地会多出这些东西（全部在 `data/` 里）：

```
data/
├── jproperty.db            ← SQLite：房源主档 / 快照 / 变更 / 运行日志 / 水位线
├── attachments/            ← 每个物件的 PDF 图纸（{物件番号}.pdf）
├── exports/                ← 当天 Excel（大阪房源_YYYYMMDD.xlsx）
├── daily/                  ← 按天 HTML 页（可离线看，解决 REINS 23:00 后打不开）
└── session.json            ← 登录会话（等同账号凭据，勿外传）
```

#### 抓取节奏（一条详情要多久？怎么循环？）

**核心循环（真实模式）**：每拉完一个房源的「详情页全字段 + PDF 图纸」后，程序**间隔 1–2 秒**就进入下一条，如此**不断循环**，直到本轮所有房源（含全部保存条件、全部分页）都更新完。

具体流程：遍历保存検索条件（01 土地+一户建 / 02 公寓）→ 每个条件翻页 → 逐行解析列表 → 遇到「新盘 / 还没详情」的房源就进详情页抓全字段 + 下载 PDF → 退回列表 → **间隔 1–2 秒** → 下一条。已存在且已有详情的房源只刷新列表字段，不进详情页、不加间隔。

- 这个**间隔**由 `config.yaml → crawl.delay_range_seconds: [1.0, 2.0]` 控制（单位秒，区间内随机）。
  - 想更快：调小，例如 `[0.8, 1.5]`；想更稳 / 更像真人：调大。
  - 改完重启服务（`serve.py`）即生效，不用动代码。
- **离线演示模式（demo）** 不联网、本地生成样例数据，瞬时完成，不受这个间隔影响。

> ⚠️ 节奏再快，两条红线不变：① 绝不代输账号密码 / 不识别验证码；② 会话失效立即停机告警。
> 间隔只是"两次操作之间的人工停顿"，不影响这两条底线；调太小会增加被风控注意的概率，请自行权衡。

### 第 3 步：更新机制 —— 定时 / 随机 / 手动

在仪表盘第三块「三种更新方式」里设置：

| 方式 | 怎么用 |
|---|---|
| ① **定时更新** | 选固定间隔 **1 / 2 / 4 / 8 小时** → 点「保存并启动自动更新」 |
| ② **随机更新** | 方式选「随机更新」，填随机下限/上限（如 1–3 小时）→ 每轮间隔在区间内随机 |
| ③ **手动更新** | 随时点「▶ 手动更新」→ **按你点击的当前时间节点立刻跑一轮** |

- 三种方式跑的是**同一套抓取管道**，只是"什么时候触发"不同。
- 只在 **07:00–23:00** 内执行（REINS 日本时间 23:00–次日 07:00 维护，年末 12/27–1/4 也关）。
- 只要网页开着，调度就在后台跑；**关掉网页就停**（这是 MVP 的取舍，正式版会做成常驻服务）。

## 一之三、账号管理 + 操作台（测试 / 真实下载）

### 账号管理（顶部导航「账号管理」）

把你的 REINS 账号**录入并本机加密保存**，之后可以一键自动登录，不用每次手工输。

| 功能 | 说明 |
|---|---|
| 录入 / 保存 | 会员ID + 密码，**Fernet 加密**存到 `data/credentials.json`（密钥 `data/.cred_key`，权限 600） |
| 显示密码 | 点「显示已保存密码」→ 在 localhost 下解密回填（用完可点「清空」） |
| 清空 | 删除已保存的账号 |
| 测试登录 | 用保存的账号自动填表登录，验证能否进会员页（不抓取） |

> ⚠️ 红线不变：密码只用于**你本账号**自动登录；不联网、不上传、不共享、不识别验证码。
> 若自动登录遇验证码或失败，提示你改用「重新登录」（手工登录）。

### 操作台（仪表盘「操作台 · 测试与真实下载」四按钮）

| 按钮 | 行为 | 落库？ |
|---|---|---|
| ① **测试登录** | 自动登录，验证能否进会员页 | 否（只存会话） |
| ② **测试查询** | 登录后跑 1 个最小范围查询，返回条数 + 样本 | 否（纯探针） |
| ③ **测试下载数据** | 真实下载但限小量（≤3 条 + PDF） | 是（轻量） |
| ④ **真实下载数据** | 按配置全量跑一轮，写入正式库 | 是（正式） |

结果实时显示在「上次测试结果」和日志里。**推荐顺序：①②③ 都通过后，再点 ④。**

> 自动登录用的页面选择器在 `config.yaml → selectors.login`（默认值是合理猜测）。
> 若第一次真实登录报"找不到元素/超时"，把登录框的 `name`/`id` 告诉我，我改这里。

### 数据要落到别的地方？

改 `config.yaml`：

```yaml
app:
  output_root: ./data          # ← 换成外挂盘 / 你的网站空间路径都行（支持绝对路径）
```

## 三、合规红线（写在代码里，不能改）

1. **不代输账号密码**、不自动重试登录、不换 IP、不识别验证码 —— 一律手工登录一次。
2. 会话失效 → **立即停机 + 告警**，绝不硬闯。
3. REPL 页面出现「メンテナンス」→ 停止本轮全部查询。
4. 默认排除**借地权**（无所有权的"小产权"）。
5. 拟人化节奏：每条房源操作间隔默认 **1–2 秒**（`config.yaml → crawl.delay_range_seconds`）；
   想更快可改小（如 `[0.8, 1.5]`），想更稳可改大——调太小会增加被风控注意的概率。

## 六、版本管理与回滚（改代码前先存档）

**约定：每次让 AI 生成 / 修改代码之前，先存一个检查点。改坏了随时回滚，不用慌。**

### 怎么存 / 怎么回

| 想做什么 | 怎么做 |
|---|---|
| **存档（最常用）** | 双击 `checkpoint.bat`；或命令行 `python checkpoint.py "这次要改什么"` |
| **看两条线各自的状态** | `checkpoint.bat --lines` |
| 看所有检查点 | `checkpoint.bat --list` |
| 看还没存档的改动 | `checkpoint.bat --diff` |
| **回到上一个检查点** | `checkpoint.bat --restore HEAD~1` |
| 回到某个指定检查点 | `checkpoint.bat --restore 03de262`（编号用 `--list` 查） |
| 当前状态 | `checkpoint.bat --status` |

### 两条线：产品线 与 研发线

本项目**分开阅读、分开演进，但一起备份**：

| | **产品线** | **研发线** |
|---|---|---|
| 是什么 | `docs/**` 与根目录 `README.md`（PRD 稿、方案、沟通记录） | `core/**`、`web/**`、`config.yaml` 等源码与脚本 |
| 给谁看 | 业务 / 产品 / 同事 | 看代码的人 |
| 版本号 | PRD 稿各自的版本（主 PRD 另有 `vX.Y.Z`） | `core/version.py` 的 `VERSION`（页脚显示） |

一次"存档"会**把两条线（外加房源库数据）一起备份**，并分别报告各线改了什么：

```
1) 数据：房源库已备份 → .backups/db/jproperty_20260913_163341_871f8462.db
2) 产品线（docs/ + README.md）：3 个文件
     A docs/PRD/00_沟通记录与需求演进.md
3) 研发线（core/ web/ config.yaml 等）：1 个文件
     M checkpoint.py
4) 两条线已一起提交 → 新检查点 c14c043 …
```

> **为什么不拆成两个仓库**：本项目"改需求顺带改代码"是常态（`v1.2.5` 同时改 PRD + 4 个 `.py`）。
> 拆成两个仓库，回滚会变成半截——代码退回去了、文档没退，下一个人会照着错的文档理解代码，比不回滚更危险。

一次"存档"实际做了三件事：

1. **备份房源库**（数据）`data/jproperty.db` → `.backups/db/`（保留最近 20 份，内容没变就不重复存）；
2. **备份产品线**：`docs/**` 的改动；
3. **备份研发线**：`core/**`、`web/**` 等的改动；
4. 两条线**同一个 git 检查点**，一次回滚一起退。

> 回滚是"把代码文件恢复到那个时间点的样子"。房源库是另一个体系（另有上面的自动备份），
> 两者互相独立，不会因为回滚代码把数据删掉。

### 什么进版本库、什么不进

| 进（可回滚） | 不进（有单独备份 / 属敏感数据） |
|---|---|
| `core/`、`web/`、`config.yaml`、`docs/`、启动与验证脚本 | `data/`（房源库、図面 PDF、Excel、日志、`session.json` / `credentials.json` **登录凭据**） |

也就是说：**账号密码和登录会话永远不会被提交进版本库**，这一点由 `.gitignore` 保证。

### 出问题时的心理预期

- 代码改坏了 → `checkpoint.bat --restore HEAD~1`，回到上一个检查点，完事。
- 回滚前脚本会**先自动把当前现场存一份**（叫 `safety` 提交），所以"回滚错了"也能再回来。
- 改了 `.py` 需重启 `start_mvp.bat` 才生效；只改模板 / JS / CSS 刷新页面即可。
