## 0. 怎么读这份文档

- **用户原话**用引号直接引用；只能还原要点的地方写「要点」，不逐字编造。
- **PM 判断**里凡是"查了库/查了日志/查了代码"的，都写明依据——这是 PM 和"猜"的区别。
- 未闭环的事项标 **⏳**，闭环后标 ✅ 并注明版本。
- 「落地」写的是**版本号 / 文件**，便于从文档反查代码。

## 3. 2026-09-11：本地版 MVP 从 0 到可用

> 这一天的节奏是"用户点一下就报一个问题，PM 当场定位+修+写进 PRD"。

### 3.1 账号管理 + 操作台（用户要求）

- **用户原话（要点）**：要 ① 账号管理（录入账号密码、支持清空/显示密码）；② 测试与操作按钮（登录 / 测试登录 / 测试查询 / 测试下载数据 / 真实下载数据）。
- **落地**：账号管理页（Fernet 加密存 `data/credentials.json`，密钥 `data/.cred_key`）+ 仪表盘「操作台」四按钮（测试登录 / 测试查询 / 测试下载 / 真实下载）。
- **红线（PM 主动设的，用户未反对）**：程序**绝不代输账号密码、不重试登录、不识别验证码、不换 IP**；密码只用于本账号自动登录。

### 3.2 「测试登录」报 `TypeError: Failed to fetch`（用户报）

- **PM 查到**：**不是接口逻辑错，是服务进程已退出**——用户看到的页面是服务还活着时渲染的，点按钮时 8765 已无监听，浏览器在网络层就失败了。
- **结论**：先让用户把账号**保存**（截图显示填了但没点保存）再点测试登录；同时前端把 `Failed to fetch` 这类英文报错**中文化**，并加"服务已停止"红色横幅（每 4 秒心跳，服务恢复自动消失）。
- **产品启示（写进 PRD 的坑）**：这条横幅后来成了救命功能——用户分不清"我操作错了"和"服务死了"。

### 3.3 账号页 v2：账号名称 + 网站地址 + 全站版本号

- **用户以 PM/SA 视角提**：① 保存账号至少要含「账号名称」「网站名称」两项；② **全站页脚加版本号 + 更新日期时间**。
- **落地**：账号页加两个输入框；`base.html` 页脚加 `版本 v{{version}} ｜ 更新于 {{build_at}}`（单一来源 `core/version.py`）。
- **PM 自己犯的错并纠正（记在案）**：验证新增字段时误用测试密码覆盖了用户的真实账号 → 已清空并请用户重新录入。
  **教训**：验证要用不同的 `member_id`，绝不动用户的真实数据。

### 3.4 登录根因真机定位 + 三视角重整页面

- **用户报**：后台不能正常登录。
- **PM 查到**：8765 无监听（WinError 10061）→ **服务已死**，非登录逻辑问题；用同一逻辑重新拉起服务。
- **同时**：用户发 **11 张真实 REINS 操作截图**（红框＝必用元素）→ 按真机校准选择器。

### 3.5 真机探查検索页 + 抓取全链路跑通

- 用户反馈"卡死/不需要做选择" → 实为 REINS 弹「**保存条件を読み込みますか？**」确认框 → 改成**自动点 はい**。
- 用户要求：点详情页 + 下载 PDF，模拟速度 **2–3 秒/房源**。
- PM 主动确认未擅自改的项：图片下载仍关闭（`download.images=False`），是否开启等用户答复。
- **桌面启动 BAT** 两次故障：① 旧 BAT 用 `netstat -ano|findstr` 在**中文 Windows GBK 下解析失败** → 端口清不掉 → 双击闪退；② 修复后重写为 `serve.py` 端口自愈。

### 3.6 提速：间隔 2–3 秒 → 1–2 秒

- **用户原话（要点）**：「获取详情页内容 + 下载 PDF 后，返回下一次操作的间隔最好在 **1 秒左右**，不断循环把信息更新完」；模拟与真实都要更快；并要求**在产品说明文档里清晰标识这个逻辑**。
- **落地**：`crawl.delay_range_seconds` 由 `[2.0,3.0]` → `[1.0,2.0]`（试跑分支同步改，保持一致）；间隔加在"详情+PDF 拉完"之后、下一条之前；README 写明。

### 3.7 查询页内联全量详情 + 概览定时刷新

- **用户要求**：① 下载后点查询，能把**检索+详情**全部信息查出来；② 默认当天数据、可选任意一天；③ 概览**每 1 分钟自动刷新** + 手动刷新按钮。

## 4. 2026-09-12：功能深化（v1.1.4 → v1.1.12）

### 4.1 指定日期下载（"问题二"）实机验证与修复闭环

- **用户诉求**：能按**指定日期**（如"9 月 5 日登录的公寓"）下载数据。
- **PM 查到的根因（非显然）**：REINS 手动指定日期查询时，「検索要求」并非「物件種別 / 所在地 / 沿線」任一 → **必须先套用「保存した検索条件」再叠加筛选**；控件位置在 `div.p-label` 的**相邻兄弟**里，不是后代。
- **落地**：前端 `/specified` 手动选项 → ①「确定」= 预览（不落库）→ ②「下载」= 独占执行（暂停当天下载、跑完自动恢复），产物＝数据 + 図面 PDF + Excel + 按天页。

### 4.2 i18n 全页铺页收尾（"诉求 C"）

- 四语言切换从"只有框架"铺到全部页面；建立**键覆盖审计**做法（合并字典两段赋值再比对模板用到的 key）。
- **遗留**：模板改动需用户重启一次服务才生效（静态 JS 已热重载）。

### 4.3 降价比例（→ v1.1.4）

- **用户要求**：在查询列表行、详情页头、对比表价格单元格显示**降价比例百分比**。
- **口径（PM 定，用户认可）**：公式＝**降价額 ÷ 修改前金額**（分母取"修改前"，不是修改后）；仅在降价时显示，形如 `↓3.2%`。

### 4.4 降价比例的位置与样式（→ v1.1.5）

- **用户追加要求（原话要点）**：比例要放在**降价金額与当前金額中间**，且**颜色/字体与降价金額一致**。
- **落地**：三处统一为 `↓ 170 万円` → `↓ 1.9%` → `8,680 万円`；样式改为同款**绿底胶囊**。
- **顺手修**：详情页降价徽标漏单位（`↓ 3,280` → `↓ 3,280 万円`）。

### 4.5 「下载文件清单（条件 × 文件 矩阵）」（→ v1.1.6，用户诉求 B）
