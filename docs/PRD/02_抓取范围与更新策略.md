## 一、背景

抓取范围经历过一次**大翻车**，用户两次报"下少了"：

1. v1.1.12：线上「売一戸建」117 件 / 公寓 454 件，本地只有 8 / 222 —— 三条根因叠加（配额截断、多条件共用配额、種目一次只填一个 + 最新順排序）；
2. v1.2.3：手动更新**只下一户建、公寓一条没下** —— 旧逻辑按保存条件顺序跑，条件 01 撞上单轮时长上限就整轮 `break`，公寓永远轮不到。

结论：**抓取范围必须是"配置里的显式声明"，不能是"代码里跑成什么样就是什么样"。**

## 二、目标

| # | 目标 | 衡量 |
|---|---|---|
| G1 | 每一轮更新固定覆盖约定的種目范围 | 6 個種目全部跑到 |
| G2 | 单轮跑不完时**只收尾当前组、继续下一组**，不整轮放弃 | 任一组到点不影响其余组 |
| G3 | 配额按条件独立，互不挤占 | 一戸建不被土地吃光 |
| G4 | 节奏像人，不被风控 | 无并发 + 随机停顿 |

## 三、抓取范围（当前口径）

### 3.1 固定覆盖 6 個種目 / 3 组（v1.2.3 起）

| 组 | 物件種別 | 物件的 2 个種目（REINS 原值） |
|---|---|---|
| 第 1 组 | 売一戸建 | 新築戸建 / 中古戸建 |
| 第 2 组 | 売一戸建 | 新築テラス / 中古テラス |
| 第 3 组 | 売マンション | 新築マンション / 中古マンション |

> 說明：REINS「基本条件」原生是 **2 行 ×（種別 + 種目1 + 種目2）= 一次检索可填 4 个種目槽位**。
> 实现上 `_fill_subtype_slots()` 一次填满两行，**只发 1 次检索请求**（不是逐種目各跑一遍）——更像人、更不容易被风控。
> 另 2 个種目（新築タウン / 中古タウン）与 土地，按面板勾选纳入（土地默认不勾）。

- 配置位置：`config.yaml → search.update_groups`（显式声明范围）；
- 面板位置：数据抓取设置 → 第 4 步「下载条件 → 物件種別（分组多选）」；
- **自动 / 手动更新 / 正式下载 / 指定日期 / 预览五处统一**听这份声明。

### 3.2 保存条件（地区基线）

- `search.saved_conditions: ['01','02']`。
- 截图证实：**02 = 大阪全市 · 当天 · 有所有权的新建公寓和二手公寓**。
- v1.2.3 起，保存条件**降级为"只带地区基线"**，填種目前先复位两行 6 个槽位，避免残留条件干扰。

### 3.3 配额（v1.1.12 起）

| 参数 | 旧值（问题根源） | 现值 |
|---|---|---|
| `crawl.max_items_per_run` | 200 | **5000** |
| `crawl.max_pages` | 7 | **300** |
| 配额归属 | 所有条件**共用一份** | **每个保存条件各一份** |

## 四、更新与触发策略

### 4.1 三种触发方式

| 方式 | 行为 |
|---|---|
| **随机间隔**（唯一的自动方式，v1.2.0 起） | 每轮之间随机等 `random_min_minutes` ~ `random_max_minutes` 分钟（默认 20–60）；**下限硬夹 ≥ 5 分钟** |
| **手动更新** | 点按钮＝按点击当下时间立即跑一轮 |
| ~~定时（固定间隔）~~ | **已去掉**（用户拍板 Q1：太规律＝像机器） |

### 4.2 运行窗口

- 只在 **07:00–23:00** 执行（REINS 日本时间 23:00–次日 07:00 维护；年末 12/27–1/4 也关）。
- 窗口外调度线程**睡到次日 07:00**，一次都不抓（页面上显示「当前不在运行时段」）。
- **注意**：夜里"跑着"的是一个睡着的线程，不必为此关掉自动更新（v1.2.0 已向用户澄清）。

### 4.3 单轮时长上限（v1.2.2 / v1.2.3）

- `crawl.max_minutes_per_group`（默认 **25 分钟**，0＝不限）。
- **按"组"计时**：到点只收尾当前组（落库 + 导出），**继续下一组**——不再整轮 `break`。

### 4.4 边抓边落库（v1.2.2）

- `crawl.flush_every`（默认 **5**）：每攒够 5 条就落库一次（主档 + 快照 + 变更 + PDF），轮内重复番号直接丢。
- 查询页在"今天 0 条"时显示「**正在抓取：已落库 N 条**」，每 20 秒自动刷新。
- **为什么必须有**：老流程整轮抓完才一次性落库，一轮几小时期间本地全空；且 `pdf_bytes` 全堆内存，中途崩溃整轮白跑。

### 4.5 节奏（模拟人工，v1.1.7）

| 环节 | 停顿 |
|---|---|
| 两条房源之间 | `[6, 14]` 秒随机 |
| 约 15% 概率长停顿 | `[20, 45]` 秒 |
| 两个条件之间 | 8–20 秒随机 |
| 并发 | **刻意不开**（并发最像机器、易限流封号） |

- **用户真实目标（原话要点）**：不是"越快越好"，而是「**尽可能像人操作、不被平台判违规**」。
- 因此曾把间隔从 `[2,3]` 提速到 `[1,2]` 的做法被推翻——**现在是"宁可慢"**。

### 4.6 下载条件（v1.2.0，第 4 步，三层）

| 层 | 内容 | 默认 |
|---|---|---|
| **核心** | 物件種別 / 種目（一户建 2 + 公寓 4 + 土地 1，按 kind 联动）；日期「**当天登录（登録年月日）**」+「**当天更新（変更年月日）**」两个都勾 → **跑 2 次检索、按物件番号去重**；土地権利＝所有権のみ | 種目按上表；日期两个都勾；所有権勾上 |
| **可选** | 区 / 价格 / 面积 / 沿線 / 駅 | **全部不勾**；勾了才启用输入框；整块折叠 |
| **补充** | 所有権のみ | — |

- **正式下载只有一个按钮**（Q4 拍板）：条件动过 → 按条件跑；全默认 → 按配置跑。走独占执行（暂停当天下载、跑完自动恢复）。

### 4.7 会话自愈（v1.2.1）

- 抓取入口统一走 `Auth.open_authed_page()`：会话失效 → `try_relogin()`（用本机保存账号自动重登**一次**）→ 成功则重建上下文重试，失败才停机并提示手工登录。
- **红线**：只填表提交一次、**不重试**、**不识别验证码**、**不换 IP**。

## 五、需求（EARS 表述）

**R1（Ubiquitous）** 系统应始终以 `config.search.update_groups` 作为自动/手动更新、正式下载、指定日期下载的**唯一范围声明**。

**R2（State-driven）** While 某一组的运行时长达到 `max_minutes_per_group`, the system shall 收尾该组（落库 + 导出）后继续下一组，不得中断整轮。

**R3（Ubiquitous）** 系统应为**每个保存条件独立计数**配额，条件之间不得互相挤占。

**R4（Event-driven）** When 开始自动更新轮次且会话已失效, the system shall 用本机保存账号自动重登一次；重登失败才停机并给出指引。

**R5（Event-driven）** When 单轮已落库条数达到 `flush_every`, the system shall 立即落库（主档/快照/变更/PDF），使中途崩溃不丢已抓数据。

**R6（Ubiquitous）** 系统在同一检索内应填满 4 个種目槽位（两行），**不得**为每个種目单独发一次检索请求。

**R7（Unwanted）** If 出现验证码、登录失败或需要人工选择, the system shall 停机告警，**不得**尝试识别验证码、重试登录或更换 IP。

**R8（State-driven）** While 处于 23:00–07:00 或 REINS 维护窗口, the system shall 不发起任何检索请求。

## 六、验收标准

| # | 验收项 | 判定 |
|---|---|---|
| A1 | 一轮更新覆盖 6 個種目共 3 组 | 日志出现「第 1/3 组」「第 2/3 组」「第 3/3 组」 |
| A2 | 任一组超时后其余组仍执行 | 构造 `max_minutes_per_group` 极小值验证 |
| A3 | 土地条件拿不到一戸建的额度 | 分别核对每条件的 `fetched` |
| A4 | 下载进行中即可查到已落库数据 | 抓取中途点查询，能看到「正在抓取：已落库 N 条」 |
| A5 | 会话过期能自愈 | 构造过期会话，日志出现重登成功并继续 |
| A6 | 无并发请求 | 抓取期间请求数呈线性、无并行 |
| A7 | 窗口外不抓 | 日志显示"睡到次日 07:00" |
