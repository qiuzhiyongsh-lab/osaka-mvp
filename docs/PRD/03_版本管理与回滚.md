> 覆盖版本：v1.2.6 起（本项目从这一版开始纳入版本管理）

## 一、背景

**用户原话（2026-09-13 16:31）**：
> 「每次让 AI 生成/修改代码前先 commit。改坏了随时回滚。」

在这之前，项目**没有 git 仓库**——所有改动只存在于文件系统，"改坏了"没有退路。同时业务方明确提出：
> 「**PRD 稿和代码是两条线去存储和运行的**：一个是产品的角度去看，一个是研发的角度去看。**在备份的时候是两条线同时备份。**」

## 二、目标

| # | 目标 | 衡量 |
|---|---|---|
| G1 | 任何一次 AI 改动之前，都存在一个可回退的检查点 | 检查点数量 ≥ 改动轮次 |
| G2 | 回滚是"一条命令"，且**回滚错了还能回来** | `--restore` 前自动存 safety 提交 |
| G3 | 两条线（产品 / 研发）**同一次存档一起备**，不会一半退一半不退 | 单次 `checkpoint` 同时覆盖两者 |
| G4 | 登录凭据**永不进版本库** | `.gitignore` 排除 `data/`，`ls-files` 无凭据文件 |

---

## 三、两条线

| | **产品线** | **研发线** |
|---|---|---|
| 内容 | `docs/**`（PRD 稿、方案、沟通记录） | `core/**`、`web/**`、`config.yaml`、根目录脚本 |
| 读者 | 业务 / 产品 / 同事 | 看代码的人 |
| 版本号 | 各 PRD 稿自己的版本 + 主 PRD 的 `vX.Y.Z` | `core/version.py` 的 `VERSION`（页脚显示） |
| 改动时机 | 想清楚先改文档 | 文档定了再改代码 |

**存储方式**：同一个 git 仓库，两条线**分开阅读、分开演进**，但在**同一个检查点**里一起提交。
**为什么不拆两个仓库**：本项目"改需求顺带改代码"是常态（v1.2.5 同时改 PRD + 4 个 `.py`）。
拆开后回滚会变成半截——代码退了、文档没退，下一个人会照错文档理解代码，比不回滚更危险。

## 四、版本号规则

| 项 | 规则 |
|---|---|
| 代码版本 | **单一来源** `core/version.py` 的 `VERSION` / `BUILD_AT`；页脚 `{{ version }}` 取自它 |
| 改 UI/功能时 | **必须同时**改 `core/version.py` 与 `docs/UI_PRD/界面的UI及功能.md`（版本头 + 修订记录），否则页脚与 PRD 脱节 |
| 主 PRD 版本 | 与代码版本**同号**（v1.2.6 代码 ↔ PRD v1.2.6） |
| 主题 PRD（本目录） | 各自独立 v1.0 起，不跟代码版本走；文首注明「覆盖版本」 |
| 生效条件 | 改 `.py` → **必须重启** `start_mvp.bat`；只改模板/JS/CSS → 热重载，刷新即可 |

### 4.1 热重载契约（2026-09-13 事故后确立）

| 改动层 | 是否热重载 | 必须遵守 |
|---|---|---|
| Jinja 模板 `.html` | ✅ 是 | **不得硬依赖"同一次发布新增的后端符号"**：新 stat 键用 `stats.get('k', 0)`；新 Jinja 全局用 `{% if f is defined %}` 包住 |
| 静态 `.js` / `.css` | ✅ 是 | 新增 i18n 键要与 `i18n.js` 同步（否则显示裸键） |
| Python `.py` | ❌ 必须重启 | 见 `04_更新生效与重启策略.md`（安全重启 ＋ 断点续跑，待拍板） |

> **事故复盘**：v1.2.6 把 `today_changed` / `today_total` 加进 `store.stats()`，模板先热重载、后端没重启
> → 概览页 `UndefinedError`；同类问题还有 v1.2.5 的 Jinja 全局 `wareki_to_ad` → 详情页也会报错。
> **两处均已按契约加固，并用「模拟旧后端」的方式验证通过（4 页面全 PASS）。**

## 五、存档与回滚流程

### 5.1 命令

| 想做什么 | 命令 |
|---|---|
| **存档（AI 改代码前必做）** | 双击 `checkpoint.bat`；或 `python checkpoint.py "这次改什么"` |
| 看所有检查点 | `python checkpoint.py --list` |
| 看未存档改动 | `python checkpoint.py --diff` |
| **看两条线各自的状态** | `python checkpoint.py --lines` |
| 回到上一个检查点 | `python checkpoint.py --restore HEAD~1` |
| 回到指定检查点 | `python checkpoint.py --restore <编号>` |

### 5.2 一次存档实际做了什么

1. **数据**：备份 `data/jproperty.db` → `.backups/db/`（保留最近 20 份，内容相同不重复存）；
2. **产品线**：`docs/**` 的改动一并纳入提交；
3. **研发线**：`core/**`、`web/**` 等的改动一并纳入提交；
4. 输出**分线报告**：两条线各改了哪些文件。

### 5.3 回滚的安全设计

- `--restore` 会**先自动把当前现场存成一个 `safety` 提交**，再 `reset --hard`。
  → 所以"回滚错了"可以再回到回滚前。
- 回滚的是**代码与文档**；房源数据是另一套体系（§5.2 第 1 条的独立备份），不会因为回滚代码被删。

## 六、什么进版本库、什么不进

| 进（可回滚） | 不进（另有备份 / 属敏感数据） |
|---|---|
| `core/` `web/` `config.yaml` `docs/` 启动与验证脚本 `checkpoint.*` | `data/`：房源库 `jproperty.db`、図面 PDF、Excel、日志、**`session.json` / `credentials.json` / `.cred_key` 登录凭据** |
| | `.backups/`（本机快照）、`__pycache__`、根目录 `_*` 历史诊断脚本 |

> **红线**：账号密码与登录会话**永远不进版本库、永不上传云端**。由 `.gitignore` 保证，验收项 A4 会核对。

## 七、需求（EARS 表述）

**R1（Ubiquitous）** 系统应始终保证"AI 改动之前存在一个可回退的检查点"。

**R2（Event-driven）** When 执行 `--restore`, the system shall 先把当前工作区存成 safety 提交，再恢复到目标检查点。

**R3（Ubiquitous）** 备份应同时覆盖数据、产品线、研发线三块内容，并**分别报告**两条线的改动。

**R4（Unwanted）** If 版本库中即将纳入 `data/` 下的凭据类文件, then the system shall 阻止纳入（`.gitignore` 排除）。

**R5（State-driven）** While 存在未存档改动, the system shall 在状态查看中明确显示数量与文件名。

**R6（Ubiquitous）** 存档操作**不得**影响正在运行的服务进程（不重启、不停服）。

## 八、验收标准

| # | 验收项 | 判定 |
|---|---|---|
| A1 | 存档后工作区干净 | `--status` 显示"干净" |
| A2 | **回滚真的能救回来** | 提交探针文件 → `--restore HEAD~1` → 探针消失、历史干净 ✅ 已实测 |
| A3 | 回滚可逆 | safety 提交存在，能再回滚回去 |
| A4 | 凭据未入库 | `git ls-files` 中不含 `session.json` / `credentials.json` / `.cred_key` / `jproperty.db` |
| A5 | 房源库有独立备份 | `.backups/db/` 下有对应快照，且内容没变时不重复存 |
| A6 | 两条线分别报告 | 存档输出同时列出产品线与研发线改动 |
| A7 | 存档不影响服务 | 存档前后 8765 仍在监听 |

## 九、环境注意（踩过的坑）

| 坑 | 说明 |
|---|---|
| **Windows `.bat` 必须 CRLF 换行** | 工具默认写 LF，cmd 按字节偏移读文件会乱码/截断（实测报 `'heckpoint.bat' 不是内部或外部命令`）→ 用 Python 显式写 `\r\n` |
| 沙箱禁止调用 `cmd.exe` | 因此 `.bat` 无法由 AI 自测，需用户双击验证 |
| 本机 bash 工具 PATH 异常 | `ls`/`cd`/`head`/`git` 等命令找不到 → 一律用全路径调用 `.exe` 或 python |
| git 路径 | `C:/Users/25374/.workbuddy/binaries/PortableGit/versions/1.2.0/cmd/git.exe` |
| 仓库配置 | `core.autocrlf=false`（保证回滚字节一致）、`core.quotepath=false`、身份 `AI Checkpoint` |
