# PRD · 更新生效与重启策略

> 版本 v1.0 ｜ 2026-09-13 ｜ 归属：**产品线**
> 触发：用户提问「我现在有可能正在下载，重启之后能不能衔接上去继续下载？如果不能，需要重新思考产品结构。」
> 相关：`03_版本管理与回滚.md`、`../UI_PRD/界面的UI及功能.md`

---

## 一、背景：为什么会有"要重启"这件事

本项目是「Python 后端 + Jinja 模板 + 静态 JS/CSS」的本地服务，**三层重载能力不一样**，而用户看到的只有一句"请重启"——体验很差：

| 层 | 改完要不要重启 | 实证 |
|---|---|---|
| Jinja 模板 `.html` | **不用**，热重载 | 旧后端 + 新模板 → 概览页报 `UndefinedError` ⇒ 证明新模板**已经生效** |
| 静态 `.js` / `.css` | **不用**，热重载 | 同上 |
| Python `.py` | **必须重启** | 新模板引用的 `today_changed` 由 `core/store.py` 提供；该文件没重启就不生效 → 报错 |

**用户的原话（2026-09-13）**：
> 「我现在有可能正在下载这些信息，如果重启之后，是不是能够衔接上去，让它自动继续下载？如果不能，我认为这里面需要重新思考你的产品结构。我的想法是：**1. 要么你可以让我重启，但必须能够续上下载；2. 要么就不需要让我重启。**」

---

## 二、事实核查：现在重启会怎样

| 问题 | 事实 | 依据 |
|---|---|---|
| 正在跑的这一轮在哪？ | 在 **crawler 线程的内存里**（`collected` 列表 + `seen` 集合 + 组/页循环游标） | `core/crawler.py::_live_items` |
| 重启后这一轮会续上吗？ | **不会**。进程结束 = 本轮循环消失，没有持久化游标 | 同上 |
| 已经抓到的会丢吗？ | **不会丢**。v1.2.2 起每 `flush_every`(=5) 条就落库（主档/快照/变更/PDF） | `core/crawler.py::_BatchSink` |
| 重启后剩下来的会被补上吗？ | **会被补上，但要重新翻页**。新一轮按 `search.update_groups` 重跑同一范围，`pick_queue` 跳过已有 `detail_json` 的房源 ⇒ 只抓缺的 | `core/differ.py::pick_queue` |
| 代价是什么？ | ① 重新检索/翻页 = **额外请求**（与"模拟人工、不被风控"的目标相冲突）；② 用户等待时间变长；③ 中途打断时"最后不足一批"的几条要重抓 | — |

**结论**：现状是「**不丢数据、缺口能补齐，但不能断点续传**」。
用户要的两条路，现状**两条都不满足**：既不满足"重启能续上"，也不满足"不用重启"。

## 三、三个方案对比

| | **A. 安全重启 ＋ 断点续跑**（PM 推荐） | B. 完全免重启（热替换代码） | C. 只做兼容兜底（本次已做） |
|---|---|---|---|
| 做法 | 服务在**安全点**自行重启；重启前存游标、重启后从游标继续 | 运行时替换已导入的模块 | 模板对后端缺失的键/函数做降级 |
| 用户操作 | 点一个「应用更新」按钮，**不用管** | 无 | 无 |
| 正在下载时可用 | ✅ 等当前组收尾再重启，进度接着跑 | ✅ | ✅ 但只能避免报错，功能仍旧 |
| 技术风险 | 中（需实现游标持久化 + 自重启） | **高**：Python 无法安全热替换已导入的类/闭包，易出现"新旧代码混跑"的诡异 bug | 低 |
| 是否解决根因 | ✅ | ✅ | ❌（只是止血） |
| 判断 | **建议采用** | 不建议 | 保留（作为长期防线） |

## 四、PM 建议方案 A 的设计

### 4.1 安全点选在哪

**组与组之间**。理由：组内是一个连续循环（翻页→逐条进详情→下载 PDF），中途断开要重建浏览器上下文；
而组间本来就有 **6–14 秒随机停顿**（`core/crawler.py`），天然就是安全点。

### 4.2 流程

```
用户点「应用代码更新（不中断）」
   ↓
置一个标记（data/.apply_update）
   ↓
当前组跑完 → 写断点文件 data/round_state.json
   （run_id / 已完成到第几组 / 已完成番号集合 / 时间）
   ↓
进程自重启（os.execv，同一端口、保留会话文件）
   ↓
启动时读到断点 → 从下一组继续这一轮（跳过已完成组）
   ↓
断点文件删除，继续按随机间隔跑
```

### 4.3 为什么这样做是安全的

1. **不会重复抓**：`pick_queue` 天然跳过已有 `detail_json` 的房源；断点里再记一份已处理番号，双保险。
2. **不会丢数据**：边抓边落库已保证"落库的都在磁盘上"。
3. **不会重登/触发风控**：重启只是换进程，`data/session.json` 复用原会话，不重新登录。
4. **失败可退回**：断点文件损坏或缺失 → 退化为"重跑当天范围"，与现状等价，不会更糟。

### 4.4 兜底（本次已做，C 方案）

模板**不得硬依赖"同一次发布新增的后端符号"**：
- 后端新增的 stat 键 → 模板用 `stats.get('k', 0)`；
- 后端新增的 Jinja 全局函数 → 模板用 `{% if f is defined %}` 包裹，缺失时降级显示。

> 本次事故就是因为违反了这条：`index.html` 用了新增的 `today_changed`、`detail.html` 用了新增的 `wareki_to_ad`，
> 模板先热重载、后端没重启 → 概览页与详情页直接报错。**已修，并按"模拟旧后端"的方式验证通过。**

## 五、需求（EARS 表述）

**R1（Event-driven）** When 用户请求应用代码更新, the system shall 在当前**组**收尾后（安全点）自行重启，不得在组中途中断。

**R2（Event-driven）** When 重启前, the system shall 持久化本轮断点（`run_id` / 已完成组 / 已处理番号），供重启后继续。

**R3（State-driven）** While 启动时存在有效断点, the system shall 从断点之后继续该轮，**不得**从第一组重跑。

**R4（Unwanted）** If 断点文件缺失或损坏, then the system shall 退化为按当前配置重跑，并保证**不重复入库**（幂等）。

**R5（Ubiquitous）** 重启**不得**导致重新登录（沿用 `data/session.json`），也不得改变对外请求节奏（仍为模拟人工）。

**R6（Ubiquitous）** 模板应始终对"后端可能缺失的键 / 全局函数"做降级处理，使**模板热重载 + 后端未重启**不产生白屏或报错页。

**R7（Optional）** Where 用户希望最小改动，the system shall 允许"不重启继续跑"（读取旧代码、仅新模板生效），此时功能可降级但不报错。

## 八、v1.3.0 落地（2026-09-13）：**不用"断点文件"的断点续传**（采纳用户口径）

用户给出了一个比"方案 A"更好的定义：
> 「**灵活匹配**：重新去点的时候，要对历史上已经下载的东西做一次匹配；页面或 PDF 已经有了，就不用重复下载。
>  **确定性存储**：如果中断，**最多只允许当前这一次的详情页没有下载/存储**；上一个浏览的详情页、
>  以及所有已经下载的 PDF，都必须存在于本地或确定下载位置。」

PM 据此**推翻了原来的"游标 + `round_state.json`"设计**，改为 **以「已完成物」为游标**：

| | 原设计（方案 A 草案） | **现设计（v1.3.0）** |
|---|---|---|
| 进度记在哪 | 单独一个断点文件 | **不存在进度文件**——进度就是"库里有没有详情 / 磁盘上有没有 PDF" |
| 中断后 | 读断点、从下一组继续 | 重扫一遍，**已完成的自动跳过**，只抓缺的 |
| 优点 | 续跑精确 | ① 不会出现"断点文件与事实不一致"；② 手工删掉某个 PDF 也能被**自动补回**；③ 代码更少、更可靠 |
| 用户视角 | "我上次跑到哪了？" | "**我缺什么，它补什么**"（更符合业务直觉） |

### 配套改动（v1.3.0）

| 改动 | 内容 | 满足用户的哪一条 |
|---|---|---|
| `flush_every: 5 → 1` | 每抓一条**立即落库 + 立即落盘** | 「实时更新」+「最多只丢当前这一条」 |
| PDF **原子落盘** | 先写 `xxx.pdf.part` → `os.replace()` 改名 | 「确定性存储」：磁盘上永远要么没有、要么是完整文件 |
| 详情 / PDF **分开判断** | 详情已有但 PDF 缺失 → 用库里存的 `pdf_url` **只补 PDF，不重开详情页** | 「灵活匹配……必须非常灵活」 |
| 新增 `properties.pdf_url` | `_ensure_columns()` 幂等补列 | 免手工迁移、老库直接可用 |

**遗留**：`_collect_from_results`（"指定日期下载"路径）暂未接入后台 PDF（仍是同步下载）⏳。
