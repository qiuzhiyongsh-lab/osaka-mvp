1.2 规格（验收口径）

#项目规格
1UI日期由「1 个框」变「起 ~ 止 2 个框」，中间 ~ 连接；标签仍叫「日期」
2日期口径不动，4 档照旧（默认「登録日或変更日」）
3默认值起 = 止 = 今天（保持现在"打开就是今天"的习惯，不让老用户困惑）
4快捷档新增 5 个一键按钮：今天 / 近 3 天 / 近 7 天 / 近 30 天 / 全部
5留空语义两端都空 = 不按日期过滤（等价于现在隐藏的 date=all，但变得"看得见"）
6只填一端只填起 / 只填止 → 按开区间处理（"9/13 以后"这种查法）
7起 > 止前端自动交换 + 淡提示「起止已自动调换」，不报错（不打断销售动作）
8摘要文案「日期 2026-09-15 共 447 条」→「日期 2026-09-13 ~ 2026-09-15 共 N 条」
9条件记忆起止两值进 localStorage「查询条件记忆」，刷新后还在
10四语中文 / 繁中 / English / 日本語 四套文案都要补（i18n.js）

后端改法（给未来动手的人）

/api/query 新增参数：date_from、date_to（YYYY-MM-DD，可空）
store.search() 把「= ?」换成「BETWEEN ? AND ?」，四种口径一一对应：

  registration : reg_date_iso BETWEEN ? AND ?
  change       : chg_date_iso BETWEEN ? AND ?
  download     : substr(COALESCE(last_seen_at,first_seen_at),1,10) BETWEEN ? AND ?
  any（默认）  : (reg_date_iso BETWEEN ? AND ? OR chg_date_iso BETWEEN ? AND ?)

兼容旧链接：date=YYYY-MM-DD → 视为 from = to；date=all → 保留
⚠ 三条必须继承的「不变量」（否则会重犯旧 Bug）
  • 日期口径绝不能回到 first_seen_at。该字段会被每轮抓取覆写，语义是"最后一次抓取日"，不是平台登録/変更日。
  • 「任一」口径的 BETWEEN，语义是"任一日落在区间内"，不是「两日都在区间内」。 （历史教训：两排日期都勾 = AND 交集，曾实测 866 并集 vs 145 交集。）
  • date=all 不能被写进 <input type="date">（浏览器会当非法值清空），现状已用 ALL_DATES 标记处理，改版后要保住。

8线上分享版 ⇄ 本地版：同步机制 + 对齐实录

一句话：线上不是本地页面的"复制品"，而是跑同一份代码的另一个部署实例 —— 靠一个环境变量 OSAKA_PUBLIC=1 把"只有本机才有意义"的能力收起来。 所以「页面保持一致」这件事，本质是「改完本地 → 跑一次同步脚本 → 重新发布」。

8.1 链路（谁依赖谁）

osaka-mvp/web/app.py  ├─►  tools/sync_to_publish.py  ──►  osaka-house-publish/app_local/
osaka-mvp/web/templates┤      （刷数据 + 复制代码 + 脱敏配置 + 生入口）
osaka-mvp/web/static  ─┘
                                    │
                                    ▼
              app_local/serve_public.py（OSAKA_PUBLIC=1 对外模式）

8.3 五条固化约束（写进脚本，不靠人记）

#约束
1PDF 三处入口一律不上传：列映射里没有 PDF 列 + 显式排除名单 + 同步脚本做泄漏检查（非 0 即中止）
2凭据不上云：data/ 整体不复制；配置里的密码 / token / api_key 一律剔除
3每次重新发布前必须先跑同步脚本，否则线上会用旧包把数据回退
4重新发布 = 覆盖线上链接，每次都要勇哥点头
5同步脚本一律走 core.config.load()，禁止直接 yaml.safe_load("config.yaml") —— 凭据拆到 config.local.yaml 之后，任何"只读模板"的取数都会拿到空值（本次踩过，见 8.5）

8.5 【2026-09-17 02:25】线上重新对齐到 v1.7.6 —— 顺带修掉一个静默失效的链路缺陷

项重发前重发后
线上代码版本v1.6.1v1.7.6（与本地一致）
线上数据旧包3042 条（与本地一致）
查询页多选（区 / 取引態様）无有
日期快捷档有已删
默认隐藏其他详情无有
挖出来的缺陷：同步脚本原来只读 config.yaml（模板）。v1.7.5 把真凭据拆去 config.local.yaml 后，脚本读到的是 空 —— 线上拿到的 ingest_token 变成空串， 于是本地每轮抓完自动推送数据时被线上 401 拒绝，而且不报错（表面上只看到"线上数据没更新"）。
修法：改走 core.config.load()（_DEFAULTS ← config.yaml ← config.local.yaml 三层深合并）， 敏感键仍由脚本的脱敏逻辑统一剔除。已固化成本章第 5 条约束。
