## 3. 本期立即执行 · 需求 1（日期 = 时间段）

### 3.1 客户为什么提（勇哥原话，这是本需求的「正当性」）

> **勇哥**：「这个日期的话是在可以**搜索一个时间段**…因为这里面是查询嘛，你要不就查询一天也行，或者说是查询一个时间段也行。」
>
> **勇哥（关键论据）**：「你不可能…比如**这个时候（昨天）没填的这一套房，我可能（今天）没填的话，是昨天有今天没有，那这套房不就搜不出来了吗？**…我肯定来说是尽可能的是跟那个后台越接近越好。」
>
> **梓榮**：「明白对是。」

**翻译成人话**：现在「日期」是**单选一天**。有些房源**昨天在平台登録了、今天没有**（不在今天的更新里），
按「今天」查就永远漏掉它。要能一次查「9/13 到 9/15」这种区间。

### 3.2 现状（代码实测，非猜测）

`web/templates/search.html` 第 60–70 行：

```html
<label class="field"><span data-i18n="search.date">日期</span>
  <input type="date" id="date" value="{{ today }}">        <!-- ← 单日，只有一个框 -->
</label>
<label class="field"><span data-i18n="search.date_caliber">日期口径</span>
  <select id="date_caliber">…登録日或変更日 / 変更日 / 登録日 / 下载日…</select>
</label>
```

- **单日**：`<input type="date" id="date">`，默认值 = 今天。
- **日期口径** 4 档：`any`（登録日或変更日）/ `change` / `registration` / `download`（下载日）。
- 后端 `core/store.py::search()` 第 630–651 行，日期是**等值**匹配：
  `reg_date_iso = ?` / `chg_date_iso = ?` / `(reg_date_iso = ? OR chg_date_iso = ?)` / `substr(last_seen_at,1,10) = ?`
- 特例：`date=all` → 不按日期过滤（概览 KPI「本地房源总数」点进来用）。

### 3.3 要改成什么（验收口径）

| # | 项目 | 规格 |
|---|---|---|
| 1 | **UI** | 日期由「1 个框」变「**起 ~ 止 2 个框**」，中间用 `~` 连接；标签仍叫「日期」 |
| 2 | **日期口径** | **不动**，4 档照旧（`登録日或変更日` 保持默认） |
| 3 | **默认值** | **起 = 止 = 今天**（保持现有习惯：打开就是"今天"，不让老用户困惑） |
| 4 | **快捷档** | 新增 5 个一键按钮：`今天` / `近 3 天` / `近 7 天` / `近 30 天` / `全部` |
| 5 | **留空语义** | **两端都空 = 不按日期过滤**（等价于现在的 `date=all`，但不再是隐藏参数，而是"看得见"的空） |
| 6 | **只填一端** | 只填起 / 只填止，按**开区间**处理（`>=起` 或 `<=止`）——便于"9/13 以后"这种查法 |
| 7 | **起 > 止** | 前端**自动交换**并在摘要行给一句淡提示「起止已自动调换」，**不报错**（不打断销售的动作） |
| 8 | **摘要文案** | 「日期 `2026-09-15` 共 447 条」→ 「日期 `2026-09-13 ~ 2026-09-15` 共 N 条」 |
| 9 | **条件记忆** | 起止两值要进 localStorage 的「查询条件记忆」（刷新后还在） |
| 10 | **四个语言** | 中文 / 繁中 / English / 日本語 四套文案都要补（`i18n.js`） |

### 3.4 后端改法（给未来动手的人）

```
/api/query 新增参数：date_from、date_to（YYYY-MM-DD，可空）
store.search() 把「= ?」换成「BETWEEN ? AND ?」，四种口径一一对应：

  registration : reg_date_iso BETWEEN ? AND ?
  change       : chg_date_iso BETWEEN ? AND ?
  download     : substr(COALESCE(last_seen_at,first_seen_at),1,10) BETWEEN ? AND ?
  any（默认）  : (reg_date_iso BETWEEN ? AND ? OR chg_date_iso BETWEEN ? AND ?)

兼容旧链接：date=YYYY-MM-DD → 视为 from = to；date=all → 保留 |
```

### 3.5 ⚠ 三条必须继承的「不变量」（否则会重犯旧 Bug）

1. **日期口径绝不能回到 `first_seen_at`。**
   该字段会被每轮抓取覆写，语义是"最后一次抓取日"，**不是**平台登録/変更日。所以时间段筛选必须走 `reg_date_iso` / `chg_date_iso`。
2. **「任一」口径的 BETWEEN，语义是"任一日落在区间内"**，**不是**「两日都在区间内」。
   （历史教训：两排日期都勾 = AND 交集，曾实测出 866 并集 vs 145 交集。这里必须写清，别再被理解成 AND。）
3. **`date=all` 不能被写进 `<input type="date">`**（浏览器会当非法值清空）——现状已用 `ALL_DATES` 标记处理，改版后要保住这个标记。

## 4. 本期立即执行 · BUG-1（修繕積立金 取数错位）★ 最重

### 4.1 客户看到的现象

| | REINS 图纸上的真实值 | 我们后台显示的 | 判定 |
|---|---|---|---|
| 修繕積立金 | **4,400 円**（每月） | **1,645,000 円** | ❌ 差 **373 倍** |
| 坪単価 | **164.5 万円**（※3.30578で換算） | （被塞进了上一行） | ❌ 串行 |

**1,645,000 円 = 164.5 万円** —— 一眼可见：**把「坪単価」当成了「修繕積立金」写进去了**。

### 4.2 根因（代码 + 数据双重坐实，不是猜）

**① 代码位置**：`core/crawler.py` 第 307–327 行 `LIST_FIELD_MAP`

```python
(3, 5):  "management_fee",   # 管理費（进 detail_json）
(3,10):  "repair_fund",      # 修繕積立金（进 detail_json）   ← 坐标写死
```

这是**按"网格坐标"取数**（`grid-row-start:N` / `grid-column`）。而 REINS 列表的**列语义随種目变化**：

- マンション 行：第 3 行第 10 列 = **修繕積立金** ✅
- 売地 / 戸建 行：同一坐标 = **坪単価** ❌ → 被当成修繕積立金

**② 数据实测**（本机 `data/jproperty.db`，2026-09-15 直查）

| 指标 | 数值 |
|---|---|
| 全库总行数 | **2,628** |
| 有 `repair_fund` 值的行 | **969** |
| 其中 **`repair_fund` ≈ ㎡単価 × 3.30578**（1% 内吻合） | **965** ★ |
| 其中数值「合理」（月额 ≤ 10 万円） | **0** |

> **965 / 969** 吻合「坪単価」公式；合理的月额**一条都没有**。
> 结论：**这个字段目前 100% 是脏的，不是个别串行。**

**③ 按種目分布**

| 種目 | 条数 |
|---|---|
| 中古マンション | 881 |
| 売地 | 66 |
| 新築マンション | 17 |
| 売地／オークション | 1 |

> 注：**売地（土地）本来就不该有「修繕積立金」** —— 共 67 条属"无中生有"。

**④ 抽样对照（番号 / 種目 / 库里 repair_fund / ㎡単価 / ㎡単価×3.30578）**

| 物件番号 | 種目 | repair_fund | ㎡単価 | ㎡単価×3.30578 |

| 300140682742 | 中古マンション | 497,000 | 151,000 | 499,173 |

（`3.30578` 就是截图里「坪単価 ※3.30578で換算」的那个换算系数 —— 数值层面**完全咬合**。）

**⑤ 错误是在哪儿显示出来的**

## 5. 本期立即执行 · 需求 2（REINS 物件番号検索）

>
> 会议背景（`00:35:57 ~ 00:36:26`）：
> **勇哥**：「你把这个番号复制下来，然后点这个检索，录进去一点查询，就全出来了。」
> **梓榮**：「你把链接也放进去？」→ 勇哥：「都在这，你看见了没？」
> **梓榮**：「看见——**前提是在他运作时间范围里面**。」「**如果过了这个时间段就查不了。**」
> → **痛点是"要手动复制粘贴番号"**。

### 5.2 现状（代码实测）

`web/templates/detail.html` 第 57–62 行 —— 按钮**在「物件番号」前面**：

```html
{% if row.property_no %}
<a class="btn ghost" href="https://system.reins.jp/main/BK/GBK004100" target="_blank">REINS 物件番号検索</a>
<span class="muted">物件番号 <span class="mono">{{ row.property_no }}</span>
  <span>（详情页需在 REINS 内点击「詳細」打开，无永久直链）</span></span>
{% endif %}
```

- 点击只是**新标签打开** REINS 的「物件番号検索」页，**番号不会自动带过去** → 用户自己复制粘贴。
- 已知技术约束 ⏳：REINS 详情页**无永久 URL**；带 `?bknno=` 的 GET 会返回 **E2171**（此前实测）。

### 5.3 怎么做

**2a｜位置（明确、无歧义）**

| | 现状顺序 | 改后顺序 |
|---|---|---|
| 按钮行 | `[REINS 物件番号検索]` ・ `物件番号 3001407` | `物件番号 3001407` ・ `[REINS 物件番号検索]` |

即：把 `<a>` 挪到 `<span>物件番号 …</span>` **之后**。

**2b｜自动带号 —— 两条路，请勇哥拍板 ⏳**

| 方案 | 做法 | 体验 | 可行性 |
|---|---|---|---|
| **A（推荐·立刻可做）** | 点按钮 → ① 把番号**写进剪贴板** ② 打开 REINS 物件番号検索页 ③ 本页弹一句「番号 `3001407` **已复制**，在 REINS 检索框 `Ctrl+V` 即可」 | 省掉"选中—复制"两步，只剩粘贴 | ✅ 一定可行 |
| **B（体验最好·需先验证）** | 研究 REINS「物件番号検索」是否接受**带参 URL / POST**；若支持 → 点一下**直接出结果** | 一键直达，完全免手输 | ⏳ 需先实测（已知 `?bknno=` 走 GET 会 E2171） |
| **C（本地兜底）** | 同页再给一个「**用此番号查本地库**」→ 跳 `/search?q=<番号>` | 本地库内的那套立刻调出来 | ✅ 一定可行 |

**⏳ 待确认（重要）**：勇哥原话「写进**这个查询页面**的编号里面」——
- 若指 **REINS 的那个查询页面**（我认为是这个意思）→ 按 **A / B** 做；
- 若指 **我们自己的「房源查询」页**（把番号填进关键词框再查本地库）→ 按 **C** 做。
（经核查：我们自己的查询页**目前并没有独立的「物件番号」字段**，只有「关键词」框支持番号模糊匹配，所以"C 的口径"需要新建字段。请勇哥圈一下。）

### 11.5 「同步」的技术方案（**v1.5.18 已落地：从"复制页面"升级为"跑同一份代码"**）

> 原计划是「按白名单复制模板」。实测发现这条路走不通：线上 `src/` 与本地 `web/`
> **是两个完全独立的工程**（模板同名但内容全不同，路由、字段、JS 各不相同），
> 复制过去只会四不像，而且以后每改一次都要重新对齐一次。

```
osaka-mvp/web/templates┤      （一条命令：刷数据 + 复制代码 + 脱敏配置 + 生入口）
osaka-mvp/web/static  ─┘
                                    │
                                    ▼
             app_local/serve_public.py（OSAKA_PUBLIC=1 对外模式）
                                    │
                                    ▼  main.py 读 $PORT 绑 0.0.0.0
                          osaka-house-v2.app.workbuddy.host
```

**对外模式（`OSAKA_PUBLIC=1`）收起了什么**

| 类别 | 处理 |
|---|---|

| 采集 / 账号管理 / 本地文件 / 指定日期下载 | **404** |
| `/download/*`（PDF 等本地文件） | **404** |
| 抓取 / 发布 / 调度 / 环境 / 登录 / 凭据 / 日志 / 状态 类 API | **403 JSON** |
| 导航 | 只留「房源查询 / 房源对比 / 运行日志」，logo 显示**线上版** |
