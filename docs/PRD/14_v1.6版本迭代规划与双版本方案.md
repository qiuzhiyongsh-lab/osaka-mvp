## 3. 技术诉求解读

勇哥原话 → 工程含义：

| 诉求 | 工程含义 |
|---|---|
| **同时拥有两个版本** | 两个可独立运行的版本（稳定版 + 新版）**并存可跑**，互不干扰 |
| **操作数据库时保持一个库不变** | 设一个**主库（黄金库）**，试验期间**受保护、不被新版直接改写** |
| **脏数据由更新的版本去处理** | 新版先写**工作库（副本）**；校验通过才把"干净变更"回写主库，脏数据留在工作库由新版逻辑隔离/修复 |

## 4. 双版本架构方案

### 4.1 方案对比

| 方案 | 做法 | 隔离度 | 回滚 | 复杂度 | 结论 |
|---|---|---|---|---|---|
| **A 双库快照（推荐）** | 主库冻结 + 工作库副本 + 受控回写 | ★★★★ | 删副本即回滚 | 中 | ✅ 推荐 |
| B 单库+影子表 | 新版写 `*_v16` 影子表，promote 时事务交换 | ★★★ | 需逆操作 | 中高 | 备选 |
| C 临时库试跑 | 新版跑临时库，仅回写校验通过的行 | ★★★ | 简单 | 中 | 适合小批量 |

### 4.2 推荐方案 A：双库 + 双端口 + 受控回写

```
数据层
  data/osaka.db          ← 主库（黄金）：只有"受控回写"能写；稳定版读；线上只吃它
  data/osaka_v16.db      ← 工作库：v1.6 试验写它；每轮前从主库快照
  data/snapshots/*.db    ← 快照点（回写前/每日/发布前）

服务层
  端口 8765  start_mvp.bat       → v1.5.x 稳定版，读主库     （勇哥现役，不动）
  端口 8766  start_mvp_v16.bat   → v1.6 试验版，读工作库     （新增）

代码层（git）
  tag  v1.5.19   → 稳定基线（先把未提交的 v1.5.18/19 提交+打 tag）
  branch feat/v1.6 → 新版开发；main 保持可发布
```

- **快照**：每轮开始前 `sqlite3` 的 `VACUUM INTO` 或 Python `src.backup(dst)`（原子、一致，无需停服）。
- **工作库写**：v1.6 只写 `osaka_v16.db`。
- **主库冻结**：除 `db_guard.py promote` 外，**任何进程不得写主库**。
- **线上**：`osaka-house-publish` 继续只读"主库导出的 `site_data.json`"（黄金数据），**永不读工作库** → 公网不受试验影响。

### 4.3 环境隔离（实现要点）

- 用**环境变量**切库/端口，不改共享 `config.yaml`：`OSAKA_DB=data/osaka_v16.db`、`PORT=8766`。
- `start_mvp_v16.bat`：设上述变量后启 `web/app.py`（GBK 无 BOM + CRLF，参照现 BAT 规范）。
- 配置文件如需差异，用 `config.v16.yaml` 叠加，避免污染主配置。

## 5. 主库保护与脏数据处理流程

```
[每轮前]  主库 → 快照(snapshots/pre_round_<ts>.db) → 工作库
[一轮中]  v1.6 抓取/解析 → 只写工作库
[一轮后]  一致性校验（db_guard.py verify）
            ├─ 通过 → 生成「变更集 delta」→ 回写主库（回写前再快照，可回滚）
            └─ 不通过 → 疑脏行进工作库 quarantine 表 → 新版逻辑修复/丢弃 → 记入日志
[发布前]  主库快照 + 打包 + 3-2-1 备份
```

**校验项（QA 定口径）**：
1. **件数对账**：我方落库 ≤ 平台可浏览 500（差 ≤5%），超差报警。
2. **字段非空率**：名称/地址/价格/面积 非空率不得下降（防 BUG-2 类回归）。
3. **日期口径**：`reg_date_iso/chg_date_iso` 来源 = 平台登録/変更日（不得被 upsert 洗成 NULL）。
4. **主键冲突/重复**：`property_no` 唯一性。

**新增工具 `tools/db_guard.py`**（RD）：`snapshot` / `verify` / `promote` / `rollback` 四个子命令。

**回滚**：主库异常时，用最近快照 `restore`（OPS 执行，记录发布单）。

## 6. OPS 职责细化（上线 / 保存 / 迭代）

| 项 | 做法 |
|---|---|
| **上线** | 批 1~3 分批；新版先在 8766 本地并存跑，达 SLO（对账差≤5%、新鲜度<24h、页面可用）后**转正**（主库切换/发布）；每批发布单留档 |
| **保存** | 主库每轮快照 + 每日打包 + **3-2-1**（≥2 介质、≥1 异地）；保留 N 份滚动 |
| **迭代** | 版本流转（v1.5→v1.6 转正、旧版可回退）；**季度回滚演练**；脏数据隔离→修复→回写闭环；事故 SEV 分级 + 无指责复盘 48h |
| **红线** | 凭据泄漏 / PDF 公开（本版按勇哥指示放宽）→ 发布前合规确认；数据 48h 未更新 → 叫停 |
