## 3. 待执行需求（R1–R7 + OPS）

> 编号沿用「每文档独立编号」惯例；跨文档引用写「doc#R#」。每条含 EARS 表述与验收标准。

### R1 · 列表页直接显示单价（円/㎡ + 円/坪）★ 会议确认做
- **现状**：单价需进详情页才看得到；列表仅显示房价 / 面积。
- **要改成**：搜索结果列表每条房源常驻展示「每平方米单价（円/㎡）」与「每坪单价（円/坪）」两列，无需点详情。
- **口径**：单价 = 房价 ÷ 面积；㎡単価 与 坪単価（×3.30578）并行显示；数值口径沿用 `value_sanity` 门禁（≥1 万走万円一位小数，小值走円）。`unit_price_sqm / unit_price_tsubo` 机器键按记忆已在库，主要为前端上屏。
- **EARS**：
  - *Ubiquitous*：系统应在每条搜索结果记录中常驻展示 円/㎡ 与 円/坪 两个单价字段。
  - *If* [单价为 null 或 ≤ 0]，*then* 系统应显示「—」且不参与排序计算。
- **验收**：列表每行出现两列单价；抽查 5 条 单价 = 房价 ÷ 面积（与详情页一致，误差 < 0.1%）；空值显示「—」。
- **影响**：`web/templates/search.html` 列定义 + `web/static/app.js` 行渲染；后端字段已存在，改动量小。
- **状态**：✅ 会议确认做 ｜ **优先级 P0**

### R2 · 房龄筛选 + 产权默认所有权
- **现状**：缺房龄筛选维度；会议确认系统**已默认过滤非所有权房源**。
- **要改成**：查询页增加「築年 / 房龄」筛选（如 築浅順 / 指定年範囲 / 新築のみ）；保持默认仅展示所有权（所有権）物业。
- **口径**：房龄 = 当前年 − 建築年（或按 REINS「築年月」）；字段来源 `building_year` 待确认是否在库。
- **EARS**：
  - *Event-driven*：When [用户设置房龄范围 X–Y 年]，the system shall 仅返回建築年落在对应区间的房源。
  - *State-driven*：While [房龄筛选为空]，the system shall 默认仅展示所有权（所有権）物业、排除借地权 / 定期借地权等。
  - *If* [房龄 + 产权组合无结果]，*then* 系统应展示空状态提示而非报错。
- **验收**：设房龄 ≤ 5 年，结果均为新築 / 築浅；取消筛选后默认不含非所有权房源（抽查权属字段）。
- **状态**：⏳ 待开发 ｜ **优先级 P1**

### R3 · 地铁「线路 + 站点区间」范围搜索
- **现状**：会议指出当前为**单点站名搜索**，不支持按线路 + 区间范围。
- **要改成**：支持「线路（如御堂筋線）+ 站点区间（心斎橋～難波）」范围搜索，返回落在该区间内任意站的房源。
- **口径**：依赖 `line_station` 结构化（线路名 + 站名 + 徒歩分）。代码已含 `line_station` / `徒歩` 字段，**待研发核对是否已结构化落库可用于区间计算**（不猜不蒙）。
- **EARS**：
  - *Event-driven*：When [用户选择线路 L 且设置站点区间 S1–S2]，the system shall 返回 L 线中站序落在 S1 与 S2 之间（含）的各站周边房源。
  - *If* [所选区间跨线路或无匹配]，*then* 系统应给出明确提示而非空结果隐瞒。
- **验收**：选御堂筋線 心斎橋～難波，返回结果其沿线站均属于该区间；抽查 3 条站名在区间内。
- **状态**：⏳ 待开发 + 待确认数据基础 ｜ **优先级 P1**

### R4 · 步行至最近车站时间字段 + 快速筛选
- **现状**：会议建议增加「步行至最近车站所需时间」字段，便于筛步行 10 分内房源。
- **要改成**：列表 / 详情展示「徒歩 X 分」；查询页支持「徒歩 ≤ N 分」筛选（默认可设 10 分）。
- **口径**：来源 = REINS 交通栏「徒歩 N 分」解析；是否结构化落库待核对（代码含 `徒歩` 字样，可能仅为展示文本需解析）。
- **EARS**：
  - *Ubiquitous*：系统应在每条房源展示最近车站步行分钟数。
  - *Event-driven*：When [用户设置徒歩 ≤ N 分]，the system shall 仅返回步行时间 ≤ N 的房源。
- **验收**：列表显示徒歩分；设 ≤ 10 分，结果均 ≤ 10。
- **状态**：⏳ 待确认数据源 + 开发 ｜ **优先级 P2**

### R5 · 回报率计算（管理费 + 修繕積立金 + 表面 / 真实回报率）
- **现状**：无回报率；且 **BUG-1（修繕積立金 被误取为坪単価）未修** → 该字段当前数据不可信。
- **要改成**：详情页支持手动录入 管理费 / 修繕積立金，自动算 表面回报率（年賃料 ÷ 房价）与 真实回报率（扣管理费·修繕後 ÷ 房价）。
- **依赖**：必须先修 BUG-1 + 存量清洗，否则回报率算错砸招牌（参见 `12` §2.5.1 结论 2）。
- **EARS**：
  - *Where* [用户录入管理费 M 与 修繕積立金 R]，the system shall 计算表面回报率 = 年賃料 ÷ 房价，真实回报率 = (年賃料 − M×12 − R×12) ÷ 房价。
  - *If* [管理费 / 修繕積立金 缺失]，*then* 系统应仅显示表面回报率并标注「真实回报率待录入」。
- **验收**：录入后两回报率实时显示；与手算一致（误差 < 0.01%）。
- **状态**：⏳ 规划阶段（依赖 BUG-1）｜ **优先级 P2**

### R6 · PDF 图纸库集成（详情页直接预览）
- **现状**：PDF 三处入口一律不上云（铁律，`12` §4）；本地保留 PDF，线上禁传。
- **要改成**：详情页可直接预览 PDF 图纸（本地端优先）；线上受存储限制 + 合规铁律，后续版本迭代。
- **⚠ 冲突提示**：与 `12` §4 铁律「PDF 三处入口一律不上云」冲突——线上预览需重新评估合规与存储；**本地端可先行，线上端待勇哥拍板**。
- **EARS**：
  - *Where* [房源存在本地 PDF 且用户处于本地端]，the system shall 在详情页提供 PDF 内联预览。
  - *If* [处于线上只读端]，*then* 系统应仅展示「PDF 仅在本地端可看」提示，不泄露文件。
- **验收**：本地端详情页点开 PDF 预览；线上端不出现 PDF 链接。
- **状态**：⏳ 后续版本（存储 + 合规待评估）｜ **优先级 P3**

### R7 · 收藏 + 标签（房源 / 客户追踪）
- **现状**：无收藏 / 标签。
- **要改成**：房源可收藏 + 打标签（如「已推王先生」「急售」），按客户 / 需求追踪对比；本地端优先，跨端同步待定。
- **关联**：与 `12` §2.5.5 **N4 收藏 + 备注 + 标签** 一致，合并跟踪，勿重复立项。
- **EARS**：
  - *Ubiquitous*：系统应允许用户对任意房源添加收藏与自定义标签。
  - *Event-driven*：When [用户为房源添加标签 T]，the system shall 在查询 / 对比中可按 T 过滤。
- **验收**：收藏后列表标记；按标签过滤命中对应房源。
- **状态**：⏳ 远期规划（合并 N4）｜ **优先级 P3**

### OPS-1 · 抓取频率：1 天 3–4 次（07:00–23:00）★ 会议决策
- **现状**：每 2 小时抓一次（7:00–23:00，约 5–6 次/天），纯手搓。
- **决策**：会议（梓榮 / Hayden / 勇哥）定——市场新放量有限，改为 **1 天 3–4 次**，满足「今天查到今天」（漏网房源出来不够快就真没了，故不必 2h 但也不能太少）。
- **落地**：调整 `config.yaml` 抓取间隔 / 次数（当前随机 1–2h / 2–3h）→ 目标 3–4 次均匀落在维护窗口内。
- **验收**：观察 1 周，每日抓取 3–4 次、覆盖 07:00–23:00；数据延迟 ≤ 抓取间隔；REINS 维护窗口（JP 23:00–07:00）不触发。
- **状态**：⏳ 待勇哥确认具体时刻表后改配置（运营决策）｜ **优先级 P1**

> 来源：勇哥 19:52 需求 ——「计划把线上空间打开，把 PDF 传到线上空间；权限暂不做要求，内部员工都可正常访问。线下从平台下载 PDF 后，线上版上传时也要同步上传，线上查询与线下一致。」
> 优先级：**高于** §10 登录权限（先打通数据同步，鉴权后做）。

### 9.1 目标（勇哥原话转写）
- 线下版从 REINS 平台把 PDF（図面/物件資料）下载到本地后，**线上版在下次同步时自动把同一份 PDF 推到线上空间**。
- 线上版的查询/详情页，要和线下版一样**能看到并打开这份 PDF**（所见即所得，不出现「线上无 PDF / 本地才有」的落差，除非本地本身就缺）。
- 范围：**离线→线上单向**（本地爬下来推上去）；线上不回写 PDF（员工不能在线上传 PDF，只能本地爬取后推）。

### 9.2 现状（代码事实，不猜不蒙）
| 环节 | 现状 | 代码位置 |
|---|---|---|
| 本地 PDF 下载 | crawler 把 PDF 落 `data/attachments/<物件番号>.pdf`（后台 `_PdfWorker`，原子改名 `.part`→`.pdf`） | `core/crawler.py:51` `_PdfWorker`；`core/pipeline.py:143` `_save_pdf` |
| PDF 下载可靠性 | ⚠ **已知缺口**：REINS「図面参照」是 `<button>` 无 href，`_pdf_url_of` 恒空；靠 `_download_pdf_by_click` 点按兜底，注释自承「今天 385 条新增、0 份 PDF 就是这个原因」（`core/crawler.py:223`） | `core/crawler.py:196-262` |
| 上传过滤 | `publisher.py` 的 `NEVER_UPLOAD = {"pdf_path","pdf_url","absent_runs"}` —— **PDF 字段被显式禁止上传** | `core/publisher.py:73-74` |
| 同步脚本 | `sync_to_publish.py` 只搬代码 + `site_data.json`（来自 `build_rows`，已剔除 PDF 列），**不复制 `data/attachments/`** | `tools/sync_to_publish.py` |
| 线上站 | `osaka-house-v2` = `OSAKA_PUBLIC=1` 只读 Flask 站，详情页 PDF 区块只在本地端渲染，线上不显示 | `osaka-house-publish/main.py`；`web/templates/*.html` |

### 9.3 铁律冲突与拍板（⚠ 关键 · 已拍板）
- 原铁律（PRD-18 §7.2 / MEMORY）：「**PDF 三处入口一律不上云**」「公网应用禁止 PDF 上传公开站点」。
- **经勇哥 2026-09-18 19:5x 拍板，正式推翻该铁律**（决策：允许房源 PDF 上云；视为已评估 REINS 合规风险）。研发可动 `NEVER_UPLOAD` 与同步管道。
- 合规提示（PM 视角）：PDF 是 REINS 図面/物件資料，含房源平面图等可能受限内容；外发到公网需确认不违反 REINS 数据使用条款。勇哥拍板即视为已评估合规。

### 9.4 设计草案（已按决策细化）
1. **本地下载可靠性前置**：先真机抽 20 套验证 PDF 实际覆盖率（勇哥此前在 v1.8.6 已要求「先取证再改」）；覆盖率低则先修 `_download_pdf_by_click` 命中率，再开同步。（决策 C：先接管道，缺失线上标「本地端才有」，不阻塞）
2. **同步管道**：`sync_to_publish.py` 增加一步——把 `data/attachments/*.pdf` 复制到 `osaka-house-publish/app_local/attachments/`；`publisher.NEVER_UPLOAD` 移除 `pdf_path`/`pdf_url`（或新增独立 `pdf_sync` 开关，默认随 detail 上云）。（决策 A：执行）
3. **线上 serve**：发布工程加 `/pdf/<物件番号>` 静态路由（带范围校验，防目录穿越）；详情页 PDF 区块改为「线上有则 iframe 内联预览，无则标『本地端才有』」。
4. **查询一致**：`pdf_path` 随 detail 上云，搜索/详情页与线下同口径（有 PDF 即显图标+可开）。

### 9.5 已拍板（2026-09-18 19:5x · 4 项全选推荐项）
- **A. 推翻铁律允许 PDF 上云** → **已拍板：是**（勇哥显式确认，铁律反转）。
- **B. 过渡期无鉴权，PDF 随线上站公开** → **已拍板：接受过渡期公开**，等 §10 登录做好再收口（符合「权限暂不做要求」）；不用 N2 访问码兜底。
- **C. 本地 PDF 下载有缺口，同步怎么处理** → **已拍板：先接管道**，缺失 PDF 线上标「本地端才有」（不阻塞）。
- **D. 线上 PDF 存储方式** → **已拍板：随包部署**（附件随代码包，简单，每次 sync 全量重传）。

### 9.8 决策摘要（2026-09-18 19:5x）
- 铁律反转：PDF 允许上云（A 通过）。
- 过渡期：PDF 公开裸奔，待 §10 登录收口（B 通过，不用 N2）。
- 质量策略：先通管道、缺失如实提示（C 通过）。
- 存储：随包部署起步（D 通过）。
- 仍待拍板：§10.4 E（角色模型）；G（N2 定位）因 B 已决暂无需。

### 9.6 验收
- 线下下载 N 份 PDF → 同步后线上 `/pdf/<no>` 可打开且字节一致（抽查 5 份 MD5/大小一致）。
- 线上详情页 PDF 区块与线下显示一致（有则预览、无则提示）。
- 缺失 PDF 的房源线上明确标注「本地端才有」，不谎称有。

### 9.7 风险
- **合规**：PDF 外发 REINS 条款风险（见 9.3）。
- **体积**：3870 套 × 每份 PDF 可能数百 KB~数 MB，随包部署会使发布包变大、sync 变慢（D 项决定缓解）。
- **下载缺口**：若 C 选「先接管道」，线上会出现大量「本地端才有」——属预期，非 bug。

## 10. 用户登录与权限（需求3 · 优先级在 PDF 同步之后）

> 来源：勇哥 19:52 需求（明确「优先级排在上述功能之后」）。
> 目标：线上站从「完全公开」变为「内部员工可登录」，并支持本地管理员工账户。

### 10.1 需求原文（勇哥）
- 两种登录方式：**(a) 手机号 + 密码**；**(b) 用户名称 + 密码**。
- 账户管理（本地）：用户名称/密码可**本地增加、删除、修改**。
- 线上登录后，用户**最多只能修改自己的密码**。
- 每个账户**默认可以清除密码**；**初始密码是随机码**，由勇哥通过其他方式提供给用户。

### 10.2 PM 叠加的严谨性（原需求不够全面/严谨处，需产品拍板 + UI 配合）
| # | 缺口 | PM 建议补全 |
|---|---|---|
| P1 | 密码怎么存？ | **必须哈希存储**（bcrypt/argon2），明文存=重大安全事故；与「REINS 凭据不入库」是两回事，员工密码单独一张表。 |
| P2 | 「清除密码」语义歧义 | 清除后该账户变成「无密码」还是「禁用」？建议：清除=禁用登录（需重新设密码才能登），而非变成任何人可登的幽灵账户。 |
| P3 | 初始随机码如何交付/丢失 | 随机码由勇哥线下给（微信/口头）；需定义「码丢失」流程（管理员重置 + 重新生成随机码）。 |
| P4 | 手机号校验 | 手机号格式/唯一性校验；「手机号+密码」与「用户名+密码」是否允许同一人双通道？ |
| P5 | 登录态 | session/cookie/token？超时？同账户多端登录是否允许？建议：服务端 session，30 分钟闲置过期，单端优先。 |
| P6 | 权限分级（你说「线下权限设置」） | 「内部员工都能看」是默认；但需定义**角色**：员工（只读+看 PDF）/ 管理员（管账户+可重置他人密码+可设初始码）。否则「权限设置」无对象。 |
| P7 | 修改密码边界 | 「最多修改自己密码」= 员工只能改自己；管理员可重置他人。需 UI 区分「修改我的密码」vs「管理员重置」。 |
| P8 | 审计合规 | 房源 PDF 属敏感外发，**登录日志 + PDF 查看/下载日志必留**（谁、何时、哪套），合规与追溯需要。 |
| P9 | 忘记密码 | 员工忘记→找管理员重置（生成新随机码）；无「自助找回」（内部系统，不需邮件/SMS 找回链路，降低复杂度）。 |

### 10.3 设计草案（待拍板后细化）
- **本地账户表** `accounts(name, phone, pwd_hash, role, cleared, created_by, created_at)`，勇哥本地 `config.local.yaml` 或独立 `accounts.db` 管理（不进 git）。
- **登录接口** `/api/auth/login`（手机或用户名 + 密码）→ 成功发 session；`/api/auth/change-pwd`（仅自己）；管理员 `/api/auth/admin/*`（增删改+重置+生成随机码）。
- **线上鉴权中间件**：除登录页/静态资源外，所有 `/api/*` 与页面需已登录 session；未登录跳登录页。
- **N2 访问码**：可作为「无账户也能看」的轻量兜底（与正式登录并存或二选一，待拍板）。

### 10.4 待拍板 / 已决
- **E. 角色模型**：是否采用「员工/管理员」两级（推荐）；还是先全员平权、后续再加。→ **仍待拍板**。
- **F. 与 PDF 同步的先后**：→ **已决**：§9 先做、§10 后做（按你优先级）；过渡期 PDF 公开风险按 §9.5-B 收口（接受公开、不用 N2，登录后收口）。
- **G. N2 访问码定位**：→ **已决（§9.5-B 通过）：过渡期不用 N2 兜底**，等正式登录做好再收口。

### 10.5 验收
- 手机号/用户名 + 密码均可登录；错误密码被拒。
- 员工登录后仅能改自己密码；管理员可增删改账户 + 重置他人 + 生成随机码。
- 清除密码后该账户无法登录（需重置）。
- 未登录访问线上站任意页跳登录；PDF 查看留审计日志。

### 10.6 优先级说明
- **本需求明确排在 PDF 同步（§9）之后**。
- 但 §9.5-B / §10.4-G 提示：若选「过渡期 PDF 公开」，则 §10 应尽早排期收口，避免敏感 PDF 长期裸奔。
