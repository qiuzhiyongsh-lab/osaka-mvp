## 0. 设计原则（PM 视角，贯穿全文）

1. **密码永不明文**：员工密码独立表、哈希存储，与「REINS 凭据不入库」是两回事。
2. **最小权限**：员工默认只能看 + 改自己密码；一切管理动作归管理员。
3. **可追溯**：登录 / 管理操作 / PDF 查看下载必留审计日志（房源图面属敏感外发）。
4. **可逆 & 不锁死**：账户系统异常时，管理员应急码可兜底进入（N2 改造）。
5. **不猜不蒙**：凡代码/需求未证伪处标 `[待确认]`，不凭空写死。

## 1. 目标与范围

- **目标**：线上展示站从「完全公开」变为「内部员工凭账号登录」，本地可管理员工账户与角色；登录收口后顺带收掉 §9 的 PDF 裸奔。
- **范围（已定）**：
  - 线上展示站（`osaka-house-v2`）：需登录才能看房源/PDF；员工管理后台**不放在线上**（账户数据在本地，见 §10）。
  - 本地 8765 管理工具：账户数据本地存；首管理员由勇哥本地建立。
- **范围外（本期不做）**：手机号登录、自助找回密码、SSO/OAuth、外部客户账号。

## 2. 角色模型（已拍板：两级）

| 角色 | 标识 | 能力边界 |
|---|---|---|
| **员工 Employee** | `role=staff` | 登录后：查列表 / 看详情 / 看单套 PDF / 对比 / 收藏 / **改自己的密码**。不能碰设置、不能管账户、不能发布、不能批量下 PDF。 |
| **管理员 Admin** | `role=admin` | 员工全部能力 + 设置页（抓取/定时/番号検索）+ 账户与权限管理 + 数据发布/上传 + PDF 批量下载/导出 + 持应急码。 |

> 不做「访客/三级」：过渡期公开由 §9.5-B 已接受，登录收口后**不再保留公开层**（勇哥选两级 + N2 改应急码，已隐含此意）。[待确认] 是否绝对禁止公开访问（见 §13 待确认 Q3。

## 3. 功能权限矩阵（已拍板：4 项仅管理员）

| 功能 / 页面 | 员工 | 管理员 | 未登录 |
|---|---|---|---|
| 房源列表 / 搜索 / 详情 | ✅ | ✅ | ⛔ 跳登录 |
| 单套 PDF 在线查看 | ✅ | ✅ | ⛔ |
| 对比 / 收藏 | ✅ | ✅ | ⛔ |
| 设置页（抓取配置 / 上传定时器 / 番号検索） | ⛔ | ✅ | ⛔ |
| 账户与权限管理（增删改 / 重置 / 随机码 / 改角色） | ⛔ | ✅ | ⛔ |
| 数据发布 / 上传到线上 / 触发重算 | ⛔ | ✅ | ⛔ |
| PDF 批量下载 / 导出 | ⛔ | ✅（留审计） | ⛔ |
| 「修改我的密码」 | ✅（仅自己） | ✅（自己+重置他人） | ⛔ |
| 登录页 / 静态资源（css/js/登录相关） | — | — | ✅（免拦截） |

> 实现：服务端鉴权中间件（`@login_required` 装饰器 + 角色检查），未登录访问任意非白名单路由 → 跳登录页；员工访问 admin-only 路由 → 403 提示「无权限」。

## 4. 登录与认证（已拍板：仅用户名+密码；N2→管理员应急码）

### 4.1 凭证
- **登录名 = 用户名（唯一）**；**不采集手机号**（原 P4 手机号通道取消）。
- 密码：6–32 位，建议含字母+数字（强度规则 `[待确认]`）。

### 4.2 登录流程
1. `/login` 页输入 用户名 + 密码 → `POST /api/auth/login`。
2. 服务端查 `accounts`，`bcrypt` 校验 `pwd_hash`；**连续 5 次失败锁 15 分钟**（防爆破，`[待确认]`）。
3. 成功 → 签发服务端 session（§8），跳回原页面或首页。
4. 失败 → 不暴露「用户不存在 / 密码错」区分（统一「用户名或密码错误」）。

### 4.3 N2 访问码 → 管理员应急码（已拍板）
- **定位**：账户系统异常 / 全员锁死时的后门，**仅管理员知晓**，不作日常登录。
- **机制**：复用现有 `config.public.access_code`（本机真值，不入库）；但语义从「公开访问口令」改为「应急码」。
- **使用场景**：① 首管理员未建立时勇哥用应急码进；② 账户表损坏 / 全员被锁时管理员凭应急码 + 用户名进，进后立即重置。
- **安全**：应急码登录后强制要求改密码 / 重建账户；应急码本身建议定期轮换 `[待确认]`。
- **与正式登录关系**：正式登录做好后，普通访客**不再能用应急码进**（应急码仅对 `role=admin` 的用户放行，或仅用于解锁）。

## 5. 账户生命周期

| 动作 | 谁可做 | 说明 |
|---|---|---|
| 创建员工 | 管理员 | 填用户名 + 系统生成**初始随机码**（12 位，含大小写+数字）；随机码由勇哥线下（微信/口头）给员工。**首管理员**由勇哥本地 seed（§10）。 |
| 改自己密码 | 员工/管理员 | `/api/auth/change-pwd`，需旧密码；改后旧 session 失效。 |
| 清除密码 | 管理员 | =**禁用登录**（非幽灵账户）：`cleared=1`，该账户无法登录，需管理员重置设新随机码才能登。 |
| 忘记密码 | 员工→找管理员 | 管理员「重置」→ 生成新随机码，员工用随机码首次登录后须改密码。无自助找回链路。 |
| 删除账户 | 管理员 | 软删（`deleted_at`），保留审计关联；不能删自己 / 不能删最后一名管理员。 |
| 改角色 | 管理员 | staff⇄admin；不能把唯一管理员降为 staff。 |

## 6. 密码存储（建议，待确认强度）
- `accounts.pwd_hash` 用 **bcrypt**（cost=12），**明文/可逆加密一律禁止**。
- 表独立、不进 git；与 `config.local.yaml` 的 REINS 凭据隔离。
- 初始随机码**不存明文**：存其 bcrypt hash，员工首次登录即用随机码作「旧密码」改密。

## 7. 会话与登录态（建议，待确认）
- **服务端 session**（Flask 签名 cookie 或 server-side store），`OSAKA_SESSION` cookie，`HttpOnly`+`SameSite=Lax`。
- **超时**：闲置 **30 分钟**过期（具体时长 `[待确认]`）。
- **单端优先**：同用户名新登录使旧 session 失效（防多端共享账号）。
- 未登录访问 → 跳 `/login`；员工越权 → 403 页。

## 10. 首管理员建立方式（建议，待确认）
- **方案 A（推荐）**：勇哥本地执行一次性脚本 / 或 `config.local.yaml` 内置 `bootstrap_admin`（用户名+初始随机码），启动时空表则自动建首 admin。
- **方案 B**：首次部署后用应急码进，再在后台建 admin。
- 选 A 最稳，避免依赖应急码。

## 11. 验收标准
1. 用户名+密码登录成功；错误密码/不存在用户均被拒且不泄区分。
2. 员工登录后仅能改自己密码；点设置页/账户管理/发布 → 403。
3. 管理员可增删改账户 + 重置他人 + 生成随机码 + 改角色 + 发布 + 批量下 PDF。
4. 清除密码后该账户无法登录；删除不删自己/不删最后 admin。
5. 未登录访问线上任意页跳登录；PDF 查看/下载留审计日志。
6. 应急码仅在账户系统异常时由管理员使用，日常不可用其进普通浏览。

## 14. 切换方案（双链接并行 · 勇哥 22:0x 新增）

> 目标：账号系统上线**不硬切**，过渡期两链接同时可访问，平滑迁移；PDF 功能在账号可用后才上线。

### 14.1 两个链接
- **A. 正式站（认证版）**：启用账号登录。未登录访问任意非白名单页 → 跳登录页；**登录页显著位置提供「临时备份页」入口链接（去 B）**，方便尚未建账号/未登录的员工临时使用。
- **B. 临时备份页（匿名版）**：与**当前线上站完全一致**（公开、无登录、PDF 公开），作为切换期替代方案；保留一段时间（时长 `[待确认]`，建议观察期 1–2 周或至全员账号激活）。

### 14.2 B 的切换提示（每次页面切换）
- B 顶部**常驻 banner**：「您正在使用临时备份页，功能将停用，请到正式站登录以正常使用」。
- **每次路由切换（SPA 导航）额外弹一次非阻塞提示**（toast / 轻 modal）：「请到正式站登录后才能正常使用全部功能」——`[待 UI 确认]` 用 toast 还是 modal，及是否每日仅首屏弹一次。
- 目的：温和引导迁移到 A，**不阻断 B 的正常使用**。

### 14.3 切换完成条件与收口
- 条件：员工账号已可正常使用（勇哥验证通过）+ 观察期结束。
- 收口动作：① 撤下 B（或 B 301 跳 A）；② **PDF 功能上线**：账号就绪后，再把 PDF 上云/收口落到 A（见 §14.5）；B 上的公开 PDF 随 B 下线停止。
- 与 §9 关系：§9 PDF 上云已拍板，但**实施排期后置到账号系统可用之后**（勇哥 22:0x 明确）。

### 14.4 部署架构（`[待确认]`）
- 需**两个独立部署**：A（认证版，新代码）与 B（当前公开快照，加 banner+切换提示）。
- URL 分配 `[待确认]`：方案 X 复用 `osaka-house-v2` 为 A、新增 `osaka-house-temp` 为 B；方案 Y 反之。取决于哪个域名对外通知员工。
- 数据：A / B **共用同一份房源数据**（同一 DB / sync），仅鉴权与 UI 提示不同。

### 14.5 时序（勇哥 22:0x 排期）
1. 账户系统研发（Q1–Q8 已定，勇哥预期 ~2h，待 RD 核实）。
2. 部署双链接：A 认证版上线（初始仅勇哥 admin + 应急码可用）、B 临时备份页上线（加 banner + 切换提示）。
3. 勇哥验证 A 账号可用（登录 / 改密 / 员工管理 / 角色）。
4. 账号可用 → **PDF 功能上线**（上云 + 收口到 A，B 公开 PDF 随之下线）。
5. 观察期 → 撤 B，全面切 A。

## 15. 风险与合规
- **应急码泄露**：应急码等同 admin，须仅线下给管理员 + 定期轮换（§4.3）。
- **PDF 敏感**：收口前 §9 过渡期仍裸奔，本系统上线即收（§12 依赖）。
- **审计合规**：房源图面外发日志必留，满足追溯（§8）。
- **不进 git**：账户表、REINS 凭据、应急码均本机存，发布同步脚本须继续剔除（沿用 §9 凭据剥离机制）。
- **双链接期数据一致性**：A/B 共用同一 DB，但 B 无鉴权 → 过渡期 B 仍裸奔 PDF；须明确「B 下线前 PDF 不视为已收口」，避免误判合规。（§14.3）

### 16.2 本地 8765 启用 Auth 的配置步骤（config.local.yaml，gitignored）
在 `config.local.yaml`（本机真值，不入库）追加：
```yaml
app:
  session_secret: "<32位随机串，稳定不随重启变>"
accounts:
  auth_enabled: true            # 翻 True 即开启账户拦截
  bootstrap_admin:             # 仅首次启动自动建首管理员；之后改密即覆盖
    username: admin
    password: "<强密码，8–20位字母+数字>"
public:
  access_code: "<管理员应急码，仅线下给管理员>"   # N2 改造为应急后门（§4.3）
```

## 17. 线上账户供给策略变更（2026-09-19 00:0x 勇哥决策）

> **推翻 §10 / §16 的「线上永不开启账号」设计。**
> 原设计顾虑：线上无账户、无管理后台 → 一旦开启强制登录会锁死。
> 现改为**账户由线下播种并同步上云**，锁死风险解除，故该保护撤销。

### 17.1 决策要点（勇哥拍板）
1. **线上初始账户由线下建立并通过同步管道上云**；线上**不具备**首次创建账户的能力（无 bootstrap_admin 语义）。
2. **默认账户 4 个**（勇哥选定：含演示禁用态的 wangfang）：

| 用户名 | 角色 | 初始状态 | 说明 |
|---|---|---|---|
| `yongge` | 管理员(admin) | 正常 | 勇哥本人；拥有设置 / 账户管理 / 发布全部权限 |
| `zhangyc` | 员工(staff) | 正常 | 只读 + 看 PDF + 改自己密码 |
| `liwen` | 员工(staff) | 待改密 | 首次登录强制改密 |
| `wangfang` | 员工(staff) | **已禁用** | 演示禁用态；管理员解锁后可登 |

3. **初始凭据**：每人一个 **12 位随机码**（大小写 + 数字），由 `secrets` 真随机**在本机生成**；生成后**仅打印一次**交勇哥线下（微信 / 口头）分发 —— **不进 git、不进记忆文件、不进日志文件**。
4. **N2 访问码**保留「管理员应急码」定位（§4.3）：凭 N2 可登录查看，管理员可进一步设置。

### 17.2 同步策略（UPSERT —— 勇哥选定）
线上表按 `username` 唯一键做 UPSERT：
- **新增**：本地有、线上无 → 插入（含初始随机码哈希）
- **更新**：`role` / `disabled` / `display_name` → 每次以本地为准
- **不覆盖**：线上用户若**已改过密码**（密码哈希已非初始随机码哈希）→ 同步时**跳过 `pwd_hash`**，避免把线上自立修改冲掉

> 本地要强制重置某员工密码时，走管理员显式的「重置随机码」动作，该动作带 `force_reset` 标记，下次同步才下推覆盖。

### 17.3 播种流程
1. 本机运行一次性脚本 `tools/seed_accounts.py`：生成 4 个随机码 → 写入本地 accounts 表 → 导出 `accounts.seed.json`（**只含哈希，不含明文**）→ 打印「用户名 = 随机码」对照表给勇哥
2. 跑 `sync_to_publish.py`：种子文件随发布包上云
3. 线上启动：accounts 表为空则导入种子；非空则按 §17.2 UPSERT
4. **防锁死兜底（必须有）**：若线上 accounts 表为空且未拿到种子 → 自动降级 `auth_enabled=False`（开放态）并打日志 —— **绝不允许把自己锁在门外**
