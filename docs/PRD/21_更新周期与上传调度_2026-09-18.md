## 1. 需求原文（勇哥两张截图）

**截图1（更新方式）**：改了「下限/上限/时段」保存后，「下一轮更新」时间没跟着变（页脚/概览仍显示旧的下一次时间）。
**截图2（上传到线上）**：现有只有「① 自动完成 / ② 手动方式」两种模式 + 月份 + 口径，没有独立的启动/暂停、没有上传周期、没有日期段选择。勇哥要求：
- 默认「启动中」，每 **10 分钟上传一次**；
- 加一个**上传周期的时间设置**并测好用；
- 可以**选择日期段**。

## 3. 设计（产品经理带着做 · 四角色视角）

### 3.1 需求1：更新周期热重算（修复 bug）
- **根因**：`scheduler._loop` 的 `next_run_at` 只在**每轮跑完瞬间**算一次；保存设置只改 `SCHED.cfg`、**不打断正在进行的分片 sleep、不重算** → 下一轮仍按旧参数。
- **修复**：`Scheduler` 加 `_rearm = threading.Event()` + `rearm()` 方法；`_loop` 分片 sleep 循环里检查 `self._rearm.is_set()` → 清位、打「⟳ 下一轮已按新参数重算」、`continue`（立即进入下一轮顶部重新算 `delay`/`next_run_at`）。保存设置 API 调 `SCHED.rearm()`。
- **验收**：保存设置后 ≤5 秒，概览页「下一轮」时间按新「下限/上限/时段」刷新；进行中的轮次不被打断。

### 3.2 需求2：上传独立定时器 + 日期段
- **解耦**：原上传是 `scheduler._tick` 尾巴的 `_auto_push()`（抓完立刻推，间隔=抓取间隔）。新增 `PublishLoop` 独立线程，**与抓取轮互补**：
  - 抓取轮尾巴 `_auto_push` = 抓完最新鲜推送；
  - `PublishLoop` = 周期兜底（即便长时间不抓、`_auto_push` 失败，也能按周期补推）。
  - 两者都走 `publisher.publish(incr)` 水位线，幂等、不重复。
- **周期**：`publish.interval_minutes`（默认 10，下限夹 1 分钟，防高频刷线上接口）。
- **日期段筛选**：`_scope_where` 扩展 `date_from/date_to`：
  - `download` 口径 → `COALESCE(last_seen_at, first_seen_at)`（本地下载日）；
  - `platform` 口径 → `COALESCE(chg_date_iso, reg_date_iso)`（平台登録/変更日）；
  - `date_to` 若只给 `YYYY-MM-DD` 自动补 `23:59:59`（闭区间更直观）；
  - 没填日期段时回退旧 `month_scope`（兼容）。
- **预览**：`preview_scope()` 只算不发（设置页「预览会传多少」按钮用），先验证范围再推，避免推完才发现范围错。
- **UI（collect.html）**：「上传到线上」卡加——启动/暂停按钮（实时反映 `loop.running`）、周期输入框(分)、日期段(起/止 `type=date`)、预览按钮、下次上传时间；轮询 5s 保持状态新鲜。
- **API（app.py）**：
  - `/api/publish/settings` 扩 `auto_enabled/interval_minutes/date_from/date_to` 四键 + 启停 `PUB_LOOP`；
  - `/api/publish/toggle`（启动/暂停，返回 `message`，PUBLIC 模式禁用返回 403）；
  - `/api/publish/preview`（返回 `count` + 前 5 样本）；
  - `/api/publish/status` 带 `loop` 状态（running/next_run_at/last_count）；
  - 启动接线：`__main__` 里 `if not PUBLIC and auto_enabled: PUB_LOOP.start()`。
- **i18n**：`pub.date_from/to/auto/interval/preview/on/off/pause/start/next/previewing/preview_count/preview_fail` 共 13 键 × 4 语言（zh-TW/en/ja/ZH）。

## 5. 影响面与风险

- **`scheduler.py`**：新增 Event + rearm，改动集中在 `_loop` 分片 sleep；不影响抓取主逻辑（仅重算时机）。
- **`publisher.py`**：`_scope_where` 向下兼容（无日期段回退月份）；新增 `PublishLoop`/`preview_scope` 为纯增量，不动既有 `publish()`/`build_rows()`。
- **`app.py`**：新增 2 个 API + 扩展 2 个；启动接线用 `if not PUBLIC` 包裹（线上展示版不启上传定时器，与既有调度一致）。
- **`config.yaml`**：`publish` 段新增 4 键（默认 `auto_enabled:true/interval_minutes:10/date_from:''/date_to:''`），旧 `month_scope/scope_caliber` 保留兼容。
- **风险**：`preview_scope` 是新增函数，若缺失会导致 `/api/publish/preview` 运行时 `ImportError` → 已补全并写离线单测覆盖（见 §6）。

## 6. 离线单测（tools/test_publish_scope.py）

不连 REINS/Flask/线上，直接 import core 做确定性断言：
- `_scope_where`：download/platform 两口径日期段 SQL + 闭区间上界补 `23:59:59` + 无筛选回退 `1=1` + 月份回退 + incr 水位线叠加；
- `PublishLoop._interval_seconds`：<1 夹 1、默认 10、负数夹 1；
- `preview_scope`：in-memory sqlite 真库计数（9 月内 last_seen_at → A001/A002/A004 共 3 行，A004 虽 is_active=0 仍计入——与 `build_rows` 一致、不过滤 is_active，保证「预览==真推」；8 月 A003 落外；platform 口径(用 reg/chg)同样 3 行；无筛选 1=1 → 4 行全在）；
- `scheduler.rearm`：Event 置位/清零语义。
- 运行：`python tools/test_publish_scope.py` → 全 PASS 退出 0，否则退出 1 + 失败明细。

> ✅ **验证已本地实跑（`py_compile` 全绿 + 单测 19/19 PASS）**：Shell 通道恢复后已跑通，并抓出、修复 2 个真 bug——① `preview_scope` 重复定义死代码（已删，留 `_scope_where` 版，保证「预览 count==实际推送 count」）；② `preview_scope` 原强依赖 `con.row_factory=Row`（`cnt["c"]`/`dict(r)`），连非 Row 连接会 `TypeError` → 「预览」按钮在特定连接态下 500，改 `cnt[0]`/`dict(zip(cols,r))` 后任何连接都能跑。门禁③真机 e2e 仍由勇哥双击重启 8765 复验（看 `server.log` 3 条标记 + 设置页交互），未复验前不发布。
