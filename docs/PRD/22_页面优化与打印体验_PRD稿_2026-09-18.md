## 1. 背景与范围（结论先行）

勇哥指出：对比页直接 `Ctrl+P` 打印时，**部分信息超出一页横向范围**（实测需手动缩放 90% 才勉强进）。v1.9.12 已用纯前端手段根治该问题（详见 §3 已落地基线）。

但勇哥进一步明确：**「页面优化」应单独成文，且「它可能和显示页面有一些区别」——显示态与打印态应由 PM + UI 共同设计，而非只靠工程师顺手改 CSS。**

本稿把两件事分开：
- **A. 打印态（print）**：用户 `Ctrl+P` 调出打印机时的版式——目标是一页容下、不留白、不打断。
- **B. 显示态（screen）**：浏览器里正常看的版式——目标是信息密度高、可读、移动友好。

两者**刻意允许不同**（例如打印态隐藏导航/按钮、压缩字号；显示态保留完整交互），本稿把这种「差异」作为**设计对象**，由 PM+UI 评审定稿，而非工程默认。

## 2. 已落地基线（v1.9.12，线上已生效，仅供 PM+UI 评审起点）

> 以下已是线上现状，本稿**记录不重复实现**；PM+UI 在此基础上决定要不要改、改到什么程度。

| 项 | 现状（v1.9.12） | 位置 |
|---|---|---|
| 对比页打印方向 | `@page{ size:A4 landscape; margin:3mm }` 强制横向 | `web/templates/compare.html` 内联 `<style>` |
| 打印一页容下 | grid 列 `minmax(0,1fr)`（允许收缩到 0）+ 清零 `.wrap` 横向 padding/margin + 单元格 `min-width:0;overflow:hidden` + 字号 7px | 同上 |
| 打印隐藏非打印 UI | 顶部导航 / 页脚 / 工具栏 / 滑动提示 / 结论卡 / 操作按钮 `display:none` | 同上 |
| 进入默认隐藏中介 | `hideAgency=true` 默认 + `body.hide-agency` 闸门（按钮可切回） | 同上 `compare.html` JS |
| 字段名加粗 | 查询页筛选 label / 对比页字段列 / 详情页字段名 统一 `font-weight:700` | `web/static/style.css`（v1.9.10） |

**用户实测结论**：v1.9.12 后，对比页 `Ctrl+P` → 选「横向」→ **100% 缩放**即可整表一页（此前需手动 90%）。

## 3. 待 PM+UI 共同设计的差异空间（本稿核心）

> 以下为「显示态 vs 打印态」允许不同、需 PM+UI 拍板的设计点。**不替 PM/UI 下结论，只列决策清单**。

### 3.1 打印态设计（A）

| # | 决策点 | 现状 | 待 PM+UI 定 |
|---|---|---|---|
| P1 | 打印触发方式 | 用户手动 `Ctrl+P` | 是否加「打印此对比」按钮（调用 `window.print()`，预选横向）？ |
| P2 | 缩放策略 | 浏览器默认 + 用户手调 | 是否强制 `@page` 100% 不容用户改（防溢出）？还是留「适合」？ |
| P3 | 打印内容范围 | 全字段 | 是否提供「仅核心参数打印」开关（减少行数，进一步保一页）？ |
| P4 | 跨页一致性 | 仅对比页有 `@media print` | 查询页 / 详情页 / 房源卡是否也要统一打印风格（当前无打印样式，会截断）？ |
| P5 | 打印页眉页脚 | 浏览器自带（URL/日期） | 是否用 CSS 自定义页眉（房源来源/导出时间），去掉浏览器默认？ |
| P6 | PDF 导出 | 用户用系统打印→存 PDF | 是否做「导出 PDF」按钮（html2pdf 前端生成，脱离打印对话框）？ |

### 3.2 显示态设计（B）

| # | 决策点 | 现状 | 待 PM+UI 定 |
|---|---|---|---|
| S1 | 信息密度 | 紧凑 grid，首列 86px、套房列均分 | 桌面端是否需要「宽松/紧凑」切换？ |
| S2 | 中介公司默认隐藏 | 进入即隐藏，按钮可显 | 是否改为「只隐藏中介公司、其它其他详情仍显示」（更细粒度）？ |
| S3 | 移动端适配 | 横向滚动 `.cmpscroll` | 移动端是否改为纵向堆叠卡片（而非横向挤）？ |
| S4 | 颜色/对比 | 最优标记绿、核心字段黄底 | 配色是否按 PM 品牌规范统一（与登录页/员工页一致，见 PRD-19 mockup）？ |
| S5 | 字段名加粗范围 | 查询/对比/详情三页已 700 | 工具栏「排序/方向」标签是否也加粗（PRD-18 §13 待勇哥一句话）？ |

### 3.3 显示态与打印态的「差异契约」（PM+UI 需明确）

> 勇哥原话核心：**显示页和打印页可以不一样**。建议 PM+UI 把这条写成显式契约：

- **允许不同**：字号、隐藏元素（导航/按钮）、背景色强制打印、列宽策略。
- **必须相同**：房源数据本身（同一份 `detail_json`）、字段含义、单位（円/㎡）、最优标记判定逻辑。
- **禁止**：打印态伪造/省略房源字段（用户打印就是要完整证据）。

## 4. 验收标准（打印态，可量化）

- **AC-1**：对比页选 2–6 套房源 → `Ctrl+P` → 选「横向」→ 100% 缩放 → **1 张 A4 容下全部列与全部行**，无横向溢出、无列被切。
- **AC-2**：打印输出不含顶部导航、页脚、工具栏、操作按钮（仅房源对比内容）。
- **AC-3**：进入对比页默认不显示中介公司等「其他详情」；点「显示其他详情」可恢复；该默认对本地 8765 与线上站同时生效。
- **AC-4**（若 P6 做导出 PDF）：点「导出 PDF」生成的文件与 `Ctrl+P` 横向打印版式一致。

## 5. 排期建议

- **已上线**：v1.9.10（字段名加粗）+ v1.9.12（对比页打印一页 + 默认隐藏中介）。纯前端，零后端依赖。
- **待 PM+UI 评审后**：P1–P6 / S1–S5 / 差异契约 → 拆分到后续版本（建议作为 v1.10.x 的「页面打磨」主题，与 PRD-19 账号权限可并行，互不阻塞）。
- **依赖**：无硬依赖；若做 P6 导出 PDF（html2pdf）需评估前端包体积（发布站裁剪 playwright 的同款考量，见 PRD-18 §11）。

## 6. 风险与合规

- **R-1 打印态伪造数据**：禁止打印态省略/改写房源字段（见 §3.3 契约）。
- **R-2 跨页不一致误导**：若只给对比页做打印样式、查询/详情页不做，用户在不同页 `Ctrl+P` 体验割裂 → 建议 P4 统一三页打印风格（PM 拍板优先级）。
- **R-3 缓存**：打印样式靠 `?v=` 强刷；若用户仍见旧版，硬刷新（Ctrl+F5）一次。
