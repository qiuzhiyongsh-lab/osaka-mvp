## 0. 结论先行（三句话）

1. **需求反转**：历史上「PDF 一律不上传线上」的口径**作废**。新口径 = **PDF 必须上传到线上**，供已登录用户查看 / 下载。
2. **红线保留并升级**：**展示时不得使用明文** —— 不得把明文文件路径（`pdf_path`）或可直接访问的明文直链（`pdf_url`）下发到前端页面或数据包；访问必须经**登录鉴权 + 受控接口**。
3. **本次是"能力新增"，不是"补漏洞"**：现状是**完全不上传且线上取不到**（闸门拦 + 列丢弃 + 路由 404），并不存在"PDF 已泄漏到线上"的问题；因此本 PRD 的重心是**托管方案 + 安全展示设计**。

### 2.1 关键设计约束（红线）

| 约束 | 说明 |
|---|---|
| **不明文** | 页面 DOM、XHR 响应、`site_data.json` 中**不得含** `pdf_path`、本地绝对路径、可直接下载的明文直链 |
| **不裸奔** | PDF 接口必须在登录态之后；未登录一律 401/302，与现有 `_access_guard` 行为一致 |
| **不越权** | 低权限账号不得通过猜测 id 拿到他人/受限物件 PDF |
| **可审计** | PDF 访问建议留痕（谁、何时、哪套房），复用 `audit_log` |

## 3. 验收标准（AC）

| AC | 判定方式 |
|---|---|
| AC1 | 线上 `site_data.json` 与任意页面响应中，`grep pdf_path/pdf_url` 均为 0 命中 |
| AC2 | 未登录访问 PDF 接口 → 401 或 302（与现有守卫一致） |
| AC3 | 登录后通过页面按钮可查看指定物件 PDF，且地址栏/网络面板**不出现**本地路径或明文直链 |
| AC4 | 低权限账号访问受限 PDF → 拒绝（不返回文件内容） |
| AC5 | `tools/sync_to_publish.py --dry` 的 PDF 闸门：**明文**出现即拦、非明文的托管标识放行 |
