# 26 · PDF / 数据上传机制与「手工上传」页面设计稿

> 版本 v1.0.0　|　2026-09-23　|　PM + UI 联合设计（小巴起草，待勇哥评审）
> 触发：勇哥 2026-09-23 ——「设计上传机制，并增加手工上传的页面。可以分天或日期段上传，结合之前需要上传的内容，由 UI 与产品经理共同设计。」
> 关联：`osaka_mvp_pdf_online_prd.md`（PDF 上云 PRD）、`osaka_mvp_pdf_online_roadmap.md`、`tools/pdf_to_cos.py`（已实现的 MVP 上传器）

---

## 0. 结论先行

1. **一个页面统管三类上云内容**：PDF 文件（→ COS）、房源数据（→ 线上库）、AI 结构（→ 线上 AI 库）。
2. **两种触发**：自动（每轮抓完顺手推）+ 手工（按天 / 日期段补传）。
3. **先解决一个真问题**：现在 PDF 直链 **7 天过期后刷新页面也没用**（URL 是库里存的静态字符串）→ 必须建立**自动重签 + 增量回推**机制，否则线上 PDF 会周期性失效。

---

## 1. 背景：三个待解决问题（均已在 2026-09-23 取证）

| # | 问题 | 证据 |
|---|---|---|
| P1 | PDF 直链 7 天过期，页面刷新**不解决** | 签名写在 `site_data.json` 的 `pdf_url` 里，只在 sync/ingest 时更新。线上 `detail.html` 拿的是静态串 |
| P2 | 增量推送**不改**没变化的行 | `publisher.build_rows(mode=incremental)` 按水位线取"水位后被看过"的行；只重签、不改数据的房源**不会**被推 → pdf_url 不刷新 |
| P3 | 缺"按日期补传"的入口 | 目前只有 CLI（`pdf_to_cos.py --backfill` / `--test-one`），勇哥无法在 UI 上按天/日期段操作 |

---

## 2. 需求（EARS）

| ID | 类型 | 需求 |
|---|---|---|
| U1 | Ubiquitous | 系统须提供**一个**「云端同步」页，集中展示并操作三类上云内容（PDF / 房源 / AI 结构）。 |
| U2 | Event-driven | 当本地完成一轮抓取（新 PDF 落盘）时，系统须**自动**上传其 PDF 到 COS，并刷新预签名 URL。 |
| U3 | Event-driven | 当预签名 URL 剩余有效期 < 2 天时，系统须自动重签并**增量回推**该房源的 `pdf_url` 到线上。 |
| U4 | Event-driven | 当用户在页面上选择「日期段 + 数据类型」并点「开始上传」时，系统须按范围执行上传并**实时反馈进度**。 |
| U5 | State-driven | 上传进行中，页面须显示进度（已完成/总数、当前番号、成功/失败数），且**可继续浏览其它页面**。 |
| U6 | Unwanted | 若上传中途失败（网络/COS 限流），系统须重试 3 次后记录失败项，**不阻断**其余条目，并在结果区列出可"重试失败项"。 |
| U7 | Unwanted | 若某日无任何可上传内容，页面须显示"该范围内没有待上传内容"，而不是空列表或报错。 |
| U8 | Optional | Where 用户勾选「仅重签不重传」，系统须只刷新 `pdf_url` 而不重复上传文件。 |

## 3. 上传对象与口径（"结合之前需要上传的内容"）

| 对象 | 现通道 | 目的地 | 幂等键 | 说明 |
|---|---|---|---|---|
| **PDF 文件** | 本期新增 | COS 桶 `daban-pdf-*`（大阪） | `物件番号.pdf` | 值 = 7 天预签名直链 → 写 `properties.pdf_url` |
| **房源数据** | `/api/ingest`（v1.9.28+） | 线上 SQLite `properties` | `property_no` | 已含 `pdf_url` 列（v1.9.60 起随行上传） |
| **AI 结构** | `/api/ingest`（v1.9.38+，`ai_structure` 键） | 线上 `ai_pdf_store.db` | `property_no` | 1483 条；缺 conclusion/overall 的残缺记录不计入"有效" |

> ⚠ 口径提醒：**扫描日期一律用"平台/业务日期"**（`reg_date_iso` / `chg_date_iso`）或**本地落盘日**，**绝不用 `first_seen_at` 冒充**（项目铁律）。

---

## 4. 日期维度的定义（"分天或日期段上传"）

页面上提供**两种日期口径**下拉（默认①）：

| 口径 | 含义 | 数据来源 | 典型用途 |
|---|---|---|---|
| ① **本地下载日**（推荐默认） | PDF 落盘到 `data/attachments/` 的那天 | 文件 mtime | "把 9/22 那天抓下来的 PDF 传上去" |
| ② 平台登记日 / 变更日 | REINS 平台上的 登録年月日 / 変更年月日 | `reg_date_iso` / `chg_date_iso` | 按业务口径补传某批房源 |

**快捷范围**：`今天` / `近 7 天` / `近 30 天` / `本月` / `自定义起止` / `全部未上传`。

## 5. 触发机制（自动 + 手工）

```
┌─ 自动（常态，不需要人管）────────────────────────────┐
│ crawler 落盘新 PDF                                    │
│   └─→ [钩子] 上传 COS + 重签 → 写 properties.pdf_url   │
│        └─→ [增量回推] POST /api/ingest {rows:[{no,pdf_url}]} │
│ 定时（每天/每轮一次）扫描：签名剩余 < 2 天 → 重签 + 回推 │
└───────────────────────────────────────────────────────┘
┌─ 手工（页面上点，补历史 / 救急）─────────────────────┐
│ 「云端同步」页 → 选 日期段 + 对象 + 选项 → 开始上传    │
│   └─→ 后台任务 → 进度条 → 结果列表（可重试失败项）      │
└───────────────────────────────────────────────────────┘
```

### 6.2 交互规则（UI 侧）

| 场景 | 呈现 |
|---|---|
| 点「开始上传」前 | 必须先「预览」出命中条数；命中 0 → 按钮置灰（U7） |
| 上传中 | 进度条 + 当前番号 + 计数（**非阻塞**，可切去查询页，右上角常驻小进度条） |
| 上传完成 | 成功/失败分色统计；失败项可一键重试（U6） |
| 卡片红黄绿 | PDF 最早过期 < 2 天 = 黄；< 0（已过期）= 红；AI 残缺率高 = 黄（提示需重跑） |
| 空状态 | "该范围内没有待上传内容（可能已全部上传）"（U7） |
| 移动端 375px | 卡片竖排、日期控件堆叠、按钮全宽（项目 UI 硬要求） |
| 文案 | 简体中文为主（本页仅勇哥/本机使用，不进线上） |

## 7. 接口设计（RD 侧）

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/cloud/status` | 三张卡片的状态数据（已上传/待上传/最早过期/水位） |
| `POST` | `/api/cloud/preview` | 入参 `{scope, date_by, date_from, date_to}` → 返回命中条数与清单（**不执行**） |
| `POST` | `/api/cloud/upload` | 入参同上 + `{targets[], resign_only}` → 起后台任务，返回 `task_id` |
| `GET` | `/api/cloud/upload/status?task_id=` | 进度（已完成/总数/成功/失败/当前番号） |
| `POST` | `/api/cloud/upload/retry` | 重试失败项 |
| `POST` | `/api/pdf/resign-due` | 定时/手动：重签"剩余 < 2 天"的 URL 并增量回推（U3） |

**实现要点**：
- 上传器从 `tools/pdf_to_cos.py` **下沉为 `core/pdf_cloud.py`**（UI 与 CLI 共用一份逻辑，避免两套）。
- 增量回推复用 `publisher` 现有通道（`POST /api/ingest`，带 `X-Publish-Token`），**不需要发版**（只改数据 → 走 ingest 是既定设计）。
- 后台任务用线程 + 内存态（本地单实例，无需队列）；**绝不阻塞 Flask 主线程**。

## 8. 边界与异常

| 场景 | 处理 |
|---|---|
| COS 未配置/密钥失效 | 页面顶部红条"COS 未配置或密钥无效" + 指向操作手册 |
| 签名过期（已发生） | U3 自动重签兜底；前端加载失败显示"链接已过期，正在重新同步" |
| 本地停跑 > 7 天 | 线上 PDF 全失效 → 属于"必须本地常驻"的固有约束，页面黄条提示 |
| 上传中途关机 | 已上传的幂等（COS head 判存在），重跑只补缺口 |
| 同一番号重复上传 | COS 覆盖写 + 库内 `pdf_url` 覆盖 → 幂等 |

---

## 9. 验收标准

1. `/cloud` 页能看到三类内容状态；PDF 卡片数字与 `data/attachments` 实际份数一致（**真数据回读**，非"应该"）。
2. 选「9/22」→ 预览命中数与当日落盘 PDF 数一致（89）。
3. 点「开始上传」→ 进度实时、结果准确；中途切页不中断。
4. 上传后线上详情页**无需发版**即可看到新 `pdf_url`（走 ingest 增量）。
5. 造一个"剩余 < 2 天"的签名 → 触发重签 → 线上 URL 刷新（U3 生效）。
6. 375px 可正常操作。
