- 作者：小巴（PM/RD/UI/QA 多角色）

## 1. 需求原话与口径

> 「原先我的计划是，按了这个键以后，任务下发到线下的电脑里，让它读取这个 PDF 文件，
> 读取后把信息反向写回来。原先的这个链路就是让它当次直接完成。
> 我希望在 5~10 秒左右，任务能够完成并调回来，让我这儿能看得到。」

- 「这个键」= 线上详情页「详细信息」卡片标题行的**「重新生成」**按钮。
- 口径：线上员工点击 → 派发回**本地 8765**（唯一有 PDF 附件 + 抽取模型的地方）
  → 本地跑完把结果**回推线上** → **当次页面可见**，目标 5–10 秒。

## 2. 现状（为什么以前不行）

- 线上 `OSAKA_PUBLIC=1` 是只读站：没有 `data/attachments` PDF、没有抽取模型。
- `/api/ai/<no>/run` 在 PUBLIC 下直接 403（app.py:886「线上展示版只提供查询…」）——
  员工点了只看到红字，什么都不发生。

## 3. 方案（relay 接力）

```
线上详情页「重新生成」
  → POST /api/ai/relay/request（登录用户；写线上库 ai_relay_tasks 表，幂等）
  → 本地 8765 常驻线程每 2s GET /api/ai/relay/claim（X-Publish-Token 机器通道）
  → ai_pipeline.run_one(force=True, allow_cloud=False)   ← 守 v1.9.55 线下总闸，绝不烧钱
  → save_fields 落本地 AI 库（本地仍是单一权威源）
  → 该行 ai_structure POST /api/ingest（复用既有回推链路，无需发版）
  → POST /api/ai/relay/result 置 done
  → 线上前端每 2s 轮询 /api/ai/relay/status → done 后 loadAI() 刷新卡片
```

### 3.1 耗时预算（对照 5–10s 目标）

| 环节 | 耗时 | 依据 |
|---|---|---|
| 线上落任务 | <0.1s | 本地 SQLite insert |
| 本地领取 | 0–2s | 轮询间隔 2s |
| 本地抽取 | 0.5–6s（文字层）/ 10–30s（扫描件 OCR） | 实测 400140714422 = 5.9s；文字层常 <1s（v1.9.33 GAP-1 记录） |
| 回推线上 | 0.5–1s | /api/ingest 单行 |
| 前端感知 | 0–2s | 轮询间隔 2s |
| **合计** | **文字层 ≈2–8s ✅；扫描件更久但全程秒数进度可见** | |

- 扫描件抽取耗时不可压（OCR 是 CPU 活），但前端每秒显示「已派发…Ns / 排队中 /
  本地服务可能未连接」，用户全程知道在跑，不是「点了没反应」。

### 3.2 改动清单

| 文件 | 改动 |
|---|---|
| `web/app.py` | ① `ai_relay_tasks` 表（主库，懒建）+ `_relay_sweep` 超时清理；② 4 个端点：`POST /api/ai/relay/request`（登录）、`GET /api/ai/relay/status`（登录）、`GET /api/ai/relay/claim` + `POST /api/ai/relay/result`（X-Publish-Token）；③ `_access_guard` 豁免 claim/result（与 /api/ingest 同款理由，令牌自校验）；④ `_start_ai_relay_loop()` 本地常驻轮询线程（未配 publish.endpoint 时每 60s 静默待机） |

| `core/version.py` | 1.9.63 |

### 3.3 安全与防呆

- claim/result：与 `/api/ingest` 同款 `publish.ingest_token` 校验，令牌不对 401；
  登录守卫豁免理由同款（机器对机器，无浏览器会话）。
- request/status：走默认登录守卫（线上只有登录员工可点）。
- 幂等：同房源已有 pending/running 任务 → 复用，不重复排队。
- 互斥：`aiRunning` 前端锁 + 单线程本地 worker 串行处理（多任务自动排队，前端显示「前面还有 N 个」）。
- 超时：pending>30min（本地不在线）或 running>10min（抽取卡死）→ 自动判 fail；
  终态任务 24h 后清理防膨胀。
- 云端零调用：relay worker 硬编码 `allow_cloud=False`（v1.9.55 线下总闸在接力链路同样生效）。
