## 一、背景与需求原话

勇哥（2026-09-24）：「根据后台平台的含义，这里的"锁"代表它确定了位置在哪儿。
1. 去想办法确认是否能够获取到这个"锁"的信息。
2. 这个"锁"的信息具体是什么样的。
3. 结合谷歌地图，将对应的"锁"在地图上显示出来。
这一点需要由产品经理和 UI 经理共同论证其可行性，并形成一份 PRD 稿。」

### ⚠️ 先做一处术语澄清（重要，影响方案走向）

截图里圈的不是"锁"，是 **「所」** —— REINS 列表右侧三个小图标之一：

| 图标 | 含义 | 我们库里的字段 | 覆盖 |
|---|---|---|---|
| 画 | 照片 | `has_photo` | 30% |
| 図 | 間取図 | `has_floorplan` | 96% |
| **所** | **所在図（周辺地図）** | `has_map` | **27%** |

代码实证：`core/crawler.py:913` 注释 `p-icon-type-sho = 所（所在図/周辺地図）`；
`web/templates/detail.html:43` `title="有所在図"`。所以「所」=**该房源附有一张位置示意图**，
不是"锁定坐标"的意思——它**不含经纬度**。

**但这个方向是对的**：勇哥真正要的是「把这套房标到地图上」。下面按这个目标论证。

## 二、结论先行

| 问题 | 结论 |
|---|---|
| ① 能否获取位置信息？ | **能，而且现在就有** —— 不需要去抓「所在図」。 |
| ② 位置信息长什么样？ | 两层：**库里的地址字段**（95% 覆盖，到「丁目」）+ **已抓 PDF（物件概要書）里印着含番地的完整住所**（可程序化提取，实测 14%，有优化空间）。 |
| ③ 能否结合谷歌地图显示？ | **能，且成本极低**（零新增抓取、无 API Key，用 Google Maps 的 `?q=` 嵌入）。主要风险不在技术，在**中国大陆网络可达性**与**定位精度分级**。 |

**关键洞察（PM 视角）**：去抓「所在図」是**次优路径** —— 覆盖率最低（27%）、需要新写真机抓取逻辑、
且它本身只是**图片示意图、不含坐标**，拿到后仍要 OCR 才能用。
而我们已有的 PDF 里**已经印着完整住所**，那是**最精确、最可直接地理编码**的信息。
→ **建议：不做「所在図」抓取，走「地址 → 地图」路线。**

## 三、数据现状（均为实测，非估计）

| 数据源 | 覆盖 | 精度 | 现状 |
|---|---|---|---|
| `properties.address` | **4566 / 4788 = 95%** | 「丁目」级（无番地），如 `大阪府大阪市福島区鷺洲２丁目` | 已在库、已上屏 |
| `properties.has_map`（「所」标记） | 1339 / 4788 = 27% | 仅"有/无示意图"，**无坐标** | 仅用于显示彩色/灰色小图标 |
| 已抓 PDF（`data/attachments`） | **3792 份**（2.4 GB，单页） | PDF 内含**完整住所含番地**（如 `大阪市東成区中本５丁目２３番８号`） | **已下载但未抽取地址** |
| 其中可程序化提取完整住所 | **14%**（抽样 200） | **番地级（可精确定位到楼）** | 待做抽取 |
| PDF 有文字层比例 | **57%**（抽样 200） | 其余 43% 为图片型，需 OCR | 待评估 |

> 实测方法：随机抽 200 份 PDF，PyMuPDF 提取文字 → 全角转半角 → 正则匹配
> `(?:大阪府)?…[市区郡]…\d+丁目\d+番(?:\d+号)?`。命中样例：
> `300140346783 → 大阪市北区梅田1丁目8番17号`、`300140802939 → 大阪市中央区玉造1丁目5番19号`。

## 四、技术路径对比

| 路径 | 做法 | 覆盖 | 精度 | 成本 | 结论 |
|---|---|---|---|---|---|
| **A（推荐）** | `address` → Google Maps 查询链接/嵌入 | **95%** | 丁目级（约 50–150m） | **0**（纯前端，无新抓取） | ✅ 立即可做 |
| **B（增强）** | 从已抓 PDF 抽取完整住所 → 覆盖 address | 14% → 优化后有望 40%+ | **番地级（精确到楼）** | 中（抽取逻辑 + 可选 OCR） | ✅ 二期做，增量收益大 |
| C | 抓「所」所在図（下载示意图） | 27% | 仍无坐标，需 OCR | 高（真机侦查下载方式 + 新抓取链路） | ❌ **不建议** |
| D | 让 REINS 直接给经纬度 | — | 精确 | — | ❌ REINS 不提供（列表/详情均无坐标字段，实测 `detail_json` 22 键无坐标） |

### 路径 A 的具体形态（零成本，无 API Key）
```
https://maps.google.com/maps?q=<URL编码的住所>&output=embed   ← 可 iframe 直接嵌入
https://www.google.com/maps/search/?api=1&query=<URL编码住所>  ← 新标签打开
```
> 注意：**不要**用 Google Maps JS API / Embed API（需申请 Key + 计费）；
> 上面这种 `output=embed` 形式无需 Key，满足"内部查询工具"的场景。

## 五、PM 论证

**该不该做**：该做，且**优先级 P1**。理由：
1. 房产咨询场景里「这套房在哪」是与价格并列的第一信息，目前只能看文字地址；
2. 边际成本近乎为零（数据已在库、纯前端链接）；
3. 不占用抓取资源、不影响既有链路（纯展示层增强）。

**范围建议（最小 MVP）**：
- 本轮只做 **路径 A**：详情页嵌地图 + 列表/详情「地图」入口跳转。
- 路径 B（PDF 抽住所提精度）**列为二期**，因为它需要新增抽取链路与回归验证，属独立工作量。
- 路径 C（所在図）**明确不做**，并在文档中留档原因（避免以后再被提起）。

**验收口径（EARS）**：
- The system shall 在详情页展示基于该房源住所的嵌入式地图。
- When 用户点击列表卡片的地图入口，the system shall 在新标签打开 Google Maps 并定位到该住所。
- If 该房源无有效住所（约 5%），then the system shall **隐藏地图入口**，不得显示空白地图或报错。
- While 处于线上对外站（`OSAKA_PUBLIC=1`），the system shall 同样可展示地图（纯外链、无本机依赖）。

## 六、UI 论证

**展示形态（两处入口，避免喧宾夺主）**：

| 位置 | 形态 | 理由 |
|---|---|---|
| 详情页 `/p/<no>` | 一张**嵌入式地图**（高约 260px，宽度铺满）放在「所在地」字段下方 | 详情页是"看这一套"的场景，地图有充足空间 |
| 列表卡片 | 「画図所」一排小图标**之后**追加一个「地」图标（点击新标签打开 Google Maps） | 复用已有图标语言，零新增视觉负担；不占卡片高度（卡片刚做完行合并，不再加行） |

**交互与降级**：
- 无地址 → 图标置灰且不可点（与「画図所」的彩色/灰色语义一致），**且不显示空地图**；
- 嵌入地图加载失败（网络受限）→ 用 `onerror`/超时兜底显示一行文字链接「在 Google 地图中打开」；
- 移动端 375px：详情页地图宽度自适应铺满，不改动现有窄屏折行策略。

**风险提示（UI 侧，需勇哥拍板）**：
- **Google 在中国大陆访问不稳定**。团队若在重庆使用，嵌入地图可能空白。
  → 备选：日本本土地图（国土地理院 / Yahoo!地図）或保留"打开新标签"作为主路径、嵌入为辅。
  **这一条建议在开发前先由勇哥确认使用地**（日本现场 vs 国内）。

**视觉一致性**：地图卡片沿用现有 `card` 圆角/边框与 `--line` 分隔线，不引入新色。

## 七、影响面与实现风险（门禁⑧ ①）

| # | 等级 | 风险 | 缓解 |
|---|---|---|---|
| M-1 | 🟠 | **Google Maps 在部分网络下不可用** → 嵌入地图空白，体验"看着像坏了" | 必须有降级文案 + 文字链接兜底；开发前确认主要使用地 |
| M-2 | 🟠 | **地址精度不足**：丁目级地理编码可能定位到街区中心，与真实楼栋差 50–150m，对"这套房在哪"是**误导风险** | UI 上明确标注"位置约为该丁目范围"；二期用 PDF 抽番地提精度 |
| M-3 | 🟡 | 有少量**非大阪**房源（实测抽到东京涩谷的物件），地址格式差异可能导致定位错误 | 抽取/展示时校验都道府県前缀 |
| M-4 | 🟡 | PDF 抽取地址存在**噪音命中**（邮编/门牌粘连，如 `0355号東京都渋谷区…`） | 需清洗规则 + 人工抽验；**不可直接入库覆盖 `address`** |
| M-5 | 🟡 | 线上对外站是否需要地图（合规） | 地址本身已公开显示，地图只是同一信息的另一种呈现；若勇哥认为超范围，加开关控制 |
| M-6 | ⚪ | 嵌入地图造成第三方请求（隐私/性能） | 用 `loading="lazy"`，详情页才加载 |

## 九、建议的实施方案（若勇哥拍板走 A + 二期 B）
