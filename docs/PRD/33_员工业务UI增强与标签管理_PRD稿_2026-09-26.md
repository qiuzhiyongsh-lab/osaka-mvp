## 三、详细设计

### A-1 查询页收藏图标（`web/templates/search.html` + `fieldmap.js`）

- **位置**：列表项操作行，`加入对比` 按钮**右侧**、`専任/専属` 徽章**左侧**（即两元素之间）。
- **形态**：星形/心形图标按钮，尺寸与「加入对比」一致（不是文字按钮）。
- **两态**：
  - 未收藏：描边（灰色轮廓）
  - 已收藏：实心填充（品牌色）+ 轻微底色，形成「反选」观感 — 与「加入对比」选中态视觉语言一致
- **交互**：点击 → 调 `POST /api/emp/fav/toggle`（已存在）→ 依据返回 `added` 切换两态；**不跳页、不刷新**；失败给出提示。
- **登录态**：未登录时不显示或点击提示登录（`/api/emp/*` 走登录守卫）。
- **性能**：列表 50 条需知道各自"是否已收藏"→ 列表接口一次性带回 `faved` 集合（避免 50 次请求）。

### A-2 详情页收藏栏（`web/templates/detail.html`）

- **位置**：`打开PDF文件` 与 `物件番号` 之间（即 `加入对比` 上方）。
- **形态**：一整条"收藏栏"（比图标略宽，含图标 + 文字「收藏 / 已收藏」），因为详情页空间充裕且是勇哥"常去点击的位置"。
- **交互**：与 A-1 完全一致（同一 `fav/toggle`）。

### A-3 员工业务·收藏列表（`web/templates/emp.html` 的 `panelFav`）

- **列表形态**：**复用查询页的房源卡片渲染**（默认基础信息 + 「详细 ⇄ 简介」展开更多 + 点「详情页面」进详情页），**字段与查询页完全一致**。
- 现状是"番号 + 收藏时间"两列表格 → 改为卡片列表。
- **保留**：手工"输入番号添加收藏"入口（作为后门，不删）。
- ⚠️ **实现约束（关键）**：必须与查询页**共用同一套卡片渲染函数/i18n 键**，不得各写一份——否则将来字段一变就漂移。

### B-1/B-2 客户页重设计

- **整体**：从"三个输入框 + 一张裸表"升级为**卡片式列表**：每客户一行卡片，信息分组（名称 + 标签 / 联系方式 / 归属 / 登记时间 / 关联房源数），操作按钮收进更清爽的按钮组。
- **删除按钮配色（B-2）**：红底白字 → 改为**红色描边 + 红字（浅底）**，与「编辑/转移」同一个按钮族；危险操作点击后二次确认。
- **空状态**：无客户时给引导文案 + 新建入口（UI 规范要求三态）。

### B-3 客户标签

- **位置**：客户卡片「名称」右侧（或下方）显示已打标签；点「+ 标签」直接弹出标签选择器。
- **选择器**（与 C-1 共用组件）：
  - 列出**客户类**标签（多选，已选高亮）
  - 底部输入框「新建标签…」→ 回车/点「+」**当场创建并自动勾选**（即勇哥说的"不需要进行其他多余操作"）
  - 支持改色（创建时可选色，默认自动配色）
- **落库**：新建 `customer_tags` 表。

### C-1 收藏时打标签

- 在查询页/详情页点收藏**成功后**，若该房源尚无标签，**行内/浮层直接出现标签选择器**（不跳页）：可多选既有「收藏类」标签，也可当场新建。
- 已收藏的房源，再次点标签图标可随时增删标签。
- 复用 `POST /api/emp/tag/bind` 与 `property_tags`。

### C-2/C-3 标签管理页（`emp.html` 的 `panelTag` 重做）

- 标题统一为 **「标签管理」**。
- **分栏**：**左右两栏**（桌面宽屏）：
  - 左栏「**收藏类标签**」（作用于房源）
  - 右栏「**客户类标签**」（作用于客户）
  - 窄屏（≤768px）自动改为上下分栏。
- 每栏内：标签「胶囊」列表（显示颜色 + 名称 + **`N` 个对象**），支持**新增 / 改名 / 改色 / 删除**。
- 两栏**完全独立**，互不影响（勇哥明确要求"没有直接的相关性"）。

### C-4 标签下钻 + 分页

- 点某个标签「胶囊」→ 在**该栏下方**展开对应的对象列表：
  - 收藏类标签 → 列出使用该标签的**收藏房源**（卡片，与 A-3 一致）
  - 客户类标签 → 列出使用该标签的**客户**
- **分页 50/页**，服务端分页（`?tag_id=&page=1&size=50`），显示「共 N 个，第 X/Y 页」。
- ⚠️ **实现约束**：计数与分页一律**服务端 SQL**（前端只排当前页 = 错，历史教训）。

## 四、数据模型变更

| 变更 | 内容 | 迁移风险 |
|---|---|---|
| `tags` 加分类 | 新增 `category TEXT NOT NULL DEFAULT 'fav'`（`fav`=收藏类 / `cust`=客户类） | ⚠️ 原唯一约束是 `UNIQUE(owner_username, name)`，加分类后**同一名称不能跨类复用**；SQLite 无法直接改约束 → 需"建新表 + 迁移 + 改名"，或接受该限制。**建议重建表**（见风险 R1） |
| 新建 `customer_tags` | `id / owner_username / customer_id / tag_id / created_at / updated_at`，`UNIQUE(owner_username, customer_id, tag_id)` | 幂等建表，低风险 |
| 现有数据 | `favorites` / `property_tags` 不动；存量 `tags` 全部归 `fav` 类（保守） | 需确认存量标签归属 `[待确认 Q3]` |

### 新增 / 扩展接口

| 端点 | 用途 |
|---|---|
| `GET /api/emp/tags/list?category=fav\|cust` | 按类取标签（含每个标签的对象计数） |
| `POST /api/emp/tags/create` `{name,color,category}` | 新建（带分类） |
| `POST /api/emp/tags/<id>/update` `{name?,color?}` | 改名 / 改色 |
| `DELETE /api/emp/tags/<id>` | 删除（同时清关联） |
| `GET /api/emp/tags/<id>/items?page=1&size=50` | 下钻：该标签下的收藏房源 / 客户（**含总数 + 分页**） |
| `POST /api/emp/cust/<id>/tags` `{tag_ids:[…]}` | 客户打标签（覆盖式） |
| `GET /api/emp/cust/<id>/tags` | 客户已有标签 |
| `GET /api/emp/fav/list`（**扩展**） | 返回值升级为**完整房源卡片数据 + faved 标记**（供 A-1/A-3 复用） |

### ② 实现风险

| # | 风险 | 等级 | 应对 |
|---|---|---|---|
| **R1** | `tags` 表唯一约束迁移（同名称跨类） | 中 | 建新表 `tags_v2` → 迁数据（存量归 `fav`）→ 改名；全程备份 `employee.db`；幂等、可回滚 |
