## 1. 背景（勇哥原话归纳）

深挖 REINS 变更机制后确认两条事实：
1. `変更年月日`（平台变更日）**不等于**内容变化日 —— 它只是"業者碰过这条记录"的日期（92 日掲載延長、状态更新、3 ヶ月契約更新都会触发）。
2. 变更里**真正值钱的是「降价」** —— 是出手信号，也是买方中介的议价筹码。

勇哥采纳三条进 PRD：**① 降价提醒 ②「内容没变」标签 ③ 价格变更驱动 PDF 重抓**，并要求给出**展示建议**。

## 4. 开放项（Q 表，四段式）

**Q1 · 降幅闸门阈值定 50% 还是 30%？**
- 是什么：超过该幅度就标"存疑"，不按真降价展示。
- 举例：真降价通常 3～15%；异常值实测在 85%+；30～50% 之间是真空地带。
- 代价：阈值高（50%）会放过 40% 的异常；阈值低（30%）可能误伤真实的急售大降价。
- 建议：**先定 50%**（保守，只挡明显错误），上线后按真实分布再调。

**Q2 · 降价提醒要不要做"订阅/推送"？**
- 是什么：除列表徽章外，是否做每日降价清单推送（邮件/企业微信）。
- 代价：需新增推送通道与配额；但价值高（不用每天翻列表）。
- 建议：**本期只做列表徽章 + 查询筛选**；订阅推送列为 v2 候选项，先验证徽章用不用得上。

**Q3 · PDF 重抓的触发范围？**
- 是什么：价格一变就重抓，还是只在降幅超过某阈值时重抓。
- 举例：微小价格调整也要重抓 → 开销大；只抓大幅变动 → 可能漏。
- 建议：**任何 price 变化都触发**（PDF 上印的是价格，变一点也是错的），但受单轮上限保护。

### F5 房源历史时间轴 —— 2 案对比（勇哥拍板：放在「变更历史」之前）

**位置（勇哥指定）**：详情页 `detail.html` 插入于 **AI 解读（173 行 `</div>` 之后）与 变更历史（181 行 `<details>` 之前）**。
新顺序：**详细信息 → 房源図面 PDF → AI 解读 → ⭐房源历史时间轴（新） → 变更历史 → 抓取快照**

**方案 A（✅ 推荐）竖向时间轴（合并三表）**

- 一条竖线 + 节点，自上而下按**时间正序**（早 → 晚）
- 每个节点：日期时间 + 事件标签 + 一行说明
- 节点类型与取数来源：

| 节点 | 取数来源 | 显示内容 |
|---|---|---|
| 首次录入 | `changes` 中 `change_type='new'`；`first_seen_at` | 「首次录入 · 我方第一次抓到」+ 当时价格 + 平台登録日 |
| 内容变更 | `changes` 中 `content` / `modified`（`content_hash` 变了） | 「内容变更」+ 指纹 旧→新；有 `old_value/new_value` 则一并显示 |
| 降价 / 涨价 | `changes` 中 `price_down` / `price_up` | 「降价 ↓N%」+ 原价 → 现价 |
| **续期（内容未变）** | `property_history.change_date` 跳变 **且** `content_hash` 未变 | **灰点**「平台续期 · 内容与价格均未变」 |
| 当前状态 | `properties` 最新一行 + `property_history` 行数 | 「当前状态」+ 价格 / 状态 / **累计抓取 N 次** |

- 视觉（**复用 F2 的 5 档配色**，不另起炉灶）：新規蓝 / 降价红 / 涨价橙 / 内容紫 / 续期灰
- 规格：节点圆点 7px；竖线 1.5px `#D3D1C7`；标签文案 13px / 字重 500；说明 12px / 次要色
- **默认展开**（D9，勇哥"先展示出来再说"）；节点超过 N 个时才自动折叠

**方案 B 横向时间条**
- 优点：横向空间利用率高
- 缺点：节点多了会挤、日期标签重叠、小屏不可读
- 结论：**不推荐**

**推荐 A**。

**⚠️ 必须如实说明的数据限制（D10，不夸大）**
- 目前**回放不出"首次录入的完整字段"**：`changes` 首次只记了价格，`snapshots` 只有 price/status/指纹，完整字段 `detail_json`（21 个）只保留最新一份、旧版被覆盖。
- 因此：**历史房源的"首次录入全字段"无法回溯补录**。F5 对老房源只能显示"首次录入（价格）"；**F5.1 上线之后**入库的新房源才有完整基线。
- 展示口径：无基线时该节点写「首次录入（仅记录价格，完整字段自基线机制上线起记录）」，**不得留白、不得伪造**。

### F5 命中节点高亮（D13 · 来自调研 36）

**问题**：用户按某历史日期查询（如 9/15）命中一套房，进详情页后时间轴应让他**立刻知道"我是按哪天查到的"**，以及"最新在哪"。

**方案（并入 F5 时间轴）**
- 详情页 URL 支持可选参数 `?asof=YYYY-MM-DD`：由查询页结果卡片链接**透传"当前查询的命中日期"**。
- 时间轴上：
  - **命中节点** = `asof` 当日处于活跃版本的节点，加**外环高亮 + 「你按 X 日查到的」标签**（橙/黄描边）。
  - **最新节点** 独立标 **「最新」徽章**（蓝/绿），与命中节点区分。
  - 无 `asof`（用户直接进详情）= 不高亮命中节点，仅标「最新」。
- 取数：命中节点 = 在时间轴上找 `node_date <= asof` 的最大节点（即 asof 当时"生效"的那一版）。

### F6 偏差提示 —— 2 案对比（D12 · chip 为主 / 横幅为辅）

**L2 提示层**：解决"查 9/15 却想拿 9/30 最新"的两难——**不替换主信息（L1），只在主信息之上加提示**。

**方案 A（✅ 推荐）chip 为主 + 详情页顶部横幅为辅**

列表卡片 chip（双链都要加）：
- 显示：「⚠ 按 9/15 命中 · 已于 9/30 再变更」
- 提供「**看最新**」链接 → 跳详情页**不带** `asof`（即永远最新）
- 视觉：橙黄小 chip，置于价格下方或卡片右上角，**不挡主信息**；**仅在"命中后确有更新"时出现**（命中日 == 最新则不渲染，防噪音）
- 落点：`search.html` `renderFullItem` / `renderCompactItem`（F1 双链同样位置）

详情页顶部横幅（辅）：
- 触发：以 `asof` 打开且 `asof ≠ 最新变更日`
- 文案：「你正在查看按 9/15 命中的记录；该房源已于 9/30 更新（当前展示为最新信息）。[查看命中时版本] [始终看最新]」
- 两个动作：
  - 查看命中时版本 → 时间轴跳到命中节点高亮 +（若有 F5.1 基线）展开当时字段
  - 始终看最新 → 跳转 `/p/<no>`（去掉 `asof`）
- 落点：`detail.html` 顶部（F5 区块之上）

**方案 B 只做横幅 / 或把主信息直接替换成命中时版本**
- 只横幅：列表层无提示，用户翻列表时不知道有更新 → 不推荐
- 替换主信息为命中时版本：违反 L1 最新原则（调研 36 已否，全行业不这么做）→ **禁止**
- 结论：**采用方案 A**

**推荐 A**。理由：chip 在列表层就解决"知不知道有更新"，横幅在详情层解决"看不看得到当时版本"，两层互补且不破坏主信息最新。

## 7. 用户故事

- **US1**：我翻查询页列表时，想**一眼看出哪几套降价了、降了多少**，不用点进详情。
- **US2**：我看到某套"变更了"，想立刻知道**这次是内容真变了，还是只是续期**——别让我白跑一趟。
- **US3**：某套降价了，我希望**AI 解读里的价格是新的**，不要拿旧 PDF 讲错价。
- **US4**：我不想被"-94.7%"这种假降价误导，异常值要能看出来。
- **US5**（勇哥新增需求）：我打开一套房的详情页，想在**一张时间轴上一眼看完全过程** —— 什么时候进来的、中间改过几次、哪次是真改、哪次只是续期、现在什么样。不用自己拼三张表。
- **US6**（来自调研 36 · 勇哥核心痛点）：用户按历史日期查询时，既希望结果**尊重查询意愿**（命中的是该日期的房源），又希望**不被"旧信息"误导**——要能一眼知道"这套房后来还有更新、且能直接看到最新"。系统应用「三层分离」（L0 匹配 / L1 最新 / L2 提示）同时满足两者，而非二选一。

## 8. EARS 验收标准

- **[Ubiquitous]** 系统应始终以 `previous_price` 与 `price` 的差值判定降价（平台官方口径），不得用我方抓取时间推断。
- **[Event-driven]** 当某房源 `price < previous_price` 且降幅 ≤ 阈值时，系统应在查询页列表卡片价格右侧显示「↓ N%」徽章，并在详情页变更历史中标 `price_down`。
- **[Unwanted]** 若降幅 > 阈值（默认 50%），则系统**不得**显示为降价，应显示灰色「存疑·待核对」标记，且**不计入**首页「今日降价」KPI。
- **[Unwanted]** 若相邻两次快照的 `content_hash` 相同、价格也未变，则系统应将此次变更归类为 `meta_only`（续期），**不得**标记为内容变更 —— 即使平台 `chg_date_iso` 已更新。
- **[State-driven]** 在「只看降价」筛选开启时，列表应仅返回降幅合理（已过闸门）的房源。
- **[State-driven]** 在「价格变化自动重抓 PDF」开关开启时，当检测到 `price` 变化，系统应在下一轮抓取中删除旧 PDF 并重新下载，且受单轮重抓上限保护。
- **[Optional]** 若该开关关闭（默认），则系统保持现有行为（PDF 下载一次即不再更新）。

**F5 房源历史时间轴**
- **[Event-driven]** 当用户打开房源详情页，系统应在 **AI 解读卡片之后、变更历史之前**渲染「房源历史时间轴」，按**时间正序**展示「首次录入 → 每次变更 → 当前状态」三类以上节点。
- **[State-driven]** 在时间轴上，若某次平台变更的 `content_hash` 与上一次相同且价格未变，则系统应将该节点标为**灰色「续期」**，不得标为内容变更。
- **[Ubiquitous]** 系统应始终在「当前状态」节点显示该房源**累计抓取次数**（取 `property_history` 按 `property_no` 的行数）。
- **[Unwanted]** 若某房源缺失「首次录入全字段基线」（历史房源），则系统应在该节点显示「首次录入（仅记录价格，完整字段自基线机制上线起记录）」，**不得留白、不得伪造数值**。
- **[Event-driven]** 当房源首次入库时，系统应将当次 `detail_json` 全字段写入基线存储（F5.1），供时间轴回放"首次录入时长什么样"。
- **[State-driven]** 在时间轴默认展开状态下，若节点数超过配置上限，系统应自动折叠中段并保留「首次」与「当前」两个节点可见。
- **[Event-driven]** 每次重抓应在设置页状态行累加计数，并写入重抓日志供回溯。

**F5 命中节点高亮 + F6 偏差提示（L2 提示层 · 来自调研 36）**
- **[State-driven]** 当详情页接收到 `asof=YYYY-MM-DD` 参数时，系统应在时间轴上高亮该日期命中的节点（即 `node_date <= asof` 的最大节点），并标注「你按 X 日查到的」。
- **[Event-driven]** 当某房源"命中日 ≠ 最新变更日"（命中后又有更新）时，系统应在查询页列表卡片（双链 `renderFullItem`/`renderCompactItem`）显示偏差 chip「⚠ 按 X 日命中 · 已于 Y 日再变更」并提供「看最新」入口（跳详情不带 `asof`）。
- **[Unwanted]** 若命中日 == 最新变更日（命中即最新），则系统**不得**渲染偏差 chip（防噪音）。
- **[Event-driven]** 当详情页以 `asof` 打开且 `asof ≠ 最新` 时，系统应在详情页顶部显示横幅，提供「查看命中时版本」与「始终看最新」两个动作。
- **[Ubiquitous]** 系统应始终在列表卡片主区与详情主区展示**当前最新**价格/信息（L1 信息层）；偏差提示（chip/横幅/命中高亮）**不得覆盖或替换**主信息。

## 9. 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|------|
| 极端降幅脏数据（E9 实证） | 误导决策 | D5 闸门 + 灰标「存疑」，不计入 KPI |
| 徽章挤占卡片空间 | 列表变挤 | 内联同排 + 11px；简洁视图同样处理 |
| PDF 批量重抓开销 / REINS 风控 | 抓取变慢、有风控风险 | 默认关闭 + 单轮上限 + 仅价格变化时触发 |
| 双链漏改（renderFullItem / renderCompactItem） | 简洁视图看不到徽章 | 覆盖清单已列明两条链 |
| **首次录入全字段无法回溯**（D10） | 老房源看不到首次完整信息 | F5.1 仅覆盖新入库房源；页面如实标注，不伪造 |
| **`property_history` 778,403 行查询性能** | 详情页变慢 | 按 `property_no` 建/用索引；只取 `change_date` 演变（去重），不取全量行 |
| 时间轴默认展开撑长页面 | 页面变长 | 勇哥明确"先展示出来再说"（D9）；节点超上限才折叠 |
| 变更分类扩展影响既有统计 | 旧 `modified` 语义变化 | 数据迁移：历史 `modified` 按 `content_hash` 回填拆分 |
| **偏差提示噪音 / `asof` 丢失** | chip 过多或详情页丢失查询上下文 | chip 仅在"命中后确有更新"时出现（防噪音）；`asof` 随结果卡片链接透传（search→detail 带参）；无 `asof` 时不显示横幅 |

**回滚**：F1/F2 为纯展示层（模板 + 分类字典），回滚 = 恢复模板与分类映射；F3 为开关式后端流程，回滚 = 关闭开关即可（无需改代码）。无 DB schema 破坏性变更（F2 需回填，属可回滚的数据迁移）。
