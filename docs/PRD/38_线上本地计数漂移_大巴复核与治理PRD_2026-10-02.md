## 二、修正后的根因（5WHY）

### 2.1 「同口径下 636 vs 372」——为什么线上会少

- **W1**：线上当日窗口命中 372，本地 636。
- **W2**：截图时点 15:57，线上当日只收到 369 条；本地 636 是**全库复算**（含尚未推过去的行）。
- **W3**：推送走**水位线** `COALESCE(last_seen_at, first_seen_at)`（`publisher.py:176-218`）：只有"被再看到"的行才进本轮推送集。10-01 抓取产生的新/变行，若同日水位线未推进，就**留在下一批**。
- **W4**：水位线不是"内容变了就推"，而是"行被写过 last_seen 才推"（v1.9.80 已识别出这个坑，加了 `full_repush_hours=24` 定期全量重推兜底）。
- **W5 根因**：**增量推送 + 水位线语义**天然会留下"已变未推"的尾部；截图时点恰好落在尾部未推完的时刻。16:00 那次 1431 条补推证明**通道没坏、只是有时差**。

### 2.2 「线上比本地多 242」——为什么不是下架问题

- **W1**：线上 7577 > 本地 7335。
- **W2**：差异只能来自「线上有、本地没有的行」。本地删行/换番号不会同步删除线上（**推送只有 upsert，无 delete**）。
- **W3**：历史推送口径变过（早期月份口径、测试推、AI 结构派生行），这些番号今天本地已不再推 ⇒ 永久留在线上。
- **W4**：**下架判定与此无关**——下架判定改的是本地 `is_active`（1→0），行仍然会被推上去（`build_rows` 不过滤 `is_active`），线上**行数不减**，只是线上列表可能按 `is_active=1` 过滤显示。
- **W5 根因**：单向 upsert 同步 + 无对账 + 无删除通道 ⇒ 线上「只进不出」，多出来的 242 是**幽灵行**，不是脏房源。

### 2.3 「看不见」——为什么查不清

- 我们**没有任何只读通道能读到线上房源集合**：`/api/query` 需登录（本地 `public.access_code` 为空，无法用应急码）；`/api/reconcile` 被守卫 401（豁免是 v1.9.103 加的）。
- 线上代码更新通道在平台侧已断（UI 无"上传更新代码"、deploy 复用报 `app_deleted`）⇒ **要出数就必须先部署新版，而要部署新版又只能靠平台/勇哥明令**。这是死锁，不是代码问题。

## 三、🔴 新发现 P0（二巴没看到，本次已修）

**现象**：`2026-10-02 00:16` 勇哥重启 8765 后，v1.9.106 生效。实测生产库：

```
last_pulled_chg_date 列：存在        锚点非空行数：0      ← 全 NULL
pdf_sha256       列：存在（5851 行）   总行数：7335
```

**为什么**：v1.9.106 把「一次性回填」写在 `if name not in have:`（刚补出该列）分支里。生产库的列是**中途某次先被补出来**的，所以回填**一次都没跑过**。

**后果**：规则⑤ `平台 max(chg,reg) > 我方锚点` 中锚点是空串 ⇒ 对 plat 非空的 **7020 行恒为真** ⇒ 07:00 那一轮会把全库详情页重拉一遍（数小时 + REINS 风控风险）。

**已修（本次 v1.9.107）**：
1. 代码：回填**移出补列分支**，改为每次启动的**幂等空值回填**（只填 NULL/空串，已填不动）。
2. 生产库：已手工回填（回填前备份 `.backups/db/jproperty_before_anchor_backfill_20261002_002810.db`）：
   ```sql
   UPDATE properties SET last_pulled_chg_date=
     COALESCE(NULLIF(chg_date_iso,''), NULLIF(reg_date_iso,''))
   WHERE last_pulled_chg_date IS NULL OR last_pulled_chg_date='';
   -- 影响 7335 行；锚点非空 7020 行（315 行两日期皆空，保持 NULL）
   ```
3. 复算：`规则⑤ 命中行数 = 0` ⇒ 风险消除。
4. 诊断 `_diag_anchor_107.py` **6/6 PASS**（列已存在仍回填 / 两日期皆空保持 NULL / 已填锚点不被覆盖 / 锚点落后才触发重拉）。

## 七、EARS 验收标准

- **Event-driven**：当 `Store._ensure_columns()` 执行时，系统 shall 对 `last_pulled_chg_date` 为空的行回填 `COALESCE(NULLIF(chg,''),NULLIF(reg,''))`，且**不覆盖**已填值（幂等）。
- **State-driven**：在锚点已回填的状态下，系统 shall 使「平台日期 > 我方锚点」的命中行数与**真实变化量**同量级（当前实测 0，因无平台侧更新）。
- **Unwanted**：若线上 `running_version < v1.9.103`，系统 shall 在对账尝试中返回守卫 401 并明确提示「需先部署新版」，**禁止**把它误报成"令牌错误"。
- **Optional**：若启用 F5，搜索页 shall 在「共 X 条」旁回显筛选起点日期与口径（`date_caliber`），且「今/今日」与「共 X 条」口径差异有 tooltip。
- **Optional**：若启用 F7，`serve.py` shall 在非 PUBLIC 模式下随进程启动上传定时器，并在启动日志中留一行可核验的记录。
