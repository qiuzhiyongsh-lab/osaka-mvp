## 1. 背景与动机（来自阿丹录音的关键洞察）

勇哥原始需求（书面）：

> 在房源查询页里面，需要实现多选 PDF 文件并下载的功能。操作流程：1) 用户通过各种方式筛选出一部分房源，觉得不错后，点击对应的勾选项将这些房子选中；2) 选中后，点击下载，将这些房源对应的 PDF 文件下载下来，并合并成一个 PDF 文件。

阿丹在录音中澄清了 **为什么** 要这么做（证据：转录文本 line 13–24、35、88–94、300–310）：

- **核心痛点 = 多 PDF 反复切换效率低**。搜索一页约 30 个物件，先快速勾一批「觉得不错」的，一次性下载合并成一个多页 PDF，打开就能逐页慢慢看、逐页在旁边 Excel 算回报率（表面/实际回报率），不用在多个 PDF 之间来回开/关（line 19–24）。
- **典型批量 = 3～20 套，极少到 50 套**（line 54–61：阿丹确认「最多十来二十个吧，一般不会选到五十套那么多」）。
- **下一步动作 = 人工算回报率**（line 35、88–94）：合并 PDF 只是「把候选装进篮子」，真正的决策依赖逐套看图纸 + 算 ROI。阿丹明确希望「后期把回报率也算上去就更方便」（line 36–37）——这属于**独立在做的回报率 PRD（v1.1.0）**，本 PRD 不覆盖，仅作关联引用。
- **阿丹工作流 = 大海捞针 → 装篮子 → 逐套算**（line 194–198、276–280）：先用筛选/收藏/标签把「不错的」收拢到几百套，再从中逐套算。合并 PDF 服务于「装篮子后集中看」这步。

> 顺带确认：阿丹在录音中吐槽「收藏页没有对比栏」（line 200–215、239、241「这个我后面把它加上去」）—— 这正好对应本会话已完成的 **#617 收藏页对比悬浮栏**（v1.9.112 已落码待发版）。本 PRD 的「扩展到收藏页」即复用该栏。

## 6. 技术方案（两套环境 PDF 来源不同 → 两种实现路线）

**关键事实（已核实代码）**：

- 本地 8765：`web/app.py:2455` 把 `pdf_url` 重写为本地路由 `/download/attachments/<文件名>`；`pdf_path` 落盘在 `data/attachments/<番号>.pdf`（crawler.py:149）。
- 线上 v100：`web/app.py:2459` 保留库里的 `pdf_url` = **COS 预签名直链**（勇哥 2026-09-23 拍板「PDF 上云 + 登录即可看」，见 `docs/PRD/23_线上PDF托管与安全展示_PRD稿`）。
- 行 payload `_row_payload`（`web/app.py:2416`）已带 `pdf_url`，查询页「図面」按钮即用此字段 → **前端天然能拿到每套 PDF 的可下载地址**。

### 方案 A：前端 pdf-lib 合并（★ 推荐 MVP）

- 在浏览器内用 `pdf-lib`（新增到 `web/static/vendor/`）逐套 `fetch(row.pdf_url)` 取 blob → `PDFDocument.load` → `copyPages` 合并 → `save` → 触发下载。
- **一套代码通吃本地（本地路由）与线上（COS 直链）**，无需新建后端端点。
- 优点：零服务端改动、双环境通用、PDF 不落服务器盘、对大批量内存可控（20 套 ≈ 20~40MB，浏览器无压力）。
- 缺点：COS 预签名 URL **有有效期**——若用户勾选耗时过长，点下载时旧 url 可能过期（本地路由无此问题）。缓解：点击下载时**实时重新拉取** `pdf_url`（前端重新请求行数据或后端给个「续签」轻接口）；基本不影响 MVP，因为用户通常勾完即下。
- 依赖：`pdf-lib`（前端 JS，纯静态，随 `web/static` 热重载）。

### 方案 B：后端 pypdf 合并（增强，适合 Phase 2）

- 新增 `POST /api/pdf_merge`，收 `nos=[...]`：本地读 `pdf_path` 磁盘文件、线上 `fetch(pdf_url)` → `pypdf`（`venv` 已装 6.19.0）合并 → 流式返回。
- 优点：可注入**封面/目录页**（每套 番号+地址+价格，方便阿丹逐页定位算 ROI）、对超大批量更稳、规避 COS 过期（服务端实时续签）。
- 缺点：线上部署需把 `pypdf` 纳入 `requirements`（run.py 托管 venv）；本地与线上两分支取 PDF 逻辑不同，需 `if PUBLIC` 分支。
- 触发点：仅当要做「封面/目录页（FR + 增强）」或「批量 >50 且要服务端兜底」时上此方案。

> **建议**：MVP 走方案 A 快速交付核心诉求；封面/目录页与收藏页扩展（Phase 2）视反馈再决定是否补方案 B 的封面注入。

## 7. 边界与异常处理

| 场景                 | 处理                                      |
| ------------------ | --------------------------------------- |
| 单套无 PDF（pdf_url 空） | 插占位页「番号 X：无PDF」，末尾汇总缺失清单（FR6）           |
| 全部无 PDF            | 禁用下载按钮并提示「所选房源均无 PDF」                   |
| 仅勾 1 套             | 允许下载（等于单套 PDF，不强制 ≥2；与对比不同）             |
| 勾选 0 套点下载          | 下载按钮禁用                                  |
| COS url 过期（线上）     | 点击下载时实时重取 pdf_url；失败则该套转占位页并提示          |
| 某套 fetch 失败/损坏     | 该套转占位页「番号 X：PDF 获取失败」，不中断整体             |
| 超大批量（>50）          | 软上限提示分批（FR7）；硬上限建议 100 防浏览器内存爆          |
| 文件名中文/特殊字符         | 用 `osaka_合并PDF_日期_N套.pdf` 纯 ASCII 前缀，安全 |

## 8. 验收标准（QA 视角）

1. **功能主路径**：查询页勾 3 套（含 1 套无 PDF）→ 点下载 → 得 1 个 PDF，页数 = 3 套之和（含 1 占位），打开后顺序与勾选顺序一致。
2. **本地环境**：8765 下勾选落盘 PDF 的房源，合并文件内容与 `data/attachments/<番号>.pdf` 逐页一致。
3. **线上环境**：v100 下用 COS `pdf_url` 合并成功（需在线上真机验证预签名时效）。
4. **与对比栏隔离**：勾 PDF 下载不影响对比栏已选（限 6）；反之亦然。
5. **悬浮栏**：勾选出现、清空二次确认、隐藏复位均正常；样式与 `.cmpbar` 一致（纯 CSS/结构对齐，行宽零增加）。
6. **边界**：0 套禁用、全无 PDF 提示、COS 过期降级占位，均无 JS 报错（用 `tools/check_html_js.py` + Playwright 真机）。

## 12. 勇哥交互方案评审（可行性与改进）

**勇哥原方案**（2026-10-05，附截图）：

> 把行内绿色「PDF」三个字改成「PDF下载」，并在旁边加一个多选框。

| （隐含）单选/多选共存             | 需明确规则，否则误操作                                                                | ➕ **补充规则 F**：见 §16                                                                                                                         |
| （隐含）跨页选择                | 搜索结果分页，选择必须**跨页保留**                                                        | ➕ **补充**：选择集存 `localStorage`，翻页不丢（对标 PatternFly「across all pages」）                                                                         |
| （隐含）无 PDF 行             | 勾了没 PDF 的行会造成合并缺页                                                          | ➕ **补充**：无 PDF 行复选框**置灰不可选**（对标 eligibility 原则）                                                                                            |

**一句话**：勇哥的交互骨架（单点下载 + 多选 + 明显状态 + 悬浮汇总 + 清空）**完全正确**；主要改良三点——① 悬浮框改**底部托盘**（不遮挡、与对比栏统一）；② 明确**单选/多选共存规则**；③ 补齐**跨页保留 + 无PDF不可选 + 合并进度**三个业界必备细节。

## 13. 全网同类方案调研（bulk selection 最佳实践）

参考：Gmail 收件箱、Google Photos / iOS 照片「选择」、Google Drive、Jira / Notion 表格、Shopify/Amazon 后台、**PatternFly / Braid / Material Design** 设计系统、Eleken《Bulk action UX》*（检索 2026-10-05）*。

| #  | 业界最佳实践                                                | 本需求映射                                         |
| -- | ----------------------------------------------------- | --------------------------------------------- |
| B1 | **复选框是「可多选」的通用语义**（min 命中区 24×24 桌面 / 44×44 触屏）       | 行内多选框，命中区含整行左侧 padding                        |
| B2 | **动作条随选择出现、并持久停留在视口**（不因滚动消失）                         | 底部托盘 `position:fixed`；顶部模式条 `position:sticky` |
| B3 | **始终显示「N selected」摘要**（calm status，用 `role="status"`） | 顶部条「已选 N 套」+ 托盘「已选 N 套」                       |
| B4 | **三态「全选」**（未选/全选/半选 indeterminate）                    | 增强项：工具条「全选本页 / 全选全部／反选」（见 Q11）                |
| B5 | **eligibility 透明**：不能操作的对象置灰并说明原因                     | 无 PDF 行置灰 + tooltip「该房源无 PDF」                 |
| B6 | **完成后反馈 + 可撤销/确认**（destructive 才需确认）                  | 合并走 loading→toast；清空选择属非破坏，免/轻确认              |
| B7 | **选择跨分页保留**（PatternFly: select across all pages）      | 选择集存 localStorage，跨页累计                        |
| B8 | **单选沿用「行内即时动作」**：列表行常见「快速动作」直出（如 Gmail 的归档/删除图标）      | 「PDF下载」= 行内即时动作（点即下）                          |

> 结论：勇哥方案 = B1+B2+B3+B8 的直接体现；补上 B4/B5/B6/B7 即达业界完整度。

## 14. 推荐交互方案（2 案对比 + 线框 + 状态机）

### 案 A（★推荐，基于勇哥原案改良）——「行内 PDF 操作组 + 底部托盘」

- 行内：`… [价格] [PDF下载] [☑] [详情页面]`。`PDF下载`＝即时单下；`☑`＝加/减入选择集。
- 一勾：顶部出现 **sticky 绿条**「多选下载模式 · 已选 N 套 · 退出」；底部滑出 **悬浮托盘**。
- 托盘：横向列已选卡片（**地址 + 编号**，按勾选顺序＝PDF 页序），每卡可 `×` 移除；右侧 `清空` + `下载合并 PDF(N)`。
- 退出：点绿条「退出多选」/ 再点工具条开关 / Esc / 清空后自动退出。
- 优点：符合勇哥直觉（就在行内），发现性最好；与现有对比栏位置统一。

### 案 B（业界 select-mode，备选）——「工具条开关进入选择模式」

- 默认行内**不显示**复选框（零增宽）；点工具条「多选下载」进入模式后，行左侧才出现复选框。
- 优点：默认列表最干净（对标 Google Photos / iOS 照片）。缺点：多一次点击、发现性弱于案A。

> **推荐**：以**案 A** 为基础（尊重勇哥「旁边加多选框」的原意、发现性最好），吸收案 B 的克制——`☑` 默认**淡显**（灰 30%），hover 行或进入模式时**高亮**，兼顾「不刺眼」与「看得见」。二案可 A/B 真机比对后再定（见 Q9）。

### 线框（案 A）

```
┌ 顶栏 osaka · 房源查询 ────────────────────────────────┐
├ 🟢 [多选下载模式] 已选 3 套 · 点行内 ☑ 继续选     [退出多选] ┤  ← sticky 绿条（仅在多选时）
├ 共 178 套 · 登録日 2026-10-05        [ ] 多选下载         ┤  ← 工具条开关
├───────────────────────────────────────────────────────┤
│ ☑ 加入对比 变更 大阪市西区…ザ・サンクタス夕ワー   17,800万円 [PDF下载] [详情页面] │  ← 已选：行绿底+左侧绿条
│ ☐ 加入对比 新建 大阪市浪速区…なんばパークスハウス   5,980万円 [PDF下载] [详情页面] │
│ ☐ 加入对比      大阪市北区…グランフロント （无PDF，灰行 ☐禁用）       [PDF下载禁用] │
│ …                                                                        │
├───────────────────────────────────────────────────────┤
│ 已选 3 套（地址+编号）· 顺序即页序         [清空] [下载合并 PDF（3）]      │  ← 底部悬浮托盘（fixed）
│ [大阪市西区新町１丁目… ×] [大阪市浪速区難波中２丁目… ×] [大阪市天王寺区… ×]   │
```

### 状态机

```
[普通] --勾☑ 或 开开关--> [多选模式] --清空/Esc/退出--> [普通]
[多选模式] --点 PDF下载--> 该行加/减入选择集（不即时下载）
[普通]     --点 PDF下载--> 即时下载单套（toast）
[多选模式] --点 下载合并PDF--> [合并中:loading+禁用] --done--> toast「已下载 …N套.pdf」→ 回 [多选模式]
```

**EARS 验收（新增，可测）**

- Ubiquitous：每行有 PDF 时**恒**显示可点 `PDF下载`。
- Event-driven：当用户勾选任一 ☑ 时，系统**应**同时显示顶部绿条与底部托盘，且计数 = 已选数。
- State-driven：当处于多选模式时，点 `PDF下载` **应**改为加/减选择而**不**触发下载。
- Unwanted：当所选含无 PDF 行时，系统**应**禁止勾选该行（而非静默缺页）。
- Optional：当选择 >50 时，系统**应**提示建议分批（沿用 FR7）。
