## §1 背景（勇哥原话归纳）

1. **实际回报率**：若物业管理费 + 修缮积立金都有 → 算 `(租金 − 管理费 − 修缮金) / 房价` 得实际回报率；若两者不全 → 不算，留空。

## §4 开放项 Q 表（四段式 · 须勇哥拍板）

### Q1 🔴 租金数据源缺失（致命缺口，阻断①）

- **是什么**：实际回报率分子「租金」在系统三处数据源（主表列 / detail_json / AI 结构库）均不存在。公式勇哥已给，但无租金则永远算不出。
- **举例**：8146 条 detail_json 中租金类键出现 0 次；`properties` 无 rent 列；AI 库 2932 条无賃料字段。当前**全部房源**落入 PRD §2 状态③（租金缺失），利回り 恒空。
- **代价**：若不在抓取链路补租金 → ①整块功能 0 房源可算，等于没做；②即便前端/公式就绪也无数据填充。
- **建议（按成本排序，待勇哥选其一或组合）**：
  - **Q1-a（推荐·成本最低）**：AI 抽取 `core/ai_extract.py` SYSTEM_PROMPT 增加「月額賃料(円)」字段，复用现有 AI 结构库通道（管理费/修缮金已走此路）；
  - **Q1-b**：PDF 本地抽取 `core/pdf_local_extract.py` 补「賃料」正则（LABELS 已含字样，仅缺规则）；
  - **Q1-c**：爬虫坐标新增（REINS 详情页若有租金行，加 `LIST_FIELD_MAP` 坐标 + `LABEL_MAP` 映射）；
  - **Q1-d**：勇哥确认租金是否=某已有字段（如 unit_price 非租金，基本排除）或手工补录口径。

### Q2 列表卡片是否同步显示「实际回报率」

- **是什么**：PRD#39 已在 PDF 合并信息页设利回り 占位行；是否也在列表卡片加一行「实际回报率 X.X%」。
- **举例**：列表卡已较密，加一行可能影响密度。
- **代价**：不加 → 需进详情/PDF 才见；加 → 信息前置但占空间。
- **建议**：默认**仅在信息页 + PDF 信息页**显示（与 PRD#39 一致），列表暂不加；待租金数据落地后据密度再定。

### Q3 中介电话展示格式 / 隐私

- **是什么**：broker_tel 为公网卖方中介电话，列表常驻是否需掩码或仅登录可见。
- **举例**：当前线上为访问码登录制，非完全公开。
- **代价**：明文展示对买方便利，但公开程度需勇哥定。
- **建议**：沿用现有访问码体系（已登录可见即展示），不加掩码；若勇哥要求公开页隐藏则再议。

## §7 EARS 验收（每条可测）

- **Ubiquitous**：系统在所有列表卡片（详细+紧凑）与信息页，当 `floor` 有值时，楼层数字以醒目样式（≥17px/800/主题色）显示于「物件种别→楼层→建筑年份」固定位置。
- ** Event-driven**：当 `image_count ≤ 0`（含 0 与未知 null）时，系统不渲染「画像 N 枚」文字，仅保留 画/図/所 三标记。
- **Unwanted**：当 `broker` 为空时，列表卡片不显示中介行（不渲染空壳）。
- **State-driven**：当 `management_fee` 与 `repair_fund` 均非空且 `rent` 非空时，利回り(%) 显示计算值（保留两位小数）；否则显示空。
- **Optional**：若 Q1-a 选中，AI 抽取新增「月額賃料」字段且覆盖 ≥ 管理费现有 69.7% 水平（目标 ≥60%）。
