## 步骤 1　创建存储桶（约 3 分钟）

1. 打开 **https://console.cloud.tencent.com/cos/bucket** （对象存储 → 存储桶列表）
2. 点 **「创建存储桶」**
3. 逐项选择（**按这个填，别改**）：

| 配置项 | 填什么 | 为什么（别选错） |
|---|---|---|
| 名称 | 建议 `osaka-house-pdf` | 系统会自动拼成 `osaka-house-pdf-<你的APPID>`；APPID 在「账号信息」可见 |
| **所属地域** | **亚太 — 大阪（ap-osaka）** | ✅ 已确认 COS 支持大阪；业务在大阪，日本销售访问最快 |
| 访问权限 | **私有读写** | 🔴 **最关键**！绝不能选"公有读私有写"——否则任何人可枚举下载，我们方案 A 的安全前提就没了 |
| 多 AZ | **不开启** | 省成本；单 AZ 对本项目够用 |
| 版本控制 | 不开启 | 不需要历史版本，省存储 |
| 日志存储 | 不开启 | 省成本 |
| 服务端加密 | 不开启（默认） | PDF 非绝密；如需可后续开 |

4. 点「创建」。
5. **创建完成后，立刻记下 3 样东西**（后面要给小巴）：
   - 存储桶**完整名称**（含 APPID 后缀，如 `osaka-house-pdf-1258xxxxxx`）
   - **地域**：`ap-osaka`
   - **默认访问域名**（概览页 → 域名信息，形如 `https://osaka-house-pdf-1258xxxxxx.cos.ap-osaka.myqcloud.com`）

> ⚠ 若"大阪"在地域下拉里**选不到**：先确认账号已完成**实名认证**（境外地域通常需实名）。若仍不可选，告诉我，我改成东京 `ap-tokyo`（日本另一节点，次优）。

### 🔴 建桶前先看：访问权限到底选"私有"还是"公有读"？

勇哥 2026-09-23 补充口径：

> 「员工登录了就能打开 PDF，这份文件我必定给他看、给他下载。下载到本地后，链接从哪来已不重要，**加密没那么重要**。只要能登录就默认开放。链接不用特定、有规律就行。**安全性要求没那么高。**」

**我的推荐：仍然选「私有读写」** —— 理由不是不信任你的判断，而是这三个事实：

| 事实 | 说明 |
|---|---|
| **签名对你零操作** | URLs 由**本机脚本全自动生成 + 每轮抓取自动刷新（7 天滚动）**，你完全不用管、也不用记住"7 天"这回事 |
| **链接依旧有规律** | 展示出来是 `https://<桶>.cos.ap-osaka.myqcloud.com/300139241123.pdf?签名尾巴` —— **番号一眼可辨**，符合你要的"有规律"；系统自动在尾巴挂个签名参数而已 |
| **它挡的是批量爬取** | 私有读 = 别人**猜不到签名 → 无法按番号遍历把 3725 份図面整站搬走**。公有读则可被任何人（含竞品）一条循环全下走 |

**代价只有一个**：若本机连续 >7 天没跑抓取也没 sync，链接到期失效（详情页会提示"PDF 已过期，请联系管理员重新同步"）。本地 8765 本来就常驻，正常不会触发。

> 💡 **不想用签名？随时可降级**：事后再想要"纯规律永久直链"，只需在 COS 控制台把桶 ACL 改成"公有读私有写" + 小巴改一行前端逻辑（去掉签名尾巴）—— **无需重建桶、无需重传 PDF**。
> 反过来（先公有读想要更安全）也一样能改，但**中间的暴露窗口已经发生**。所以先按私有建，损失最小。

## 步骤 2　创建只读/只传子账号（不要给主账号密钥！）（约 5 分钟）

> 目的：给小巴一个**被阉割过的密钥**——只能读写这一个桶，拿不到你账号里任何其它资源，删不了桶。

1. 打开 **https://console.cloud.tencent.com/cam** （访问管理 CAM）
2. 左侧 **「用户」→「用户列表」→「新建用户」→ 选「自定义创建」**
3. 填写：
   - 用户名：`osaka-pdf-bot`
   - 访问方式：**只勾「编程访问」**（不要勾控制台访问）
4. 权限设置 → 点 **「新建策略」** → 弹出「选择创建策略方式」窗口 → 选 **②「按策略语法创建」**（✅ 不是 ①按策略生成器 / ③按标签授权 / ④按产品功能或项目权限——那三个做不到"只授权某一个桶"）→ 下一步模板页选 **「空白模板」**：
   - 策略名称：`osaka-pdf-only`
   - 把下面 JSON **整段复制进去**，并把 2 处占位符替换成真实值：
     🔴 **占位符连尖括号带中文一起删干净，只留纯数字 / 桶名**。
     若保留了 `< >`，腾讯云会报「**资源六段式第五段无效的 uid**」——
     正确写法是 `uid/1253537327`（**不带尖括号**），错误写法是 `uid/<1253537327>`。
   ```json
   {
     "version": "2.0",
     "statement": [
       {
         "effect": "allow",
         "action": [
           "cos:GetObject",
           "cos:PutObject",
           "cos:HeadObject"
         ],
         "resource": [
           "qcs::cos:ap-osaka:uid/这里填APPID纯数字:这里填桶名含APPID后缀/*"
         ]
       }
     ]
   }
   ```
   > 例：若 APPID 是 `1258123456`，桶名 `osaka-house-pdf-1258123456`，则 resource 填
   > `qcs::cos:ap-osaka:uid/1258123456:osaka-house-pdf-1258123456/*`
   >
   > 说明：只给 `GetObject`（预签名下载用）+ `PutObject`（上传 PDF）+ `HeadObject`（校验存在）。
   > **不给** `DeleteObject`、`GetBucket`、`PutBucketAcl` 等——所以即使密钥泄露，攻击者删不掉、列不出、改不了权限。
5. 完成策略 → 回到用户创建页，把这个策略**勾选**给 `osaka-pdf-bot` → 创建用户。

## 步骤 3　拿到 SecretId / SecretKey（约 2 分钟）

1. 用户列表里点 **「osaka-pdf-bot」** → 「API 密钥」页签 → **「新建密钥」**
2. 页面显示 **SecretId**（`AKID...` 开头）和 **SecretKey**（一串乱码）
3. 🔴 **SecretKey 只显示这一次**（后续可再新建，旧的也可禁用）→ **立刻复制保存**

> 安全底线：这是**子账号**密钥，权限已锁死在这一个桶的读/写上，风险可控。

7. 全部"写码不发布"，等你说 **「发版」** 才 sync + deploy

## 常见坑（FAQ）

| 坑 | 现象 | 解决 |
|---|---|---|
| 桶建成了"公有读" | 任何人可枚举下载 | 🔴 立刻改回**私有读写**；我们的方案是私有读+签名 |
| 给了主账号密钥 | 泄露=全账号沦陷 | 删掉重建，只给子账号 |
| 给了"用户名+控制台登录密码" | 那只是**浏览器登录网页**用的，程序调 COS 接口不认它 | 必须在同一用户下「API 密钥」页签**再新建密钥**，拿到 SecretId+SecretKey 才可用 |
| 在左侧「API 密钥管理」页拿到密钥 | 那是**主账号**的，不是子账号的 | 正确入口：访问管理 → 用户 → 点 `osaka-pdf-bot` → 用户详情页签里的 **「API 密钥」**（**不是**左侧菜单那个"API 密钥管理"） |
| 在主账号 API 密钥页点「新建密钥」，弹出风险警示 | 腾讯云在拦你用主账号密钥 | **点弹窗里的蓝色按钮「切换使用子账号密钥」** → 选子账号 → 创建 → 复制 SecretId + SecretKey |
| 已有密钥却查不到 SecretKey | 腾讯云 2023-11-30 起**只支持新建时显示一次** SecretKey | 点「新建密钥」，弹窗里**立刻复制** SecretId+SecretKey；旧密钥可禁用 |
| SecretKey 没保存 | 页面关了找不回 | 再「新建密钥」，旧的删掉 |
| 大阪地域选不到 | 下拉里没有 | 先做实名认证；仍不行改用 `ap-tokyo` 并告诉我 |
| APPID 不知道在哪 | 填不进策略 JSON | 右上角头像 →「账号信息」→ APPID |
