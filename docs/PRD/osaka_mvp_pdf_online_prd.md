## 0. 一句话目标

## 3. 现架构 PDF 链路事实（证据锚点）

```
本地 osaka-mvp/
├─ data/attachments/<番号>.pdf      # 抓取落盘（3725 份/2.4GB）—— 本地只读站用 download 路由展示
├─ data/jproperty.db                  # 房源主库，含 pdf_path（本地绝对/相对路径）
├─ web/templates/detail.html:119-125 # 「房源図面 PDF」iframe 区块，注释"线上不传 PDF 不会出现"
└─ tools/sync_to_publish.py:72       # PDF_KEYS 剔除 pdf_path/pdf_url → 线上库无 PDF 信息

线上 osaka-house-publish/app_local/
├─ web/app.py:250-280                # _public_guard：/download/* 404、PUBLIC_HIDDEN_APIS 403
├─ web/app.py:296                    # 登录白名单（已含 /api/selfcheck）
└─ serve_public.py:17-20             # core.config.load()；无 config.local.yaml → 线上无本机密钥
```

**关键约束（铁律）**：
- `sync_to_publish.py:61-70`：`SECRET_KEYS`/`SECRET_PARTS` 剔除一切凭据；仅 `ingest_token`（机器对机器校验）例外保留。**任何 COS SecretKey 不能随同步上云。**
- memory §9.4：对外数据包 `pdf_path` 须空（不能暴露本机路径）；PDF 本体可上云（勇哥 9-22 已放宽）。

## 4. 核心设计决策：签名方案（决定"仅登录销售看"如何实现）

### 4.A 推荐方案 — 私有读 Bucket + 本地预签名直链（零密钥上线）

**逻辑**：
1. 腾讯云 COS 建**私有读**存储桶（不公开列举）。
2. 本地 `config.local.yaml` 存 COS `SecretId/SecretKey`（只读子账号，仅 `GetObject` 权限）。
3. **本地脚本** `tools/pdf_to_cos.py`：上传 PDF 到 `cos://bucket/<番号>.pdf`，并用 SDK 生成**预签名 URL（有效期 7 天）**，写入主库 `pdf_url` 字段。
4. `sync_to_publish.py` 把 `pdf_url` 从 `PDF_KEYS` 剔除名单**移出** → 进入 `site_data.json` → 线上灌库。
5. 线上 `detail.html` 用 `pdf_url`（签名直链）渲染 iframe，**线上后端不持任何密钥**。
6. 每轮本地抓取 → 重新上传/重签 → 下次 sync 自动刷新（签名 7 天内有效，抓取间隔 1–3h 远小于 7 天，永远新鲜）。

**契合铁律**：SecretKey 仅本机，`serve_public.py` 无需改动密钥读取；线上只读站零密钥负担。

**语义权衡（需勇哥确认）**：预签名直链本身"拿到链接 7 天内可见"——并非绝对"仅登录销售看"。但：
- PDF 区块只在**登录后的详情页**渲染（未登录跳 `/login`，`_access_guard` 拦截）；
- 直链路径带签名随机串、不可枚举；
- 对外仍满足"不公开列举、不匿名浏览列表"。

→ 若勇哥接受此务实口径，§4.A 即终态。

### 4.B 严格方案 — 线上持密钥实时签/代理（绝对仅登录）

**逻辑**：线上新增 `GET /api/pdf/<番号>`（在 `_access_guard` 登录校验内）→ 后端用 COS SecretKey 实时生成 15 分钟预签名 URL（或流式代理）→ 返回给已登录销售。

**前提（待确认）**：
- WorkBuddy"发布为应用"是否支持**注入环境变量/Secrets**？`serve_public.py:15` 仅 `setdefault("OSAKA_PUBLIC","1")`，未读其它 env。若平台支持注入，可在启动前 `os.environ["COS_SECRET_ID"]=...`；否则需新增"允许同步的只读 COS 密钥"（突破 §3 铁律，须勇哥显式拍板）。
- 即便注入，SecretKey 落在 WorkBuddy 托管沙箱 = 平台侧可见，需用**只读子账号密钥**（泄露仅能读不能写删）降险。

**结论**：§4.B 复杂度/风险显著高于 §4.A。**勇哥 2026-09-23 已明确放弃 §4.B**（见 §4.C）。

### 4.C　勇哥安全口径放宽（2026-09-23）与我们的落地取舍

**勇哥原话**：员工登录了就能打开 PDF，此文件必定给他看且可下载；**PDF 下载到本地后，链接从哪来已不重要，加密没那么重要**；只要能登录就默认开放；**下载链接不需特定性、有规律性即可**；**安全性要求没那么高**。

**理解**：访问控制从"加密强度"退化为"登录门槛"——即"登录 = 授权看全部 PDF"，不再要求 per-user/per-file 加密隔离。

**落地取舍（`Strength vs Simplicity`）**：

| 候选 | 是否采用 | 理由 |
|---|---|---|
| **私有读 + 本地自动重签（§4.A）** | ✅ **采用（推荐）** | 签名**全自动**、勇哥零感知；链接仍"有规律"（番号可辨，仅尾巴带签名参数）；挡住**批量爬取**（竞品无法遍历番号整站搬走 3725 份図面） |
| **公有读 + 纯规律永久直链** | ⏸ 备选（一行可切） | 最简，符合"加密不重要"字面诉求；代价=任何人可枚举下载全部 PDF。**不重建桶、不重传**，事后切即可 |

**为什么推荐前者**：勇哥要的是"**我不用操心**"，而不是"**必须不要签名**"——签名由机器全自动跑，操心成本本来就是 0，却换来保护。若勇哥坚持最简公有读，改动成本 = 控制台改 ACL + 前端去签名尾巴，随时可退。

**对应修订**：§10 权限条款由"严格加密隔离"降级为"登录即授权 + 防批量爬取（尽力）"；§13 风险表"泄露"等级由高降为中低。

## 6. 功能清单（EARS）

| ID | 类型 | 需求 |
|---|---|---|
| F1 | Ubiquitous | 系统须保证线上 PDF 直链存储于**私有读** COS 桶，不公开列举。 |
| F2 | Event-driven | 当 crawler 在 `data/attachments/` 落盘新 `<番号>.pdf` 时，系统须自动上传至 COS 并刷新主库 `pdf_url`（预签名，≤7天有效）。 |
| F3 | Event-driven | 当 `sync_to_publish.py` 生成 `site_data.json` 时，系统须将 `pdf_url` 纳入数据包（不再剔除）。 |
| F4 | State-driven | 当 `OSAKA_PUBLIC=1`（线上只读站）且用户**已登录**时，详情页 `pdf_url` 非空即渲染 PDF iframe。 |
| F5 | Unwanted | 若 `pdf_url` 签名过期（>7天未 sync），详情页须显示"PDF 链接已过期，请联系管理员重新同步"，**不得** 500。 |
| F6 | Unwanted | 若某番号无 PDF（`pdf_url` 空），详情页须隐藏 PDF 区块（沿用 `detail.html:119` `{% if row.pdf_path %}` 逻辑改判 `pdf_url`）。 |
| F7 | Optional | Where 严格仅登录模式开启，系统须经线上 `/api/pdf/<番号>` 实时签（依赖 §4.B）。 |
| F8 | Ubiquitous | 系统须**全量上传** `data/attachments` 下所有 PDF（历史 3725 份 + 未来新增，**含**库内暂无对应房源的"孤儿"）。依据勇哥口径"只要取下来之后，就同步上云"；孤儿存储成本可忽略，且房源若日後复活仍可直接用。孤儿虽上传但不写 `pdf_url`（无对象可挂），详情页按 F6 隐藏。 |

## 7. 逻辑架构与数据流（详细）

```
[本地 osaka-mvp]
  crawler 抓详情
    └─ 落盘 data/attachments/<番号>.pdf
         └─ (钩子) tools/pdf_to_cos.py
              ├─ 上传 cos://bucket/<番号>.pdf   [COS 私有读]
              └─ 生成预签名 URL(7d) → UPDATE jproperty.db SET pdf_url=...
                    └─ (每轮/手动) tools/sync_to_publish.py
                         ├─ ① 数据：site_data.json（含 pdf_url，移出 PDF_KEYS 剔除）
                         ├─ ② 配置：剔除凭据（不含 COS 密钥，密钥本机）
                         └─ ③ 账号回流（v1.9.57 加固）
                              └─ workbuddy_sites_deploy → osaka-house-publish/app_local/
                                   └─ 线上 serve_public.py 灌库（pdf_url 入库）
                                        └─ 已登录销售访问详情页
                                             └─ detail.html iframe src=pdf_url（签名直链）
                                                  └─ 浏览器直拉 COS（不经我们后端）
```

**关键点**：展示流量**不经我们后端**（浏览器↔COS 直连），故不受 `PUBLIC_HIDDEN_APIS` 403 限制；后端只负责"在登录态下把 `pdf_url` 吐给页面"。

## 8. 增量自动化逻辑（Q4 落地）

- **触发点**：crawler 完成单房源详情抓取、确认 `data/attachments/<番号>.pdf` 存在后，调用 `pdf_to_cos.upload(no)`。
- **幂等**：以 `番号` 为 COS key；重跑覆盖写；`pdf_url` 仅在签名剩余 < 2 天时重签（避免每轮重签浪费）。
- **失败处理**：上传失败记入日志 + 房源 `pdf_url` 留空（详情页按 F6 隐藏），**不阻断抓取主流程**（门禁② 风险隔离）。
- **频率**：随本地 8765 自动抓取节奏（1–3h 随机），无需独立调度。

---

## 9. 数据口径

- `pdf_url`：COS 预签名直链（带 `q-sign-algorithm` 等参数），≤7天有效；**不**含本机路径（满足 §3 `pdf_path` 须空）。
- `pdf_path`：**仍**在 `PDF_KEYS` 剔除名单（本地路径不外泄）。
- 孤儿定义：`data/attachments/<x>.pdf` 但 `jproperty.db.properties` 无 `property_no=x` 且非在架 → 不上云（F8）。
- 版本：本功能随发版进版本号（建议 v1.9.60+）；`version.py` 单一源。

## 10. 权限与合规

- Bucket 私有读；如需"绝对仅登录"走 §4.B（待 WorkBuddy env 注入确认）。
- COS 用**只读子账号**密钥（仅 `GetObject`），即使泄露不可写/删。
- 不传任何本机凭据/REINS 账号到 COS 或线上（铁律）。
- PDF 内容合规：勇哥 9-22 已放宽 PDF 公开口径，但仅对"登录销售"开放符合其本意。

## 12. 成本估算（2.4GB / 3725 份 · **大阪 ap-osaka 境外地域**）

- **存储**：2.4GB 标准存储 → 约 **几元/月**（境外地域单价略高于境内；精准单价以控制台"价格计算器"查 `ap-osaka` 为准，小巴不编精确数字）。
- **流量**（主要变量）：销售看 PDF 走**境外外网下行**，约 **0.5–0.9 元/GB**（广州境内约 0.15–0.5 元/GB，大阪更贵但日本访问最快）。
  - 假设月浏览 100GB → 约 **50–90 元/月**；实际随使用量浮动。
- **请求**：PUT/GET ≈ 0.01 元/万次，忽略。
- **合计**：存储几元 + 流量 50–90 元/月量级。

> 💡 **地域权衡（已按勇哥拍板选大阪）**：销售在日本看 → 大阪最优（低延迟）；若未来发现员工主要在国内看且流量费偏高，可再镜像一个广州桶，但**现在不过度设计**，先大阪。

## 14. 验收标准

1. 线上详情页（已登录）对"有 PDF 房源"渲染図面 iframe，可翻页/缩放。
2. 未登录访问 → 跳 `/login`，看不到 PDF 区块。
3. 本地新抓 PDF 后，≤ 下一轮 sync 即在线上可见（增量自动化）。
4. `pdf_path` 不出现在线上库/数据包；COS 密钥不出现在发布工程。
5. 门禁全过：① `version.py` 证伪；② 真机 e2e（回读 `pdf_url` 条数）；③ locator 单一；⑥ `/api/selfcheck`+`/api/ping`；⑦ 总监审计红 0。
