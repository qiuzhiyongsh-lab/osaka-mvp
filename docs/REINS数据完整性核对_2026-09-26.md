## 六、根因排查结果（5WHY，推翻「12:02 disk I/O 导致 79 缺失」旧假设）

### 关键修正（证据先行）
原 §三/§五 把 79 缺失归因为「12:02:38 disk I/O error 那轮指定日期下载失败」。实测 `data/logs/server.log` **推翻**该假设：

- 12:02:38 的 `disk I/O error` 真实存在，但发生在 **戸建组（第 1/3 组）** 中段；该轮随后**被重启并于 12:23:14 完整跑完**（落库 629，含 売マンション 第 2/3 组 111+353）。売マンション 是第 2/3 组，在故障之后才跑 → disk I/O **不可能**是 79 个売マンション缺失的直接原因。
- 抽样 7 个缺失番号（`300140884516 / 300140881860 / 300140248216 / 100139958662 / 300139781505 / 300140882381 / 300140883816`）**在 server.log 中完全无记录**（无 `已存在`/未采集/未提交）→ 爬虫**从未处理过**它们，而非「采到却因 disk I/O 丢失」。

### 真正的根因：自动增量（今日日期同步）自 2026-09-25 12:30 起全死
9/26 当天**每一次**自动增量「今日日期同步（2026-09-26）」都失败：
```
11:44:56 / 12:48:50 / 13:48:09 / 14:58:03 / 16:06:51 / 17:08:36  ⚠ 今日日期同步失败：'sqlite3.Row' object has no attribute 'get'
```
而「指定日期下载」（手动、瞄准 2026-09-25）在 11:19 / 12:23 **正常完成**（落库 307 / 629）。即：**自动增量全挂、手动指定日期下载正常**。

### 5WHY
1. **为何 79 缺失？** 爬虫在可见日志窗口内从未采集到这 79 个番号。
2. **为何没采集？** 唯一能抓「当日（2026-09-26）新上架」的自动增量（今日日期同步）当天**每次都崩**；手动指定日期下载只瞄准 2026-09-25（不含 9/26），且其 売マンション 変更轴还有 378→353 共 25 条缺口。
3. **增量为何崩？** `sync_today_dates` 对每条结果调用 `_needs_detail(existing)`（crawler.py:3384），`existing = store.get_property(no)` 返回 **`sqlite3.Row`**；`_needs_detail` 在第 **1271/1273** 行对它调用 `existing.get("pdate_checked")` —— **`sqlite3.Row` 没有 `.get()` 方法**（只有下标 `[]`），抛 `AttributeError` 整轮中断。
4. **为何会调 `.get()`？** `store.get_property` 自 2026-09-17 就返回 `sqlite3.Row`（store.py:522/550/972）；而 **2026-09-25 12:30 提交 `fb7be114`** 在 `_needs_detail` 引入规则③/④时，用字典式 `existing.get("pdate_checked")` 写成了 Row 不兼容写法（应为 `existing["pdate_checked"]` 或先转 dict）。
5. **为何当时没暴露？【根因层】** 该 bug 只在「库里已存在 + 走 `_needs_detail` 判定」的路径触发；手动指定日期下载每套全量重抓/刷新、**不踩这条判定**，故 9/25 改完后的手动跑没炸；**自动增量是首个稳定踩中该路径的调用方** → 9/26 起每天全挂。**根因 = 缺回归测试 + Row/dict 混用无类型保护**。

### 影响范围（比 79 更大）
自动增量自 **2026-09-25 12:30** 起持续失效 → 9/25 下午～9/26 的「当日新上架/变更」**全種目**都可能漏抓。79 只是勇哥 405 売マンション 清单 diff 暴露的**冰山一角**；实际缺口或含戸建/土地/タウン，更大。

### 整改项（可落地，非临时绕法）
- **P0 修代码**：`_needs_detail` 入参顶部把 `existing` 归一化为 dict（兼容 Row 与 dict），现有 `.get()` 即可用：
  ```python
  if existing is not None and not isinstance(existing, dict):
      try: existing = dict(existing)
      except Exception: existing = None
  ```
  等价也可直接改 1271/1273 为 `existing["pdate_checked"]` 并加越界保护。→ 修完增量即恢复。
- **P1 回归保护**：加单测——用 `sqlite3.Row` 模拟 `get_property` 返回值喂 `_needs_detail`，断言不抛 `.get()`；冒烟别只测手动指定日期下载，要含自动增量当日。
- **P1 顺带硬化 disk I/O**：12:02:38 那次虽已自愈，但属真实现网风险（DB 在用户目录，或被 OneDrive/杀软实时同步锁文件；WAL/shm 临时文件）。建议：① 确认 `data/` 是否被 OneDrive/杀软实时同步（若是加排除）；② 写库失败加 `SQLITE_IOERR` 重试 + 单写者；③ 定期 `PRAGMA integrity_check`。
- **P2 补数据**：修完代码 + 重启 8765 让增量自愈后，再对 `data/_diff_missing_nos.txt`（79 个）走 `refresh_by_no.py --file ... --no-pdf` 把**这 79 个精确补齐**（覆盖手动轮漏的 25 条変更轴缺口）；并视情况对 9/25 下午～9/26 全種目做一轮指定日期下载兜底。
