一、全局：这个软件是干嘛的、八个页面怎么连起来

1.1 一句话说清楚这个软件

它把日本不动产网站 REINS 上的房源数据，自动抓回到你自己的电脑里，存成三样东西：

  • 一个本地数据库（软件里能查、能看）；
  • 一份 Excel 表 和一份按天网页（可以直接发给人看）；
  • 每套房子的 PDF 图纸。

然后你在本机就能查询、看详情，不必每次登录 REINS 慢慢翻。

背后在干什么（重要）：你的电脑上同时跑着两个东西——①一个叫 REINS 的网站（数据来源，在云端，需要账号密码登录）；②一个叫 本机服务 的小程序（地址就是 http://127.0.0.1:8765，你打开的每个页面都是它在响应）。它俩之间靠一个"自动操作浏览器的机器人"（Playwright 驱动 Edge）沟通：机器人帮你在 Edge 里打开 REINS、填账号、点检索、把结果抄回本机。
为什么必须"有窗口"：REINS 会拦截"没有窗口的机器人"（无头浏览器），所以这个机器人用的浏览器必须有可见窗口——这也是"测试登录/真实下载"时会自动弹出浏览器窗口的原因，属于正常现象，别手动关掉它。

1.2 八个页面是什么关系

软件一共 8 个页面。顶部那排导航就是它们的"电梯"，点一下就切过去。它们的分工可以这样理解：

页面一句话定位你会在这里做的事
概览（首页）仪表盘，看总数与状态看有多少房源、今天新增/降价多少；想立刻更新就点这里
数据抓取设置操作总控台（把数据抓回来的地方）环境自检 → 登录 → 测试 → 真实下载 → 设定自动更新
房源查询在本机库里找房子按区/价/面积筛选；给看中的房子点「加入对比」
房源对比（v1.1.0 新增）多套横向比优劣从查询/对比栏进入，一眼看哪套更好或不够好
房源详情（无导航按钮）一套房子的全部信息从查询结果点进去看细节；也可点「加入对比」把这一套放进对比篮
账号管理录入 REINS 账号（本地加密）填账号密码并保存、测试登录
本地文件打开落盘文件打开 Excel、按天网页、PDF 图纸
运行日志看每轮抓取的过程与成败排查"为什么没更新到 / 更新了几条"
账号管理→ 数据抓取设置（自检→登录→测试→下载）→ 概览（看结果）→ 房源查询→ 房源详情

旁边两支：本地文件（看导出的文件）、运行日志（看过程记录）。

1.3 每个页面都一样的"公共元素"

以下两部分出现在每一个页面，先认脸，后面不再重复。

① 顶部导航栏

位置长什么样功能 / 背后干了啥什么时候用
最左：Logo 显示"大阪房源 本地版"。点击会回到「概览」首页（相当于"回主页"）。 迷路时点它回首页。
中间：7 个导航链接 依次是 概览 / 数据抓取设置 / 房源查询 / 房源对比 / 账号管理 / 本地文件 / 运行日志。点哪个就切换到哪个页面；当前所在页会高亮（图中"概览"被框起）。「房源对比」上会带一个数字角标，显示对比栏里已选了几套（0 时隐藏）。 想去别的功能页时点。
最右：模式徽标 一个只读状态灯，告诉你软件现在处于哪种模式：真实抓取＝连真的 REINS；离线演示＝只用内置样例数据、不联网。它不可点击，只用来"看一眼现在是不是真的在抓"。 不确定刚才切没切到"真实抓取"时，瞟一眼这里。
易混点：右边这个绿/灰徽标是"状态显示"，不是按钮，点它没反应；真正"切换模式"的按钮在【数据抓取设置】页顶部（见第 5 章）。

② 页脚

每个页面最底部有两行小字：

  • 数据全部保存在本机：后面跟着一个路径，说明你的数据存在电脑的哪个文件夹（默认在 …\osaka-mvp\data）。背后含义：数据不上云、只在本机，换电脑要手动拷这个目录。
  • 版本 v1.1.2 · 更新于 2026-09-11：软件的版本号和构建时间（v1.1.0 新增【房源对比】页与查询/详情优化；v1.1.1 账号页「网站名称 → 网站地址」并使其真正生效；v1.1.2 修「清空」相关 2 个 bug、详情页对比改两步走、对比页加引导页）。报问题给开发时，把这一行一起发过去最有用。

二、概览（仪表盘）— 打开软件第一眼看到的页

这一页是干嘛的：像汽车仪表盘——一眼看到"现在有多少房源、今天新上多少、有没有降价、最近一次什么时候更新的"，并且想立刻抓一轮数据就点这里。

2.1 逐位置说明（从上到下）

位置功能背后在干什么
① 刷新条（最上面一行）显示"概览 · 每 60 秒自动刷新"，并提供"🔄 刷新一次"和"上次刷新时间"。软件每分钟自动向本机服务要一次最新数字；你也可以手动点刷新。它只刷新数字，不重新抓 REINS（真正的抓取在下面的按钮）。
② 五张数字卡（KPI）本地房源总数 / 今日新盘 / 今日降价 / 已落盘 PDF / 最近一次更新。数字直接从本地数据库统计出来。"今日新盘"=今天第一次被发现的房源数；"今日降价"=今天价格下调的数量；"已落盘 PDF"=已下载到的 PDF 份数。
③ 自动更新状态条 + 三个按钮显示"自动更新：运行中/已停止"及规则；右边是三个操作按钮（见下表）。决定"要不要让软件自己定时抓"。状态灯绿=定时任务在跑，灰=已停。
④ 最近变更表列：时间 / 房源 / 类型 / 原值 / 新值。类型有新規新盘、降价、变更。每次抓取后，软件会对比"这条房源和上次比有没有变"，把有变化的记在这里。点"房源"编号可直接进详情。
⑤ 最近运行表列：# / 开始 / 触发 / 扫描 / 落库 / 新盘 / 变更 / 状态。记录最近几次抓取任务的跑步成绩。状态成功=跑完；进行中=正在跑；失败=出错。这是判断"抓取到底有没有成功"的第一现场。

2.2 这一页的每一个按钮

按钮长相：

🔄 刷新一次

作用：手动刷新这一页上的数字（KPI、状态、两张表），让它显示"此刻最新"。

背后：向本机服务请求一次 /api/overview，把最新的统计数字和表格内容重新灌进页面，并更新"上次刷新"时间。不会去 REINS 抓数据，只是"重新读一遍本机已有的账本"。

什么时候用：你刚在别处点了"手动更新"，想看结果时；或你想确认数字是不是最新的。平时不用点，它每分钟自己刷。

按钮长相：

▶ 手动更新（立刻抓一轮）最常用

作用：不等定时任务，立刻去 REINS 抓一轮全部数据，抓完写入本机库。

背后：请求 /api/run。软件会启动真正的抓取流程：打开浏览器→登录 REINS（用你存的账号）→按保存好的检索条件（土地/一户建 + 公寓）检索→逐条打开详情、抄下全部字段、下载 PDF→对比变化→写库。整个过程可在【运行日志】页看到实时进度。

什么时候用：你想"现在就更新一次"、看有没有新盘或降价时。注意：全量一轮可能较久，跑的过程中不要再点。

按钮长相：

试跑（最轻量）

作用："小样试跑"——只跑最小范围（1 轮查询、最多 3 条详情），用来确认整条链路（登录→检索→解析→下载）通不通。

背后：同样请求 /api/run，但带 trial=true。它会限制条数、缩短耗时，属于"先尝一口"。数据也会落库，但量很小。

什么时候用：第一次配置好后、或改了设置想验证"还能不能抓"，又不愿等全量时。

按钮长相：

数据抓取设置 · 测试与设置 →

作用：一个跳转链接，把你带到【数据抓取设置】页去做登录、测试、设定自动更新。

背后：只是页面跳转（到 /collect），不改数据。

什么时候用：你要开始配置/跑通流程时的主入口。

查看全部运行日志 →

作用：跳到【运行日志】页，看完整的抓取记录。

背后：页面跳转到 /runs。

什么时候用：想排查某次抓取为什么不成功时。

三个按钮的关系："试跑"和"手动更新"是同一件事的两种力度（小样 vs 全量），它们跑完的结果都会出现在下面的"最近运行""最近变更"两张表里；"数据抓取设置·测试与设置→"是去配置它俩的入口——登录、账号、自动更新都在那边设。

三、房源查询 — 在本机库里按条件找房子

这一页是干嘛的：房源的"搜索引擎"。所有数据都来自你本机的库（已经抓回来的），所以不联网、秒出结果。

3.1 逐位置说明

① 查询条件区（页面最上方的一块）

位置填什么背后在干什么
关键词（地址 / 楼名 / 物件番号）如"中之岛 / グランドメゾン / 3001407"模糊匹配"地址、楼名、物件番号"三个字段。
区下拉：全部 / 住之江区 / 天王寺区 / …按行政区过滤。
物件種目下拉：全部 / 中古マンション / 売地 …按房子种类过滤（公寓、土地等）。
价格下限(円) / 价格上限(円)数字，可不填按价格区间过滤。空着=不限。
面积下限(㎡) / 面积上限(㎡)数字，可不填按面积区间过滤。
日期默认"当天"，可改成任意一天很关键：这一页默认只看"当天数据"。想看别的日期（比如昨天抓的），把日期改掉即可。
只看带 PDF不限 / 仅带 PDF只看那些已经下载到 PDF 图纸的房源。

② 结果区（下方卡片列表）

每张卡片代表一套房子，从上到下分别是：地址（蓝色标题）、物件番号 / 地先·名称 / 交通、价格（红色大字，单位"万 円"）、専有·土地面积、"画像 N 枚"、"有 PDF"徽标。点卡片上的地址标题即可进入【房源详情】。

"共 N 条"和日期："查询"按钮右边会显示"日期：2026-09-11 ｜ 共 11 条"，意思是"在你选的日期里，一共找到 11 条"。这就是软件确实按日期过滤了的凭证。

3.2 这一页的按钮

按钮长相：

查询 主按钮

作用：按你填的条件，在本地库里找出房源，显示在下面。

背后：请求 /api/query，把上面的条件拼成一次数据库查询；日期为空时默认查当天。返回每套房子的摘要 + 详情 + PDF 链接。

什么时候用：每次改完条件、想看结果时点。

重置

作用：把上面所有条件清空、回到初始状态（日期回到当天）。

背后：只清空表单，不查库；通常清空后可以再点"查询"看全部。

什么时候用：条件填乱了、想从头再来时。

3.3 每页条数 & 加入对比（v1.1.0 新增）

① 每页条数（工具栏右侧下拉）

默认 50 条一页，另可选 100 / 200。值只改前端分页大小，不重新抓库。分页条加了「首页 / 上一页 / 下一页 / 末页」，并显示「共 N 条 / 第 X/Y 页」。

② 加入对比（每行最左边的按钮）

结果每行最左边都有一个圆角按钮（手机上是左侧圆形勾选框）。点一下 → 这套房进入底部对比栏，按钮变绿显示「✓ 已选」；再点一下取消。

  • 上限 6 套：对比栏最多同时放 6 套。点到第 7 套会弹提示「最多同时对比 6 套房。请先在底部『对比栏』里点 × 去掉一套，再添加新的。」，不会加进去。
  • 跨页保留：选中的房子存在浏览器本地（localStorage），翻页/刷新/进详情再回来都还在；导航「房源对比」的数字角标同步变化。
  • 底部对比栏：选了 ≥1 套才出现，固定在页面底部，显示已选缩略（楼名/地址/价格/有无 PDF），右侧「清空」「开始对比」。
  • 「清空」会同步刷新列表 v1.1.2 修复：以前点「清空」并确认后，底部对比栏消失了，但列表里每行的「✓ 已加入」还留着，看上去像没清掉。现在清空后，底栏、每行按钮文字/底色、导航角标一起归零（一处改动，三处同步）。详见 11.7。
  • 顺带加固的两种场景 v1.1.2：① 你在另一个标签页改了对比栏，本页会自动跟着更新；② 点浏览器「后退」回到查询页时，页面会重新对一次勾选态，不会显示旧状态。

四、房源详情 — 一套房子的全部信息

这一页是干嘛的：点开某套房，看它的全部字段、变更历史（有没有降过价）和抓取快照。这一页没有导航高亮，因为它是从查询页"点进去"的。

4.1 逐位置说明

位置功能背后在干什么
① 顶部一行关键信息地址 + 楼名 + 价格（红色）+ 降价徽标（↓ 降了多少）。一眼看完全套最要紧的三件事，不用往下滚。
② 核心 meta 胶囊種別 / 間取り / 専有·土地·建物面积 / 沿線·駅 / 所在階 / 階建 / 築年月 / 画像数 / 物件番号。最常用的指标做成小胶囊排成一行（可自动换行），先给"筛选用得上"的数。
③ 按钮 + 说明行[打开本地 PDF][原网页][返回查询]，下一行是 [加入对比][去对比] + 一行说明文字。对比是"先加入、再一起比"的两步（见 4.2）。
④ 详细信息（密集网格）物件番号 / 所在地 / 交通 / 価格 / 前回価格 / ㎡·坪单价 / 専有·土地·建物面积 / 階 / 築年月 / 画像数 / 登録·変更年月日，以及详情页抓到的其它字段（交易方式 / 用途地域 / 管理费 / 修缮积立金 / 中介公司 / 中介电话 / 公开状态…，都译成中文）。这些是从 REINS 详情页一条条抄回来的原文，存在本机库里。电脑端一屏基本能看完，手机端两三列。
⑤ 变更历史 / 抓取快照（默认收起）变更历史：时间 / 类型 / 原值 / 新值；抓取快照：抓取时间 / 价格(円) / 指纹。变化记录与"下次抓时它变没变"的依据——这是软件判断降价的原理。默认折叠，不把页面撑长。
紧凑目标（v1.1.0 起）：电脑端一页显示完；手机端核心信息放最上面，不超过两页。所以"不常用的"（变更历史、快照）默认收起，"最核心的"（地址/价格/面积/間取り/駅）提到最上面。

4.2 这一页的按钮

按钮长相：

原网页

作用：在浏览器新标签里打开这套房子在 REINS 上的原始页面。

背后：跳到 REINS 官网对应物件链接（需你已登录 REINS 才能看到完整内容）。

什么时候用：想核对原始信息、或看本机没抓到的图片时。

返回查询

作用：回到【房源查询】页继续看别的房子。

背后：页面跳转到 /search（注意：不会带着你上次的筛选条件，属于"重新进查询页"）。

什么时候用：看完一套，接着看下一套时。

加入对比 v1.1.2 改

作用：把当前这一套放进本机浏览器的「对比篮」（最多 6 套）。再点一下 = 取消。就像超市先把想买的东西放进购物车，不结账。

背后：读写浏览器本地 localStorage（key osaka.compare.v1），不联网、不上云。按钮文字实时显示「已加入对比 ✓（N/6）」。

什么时候用：看到一套想纳入比较的房，先放进来（不用马上决定跟谁比）。

去对比 v1.1.2 新增

作用：凑够 2 套后，一次性把对比篮里全部的房子并排比。

背后：跳转 /compare（读对比篮里的全部，不是只带这一套）。不足 2 套时按钮置灰，硬点会提示你先再加一套、并告诉你加在哪。

什么时候用：觉得选得差不多了，想看对比结果时。

4.2.1 这一版为什么把「对比」拆成两步？ v1.1.2 说明

先说之前会遇到的坑。v1.1.0 时这里只有一个按钮，写着「和已选的房子对比」，点下去会带着"本套房"直接跳到对比页（/compare?nos=本套）。结果有两个问题：

  1. 只有一套，根本没得比 —— 对比的本质是"至少两套并排看"，一进页只能看到一句"还不够 2 套房"，让人莫名其妙。
  2. 把之前选好的房子顶掉 —— 跳转时只带本套房，你之前在查询页选的其它候选房就没了。

现在的两步，各干一件事：

步按钮做什么什么时候用
①加入对比把当前这一套放进「对比篮」（购物车）看到一套想纳入比较的房
②去对比这 N 套 →凑够 2 套后，把篮里全部房子并排比想看对比结果时

几个贴心细节：

  • 按钮上永远写着当前已选几套：「加入对比（已选 2/6）」→ 点完变「已加入对比 ✓（3/6）」，一眼知道进度。
  • 已选时再点一下 = 取消（同名切换），不用去找哪里删。
  • 不足 2 套时「去对比」是灰的，硬点会提示你先再加一套（并告诉你加在哪）。
  • 按钮下方有一行随状态变化的说明文字：没选时解释"对比是干嘛的"，已选时告诉你"还差几套"。
  • 不会覆盖你之前的选择（这是重点，和 v1.1.0 的行为不同）。

五、数据抓取设置 — 设置与测试总控台（最重要的一页）

先看这一句：如果你只想让软件跑起来、自动更新房源，所有"开关"都在这一页。它把整个流程按 1→2→3→4 四步 排好了，照着从上往下点即可。

这一页是干嘛的：把 REINS 的数据抓回本机之前的一切准备与设置——先确认能登录、能查询，再正式开跑。

5.1 顶部：标题 + 模式切换

页面标题"数据抓取设置"右侧有两个元素：一个模式徽标（，只读状态灯）和一个切换按钮。

按钮长相：

切换到离线演示 / 切换到真实抓取

作用：在"真实抓取"和"离线演示"之间切换模式。按钮文字会随当前模式变化：现在是真实抓取，它就显示"切换到离线演示"；反之亦然。

背后：请求 /api/mode，把配置里的 app.mode 改成 live（真实）或 demo（演示）。演示模式下所有"真实"操作都会被礼貌拒绝，提示你去切换。

什么时候用：只是想看看界面、不想联网抓数据 → 切"离线演示"；要抓真数据 → 切"真实抓取"。

5.2 第 1 步：环境自检

按钮长相：

开始自检

作用：检查你这台电脑是否具备抓取条件——不联网也能查。

背后：请求 /api/env，逐项检查三件事并以弹窗列给你：① Playwright 库是否安装；② Edge 浏览器能否被自动驱动；③ 登录会话文件是否已存在。任一不满足会显示 ✗ 和解决提示。

什么时候用：第一次使用、或换了电脑/重装后；跑真实下载失败时先来点它自查。

5.3 第 2 步：账号与登录

这一块显示"账号是否已保存"（已保存账号 / 未保存），并提供两个操作按钮。

按钮长相：

账号管理 →

作用：跳到【账号管理】页去录入/修改账号（还没录账号时，先点它）。

背后：页面跳转到 /account。

① 测试登录

作用：用你保存的账号，让软件自动填表登录 REINS，验证"账号能不能登进去"。不会抓数据。

背后：请求 /api/login/auto。软件会弹出可见的浏览器窗口，自动输入会员ID+密码、勾选同意、点登录；成功则把登录状态（会话）保存下来，供后续抓取复用。若遇到验证码等须人工介入的情况，会失败并提示你改用"手工登录"。

什么时候用：填好账号后、正式下载前；或怀疑登录过期时。

手工登录（打开浏览器）

作用：弹出浏览器窗口，由你亲手输入账号密码（适合有验证码、自动登录失败的情况）；登录成功后软件自动保存会话。

背后：请求 /api/login，打开 REINS 登录页等你操作（最多等约 5 分钟），检测到已登录就保存会话。

什么时候用："① 测试登录"失败、或出现验证码/风控提示时，用这个兜底。

顺序很重要：第 2 步 ①测试登录 必须在 ②测试查询 之前完成——没登录成功，后面查询/下载都会失败。

5.4 第 3 步：测试查询与下载

三个按钮，力度递增：② 只看不存 → ③ 小量真下 → ④ 全量真下。

按钮长相：

② 测试查询

作用：登录后跑一个最小范围的查询，看能不能查到、查到几条。

背后：请求 /api/query/test，返回"结果 N 条 + 样本几条"，不写入本机库。

什么时候用：确认"登录之后确实能检索到数据"这一步。

③ 测试下载数据

作用：真实下载但只下很小的量（1 轮、最多 3 条 + PDF），验证"检索→详情→PDF 下载→落库"这条链路通不通。

背后：请求 /api/download/test，跑一次"试跑"级别的真实抓取，会落库少量数据。

什么时候用：正式全量下载前的"彩排"。

④ 真实下载数据 较重

作用：按配置全量跑一轮，把数据正式写入本机库（SQLite + Excel + 按天页 + PDF）。

背后：请求 /api/download/real。这是真正意义上"把 REINS 数据搬回家"的动作，耗时最长。跑的过程可去【运行日志】看进度。

什么时候用：前面①②③都通过后，正式取数时点它（或日常用【概览】的"手动更新")。

5.5 第 4 步：更新方式（让软件自己定时跑）

先填"规则"，再决定"启动/保存/停止"。

字段填什么背后在干什么
自动更新方式① 定时（固定间隔）/ ② 随机（随机间隔）决定多少小时跑一次：定时=每次间隔都一样；随机=在上下限之间随机取，更像真人、更稳。
间隔（定时时出现）1 / 2 / 4 / 8 小时固定每 N 小时抓一轮。
随机下限(h) / 随机上限(h)（随机时出现）如 1.0 ~ 3.0在 1~3 小时之间随机决定下一轮时间。
运行时段 起 / 止默认 07:00 ~ 23:00只在这个时间段内自动抓（REINS 深夜在维护，抓也没用）。
按钮长相：

保存并启动自动更新

作用：把上面的规则存下来，并立刻开启定时任务，之后软件会按时自动抓。

背后：请求 /api/schedule（带 enabled=true），保存配置并启动后台调度线程。启动后【概览】的状态灯会变绿。

什么时候用：想让软件"不用管，自己更新"时。第一次跑通全流程后再开。

保存设置（暂不启动）

作用：只把规则存下来，但不开启自动更新（保持"已停止"）。

背后：请求 /api/schedule（enabled=false），只写配置。

什么时候用：想先把规则定好、稍后再开；或只想"手动更新"不想自动时。

停止自动更新

作用：关掉定时任务（红色按钮，代表"停止"）。

背后：请求 /api/schedule（enabled=false）并停掉后台线程；状态灯变灰。未启动时此按钮为灰色不可点。

什么时候用：不需要它自动跑、或临时想让它停下来时。

5.6 底部的"测试结果"和"实时日志"

  • 测试结果：显示上面四个测试按钮（①测试登录 / ②测试查询 / ③测试下载 / ④真实下载）的最近一次结果和状态标签。没有任何记录时会提示"还没有测试记录。按上面 1~4 步依次点一遍即可"。
  • 实时日志：一个深色日志框，每 2.5 秒自动刷新，滚动显示软件正在做的事（如"登录成功""检索到 N 条""已下载 PDF"）。它是最直接的"背后发生了什么"的证据窗口。

六、账号管理 — 录入你的 REINS 账号

这一页是干嘛的：把你的 REINS 会员ID和密码存到本机（加密保存、不上传），供自动登录用。

6.1 逐位置说明

位置填什么 / 是什么背后在干什么
① 状态行绿色"真实抓取/已保存"标签 + 账号名称 + 会员ID（打码）+ 登录地址 + 更新时间。告诉你"目前存的哪个账号、用的是哪个登录入口"。会员ID只显示首尾，中间打码。
② 账号名称给账号起个名（如 主账号 / 备用）。仅作标注，方便日后多账号区分，不参与登录。
③ 会员ID / ユーザID你的 REINS 登录账号（或邮箱）。自动登录时填进 REINS 的用户名框。
④ 密码（パスワード） ＋ 👁显示你的 REINS 密码；点"👁显示"可明文核对。自动登录时填进密码框。保存时加密。
⑤ 网站地址 v1.1.1 正名这个账号要登录的网址（默认已填 https://system.reins.jp/login/main/KG/GKG001200）。真正生效：自动登录优先用这里填的地址；留空或填的不是网址 → 回退 config.yaml 的 site.login_url。
⑥ 安全说明黄色小字：密码只存本机（credentials.json + 密钥 .cred_key），不联网、不上传、不共享。提醒你数据安全边界。
⑦ 登录页选择器（可折叠）"高级，自动登录失败时才需要看"，默认收起。进阶设置：若 REINS 改版导致自动登录失败，可在这里校准"网页元素定位"。平时不用动。

6.1.1 「网站地址」这一格，为什么可以放心改 v1.1.1

先说结论：它填的是网址，不是"网站名称"——所以标签已由「网站名称」正名为「网站地址」。

这个地址是可以调整、可以改变的，而且改了就生效：

  • 地址形如 https://system.reins.jp/login/main/KG/GKG001200，最后那段 KG/GKG… 是所属机构的编号。
  • 换机构、换账号时，这一段就会变 —— 你直接改这一格，点「保存账号」，之后自动登录就走新地址，不需要再去动配置文件。
  • 连域名换了也认：程序会从你填的地址里自动取站点根地址，物件详情链接照旧能生成。
  • 想回到默认？把这一格清空再保存即可（自动回退配置里的默认登录地址）。
  • 以前存的旧值（若填的是文字，不是网址）不会出错，会自动回退到配置默认值。

*图（v1.1.1）：「账号管理」页的「网站地址」输入区（输入框 + 下方说明文字）。*

6.2 这一页的按钮

按钮长相：

保存账号

作用：把填的会员ID+密码（及账号名称 / 网站地址）加密保存到本机。

背后：请求 /api/credentials，用本机密钥加密后写入 data/credentials.json。

什么时候用：第一次录入账号、或修改密码后。

显示已保存密码

作用：把已保存的密码明文显示出来供你核对。

背后：请求 /api/credentials?show=1，仅当在本机访问时才返回明文（安全限制）。

什么时候用：忘了存的是哪个密码、想核对时。

测试登录

作用：同【数据抓取设置】的"① 测试登录"——用存好的账号自动登录一次 REINS 验证。

背后：请求 /api/login/auto，弹浏览器自动填表登录。

什么时候用：刚保存完账号，想立刻验证能不能登进去。

清空 会删除

作用：删除本机保存的账号（红色=危险操作）。

背后：请求 /api/credentials（DELETE），清空 credentials.json。删了就登不了、也抓不了。

什么时候用：换账号、或不再使用时。点之前想清楚。

安全红线：密码只在本机加密保存，软件不会把你的账号密码传到云端。也不会替你输入验证码——需要验证码时请用"手工登录"。

七、本地文件 — 打开落盘的文件

八、运行日志 — 看每一轮抓取的过程

这一页是干嘛的：抓取的"行车记录仪"。想知道刚才那一轮到底跑没跑、跑了几条、有没有出错，看这里。

8.1 逐位置说明

位置是什么列 / 含义

9.2 常见任务，一步到位

场景 A｜我第一次用，想跑通整条流程

  1. 【账号管理】填 会员ID + 密码 → 点 保存账号；
  2. 【数据抓取设置】点 开始自检，确认三项都 ✓；
  3. 点 ① 测试登录（会弹浏览器，等它自己登完）；
  4. 点 ② 测试查询 → 再点 ③ 测试下载数据（小量彩排）；
  5. 都通过后，点 ④ 真实下载数据（正式全量取数）。

场景 B｜我只想看数据，不折腾抓取

  1. 进【概览】看总数/新盘/降价；
  2. 进【房源查询】，选"区/价格/面积"→ 点 查询；
  3. 点某条房源的标题 → 进【房源详情】看全部字段。

场景 C｜我想让软件自己定时更新

  1. 先按场景 A 跑通一次；
  2. 【数据抓取设置】第 4 步选"随机"、填 1~3 小时、时段 07:00–23:00；
  3. 点 保存并启动自动更新；回【概览】确认状态灯变绿、显示"运行中"。

场景 D｜我想此刻就更新一次

11.6 「清空对比栏」为什么以前会"清不掉"？ v1.1.2 修复

现象：在对比页点「清空对比栏」并确认后，本以为页面会变空，结果房子又自己回来了（表格还是那几套）。

原因：清空这个动作会触发一次"对比栏变了 → 重新加载页面"的联动。当时执行的顺序是「先清空 → 再改地址栏 → 再重载」，而那次自动重载读的还是旧地址栏（里面还带着 ?nos=A,B,C），于是又照着旧地址把 A、B、C 加载了回来，等于白清。

修复：把顺序理正 —— 先把地址栏的 ?nos= 去掉 → 再清本机选中 → 最后重载；并且给这次"自己改自己"的操作加了一个开关，避免它再触发一次多余的自动重载。

现在点「清空对比栏」的结果是：表格消失、导航角标归零、地址栏变成干净的 /compare、并显示"还不够 2 套"的引导页。

同理，对比表里点某一列右上角的 × 移出（尤其是移出最后一套时）也走同一套逻辑，不会再"复活"。

11.7 查询页「清空」也会同步刷新列表 v1.1.2 修复

现象：在房源查询页点底栏「清空」并确认后，底部对比栏消失了，但列表里每行的「✓ 已加入」还留着，看上去像没清掉。

原因：当时"对比栏变了"这个信号只通知了底部对比栏去刷新，忘了通知列表里每一行的按钮去同步勾选态。

修复：现在一处改动、三处同步——底部对比栏、每行按钮文字/底色、顶部导航角标，同时归零。

顺带加固的两种场景：① 你在另一个标签页改了对比栏，本页会自动跟着更新；② 点浏览器「后退」回到查询页时，页面会重新对一次勾选态，不会显示旧状态。
