# 发版前检查清单（一页纸勾选版）

> 配套文档：`发版铁律与根因复盘_2026-09-27.md`
> 用途：**每次发版前照此逐条打勾，全部 ✅ 才执行 deploy**。本清单本身就是流程的保险绳。

---

## A. 发版前准备（本地 osaka-mvp）

- [ ] 代码改动已完成，本地 8765 已**重启**验证（改 core/ 或 web/ 必须重启才生效）
- [ ] 已跑 `tools/sync_to_publish.py --target app_final_v3`（**必做**！略 target 会同步到 2104 冷备）
- [ ] `config.local.yaml::publish.endpoint` 指向**当前线上域名**（旧域名 404 会让回流/推送静默打空）
- [ ] `grep -rn` 扫过 `tools/` 与配置，无残留**硬编码旧域名**（历史注释中的不算）
- [ ] 本次如有功能/修复变更，`core/version.py` 的 `VERSION` 已抬档
- [ ] 🆕 **（2026-10-09 事故）确认当前会话工作区 `.workbuddy/applications.yaml` 已绑定目标 app**
      —— deploy 工具按**会话工作区**判定应用归属；未绑定 = 平台新建 app + **换子域**（红线）。
      v100 绑定在 `E:\workbuddy\2026-09-11-09-50-22\.workbuddy\applications.yaml`
      （`locator: wbapp_vN7DtOaDBJW4muPFZxjbxl`）。**在未持有该绑定的会话里发版 = 另建新站。**
- [ ] 🆕 **是否只是要更新数据？** 若代码两侧同版本，`python tools/force_full_push.py`
      走 `/api/ingest` 直推即可，**不必 deploy**（不触发重部署、链接不变、无空窗）

## B. 部署（关键：绝不删应用）

- [ ] `deploy` 指向**同一个目录**（复用沙箱 → 子域不变）
- [ ] **不传 appId**（工具按目录推导，删后才新建；我们不删）
- [ ] `domainPrefix` 照传（仅新建 app 才生效，本次不会新建 → 子域保持不动）
- [ ] 🆕 **必须显式 `startCmd=python run.py` + `port=3000`**
      —— 平台 auto 会误判入口为 `main.py`（发布目录无此文件）→ 部署失败。
      `run.py` 才是线上入口（读 `$PORT`、绑 `0.0.0.0`）；`serve_public.py` 只有 `create_app()` 无 `app.run`
- [ ] 🆕 在某会话首次 deploy 前，先看该工作区有没有 `applications.yaml`；**没有就别发**（会新建换子域）

## C. 部署后验证

- [ ] 若 `selfcheck` 显示 `running_version` 仍是旧的 → `POST /api/admin/selfrestart`（带 X-Publish-Token）原地刷新
- [ ] `GET /api/selfcheck` 的 `running_version` == 发布包版本号
- [ ] **发布后立刻核对返回的 shareLink 是否与原来完全一致**——出现随机后缀（如 `-15444`）说明新建了 app，立即 `unpublish` 并回报
- [ ] `GET /api/emp/export`（带令牌）计数：以发布前数值为基线，**只增不减**（员工数据会自然增长，减少 = 数据丢失）
      2026-10-09 基线：favorites 15 / tags 17 / property_tags 36 / customers 9 / customer_properties 27 / customer_tags 14
- [ ] `POST /api/ingest`（带令牌）返回 `ok:true` 且 `total` == 本地房源行数
      2026-10-09 实测：本地库 9204 行 → 推送 9203 行（差 1 为哨兵行，属正常）

## D. 铁律（违反任一条即记事故）

- ❌ **绝不**让用户进 UI「删除应用」来做发版
- ❌ **绝不**主动去换/回收子域（回收 = 再删一次应用，正是要永久避免的动作）
- ❌ **绝不**把不可逆/破坏性操作甩给用户（先想：有没有代码/接口能绕开）
- ❌ **绝不**在未读工具文档、未核实平台真实行为前，把"旧结论"当铁律

## E. 一句话口诀

> **改代码 → sync → 同目录 deploy → 必要时 selfrestart → 验证。**
> **不删、不换、不甩给用户。**
