# 发版前检查清单（一页纸勾选版）

> 配套文档：`发版铁律与根因复盘_2026-09-27.md`
> 用途：**每次发版前照此逐条打勾，全部 ✅ 才执行 deploy**。本清单本身就是流程的保险绳。

---

## A. 发版前准备（本地 osaka-mvp）

- [ ] 代码改动已完成，本地 8765 已**重启**验证（改 core/ 或 web/ 必须重启才生效）
- [ ] 已跑 `tools/sync_to_publish.py`（**必做**！否则账号种子/代码/配置不同步 → 全员密码错误）
- [ ] `config.local.yaml::publish.endpoint` 指向**当前线上域名**（旧域名 404 会让回流/推送静默打空）
- [ ] `grep -rn` 扫过 `tools/` 与配置，无残留**硬编码旧域名**
- [ ] 本次如有功能/修复变更，`core/version.py` 的 `VERSION` 已抬档

## B. 部署（关键：绝不删应用）

- [ ] `deploy` 指向**同一个目录**（复用沙箱 → 子域不变）
- [ ] **不传 appId**（工具按目录推导，删后才新建；我们不删）
- [ ] `domainPrefix` 照传（仅新建 app 才生效，本次不会新建 → 子域保持不动）

## C. 部署后验证

- [ ] 若 `selfcheck` 显示 `running_version` 仍是旧的 → `POST /api/admin/selfrestart`（带 X-Publish-Token）原地刷新
- [ ] `GET /api/selfcheck` 的 `running_version` == 发布包版本号
- [ ] `GET /api/emp/export`（带令牌）计数符合预期：fav 12 / tags 16 / property_tags 30 / customers 8 / customer_properties 23 / customer_tags 14
- [ ] `POST /api/ingest`（带令牌）返回 `ok:true` 且 `total` 正常（≈5723）

## D. 铁律（违反任一条即记事故）

- ❌ **绝不**让用户进 UI「删除应用」来做发版
- ❌ **绝不**主动去换/回收子域（回收 = 再删一次应用，正是要永久避免的动作）
- ❌ **绝不**把不可逆/破坏性操作甩给用户（先想：有没有代码/接口能绕开）
- ❌ **绝不**在未读工具文档、未核实平台真实行为前，把"旧结论"当铁律

## E. 一句话口诀

> **改代码 → sync → 同目录 deploy → 必要时 selfrestart → 验证。**
> **不删、不换、不甩给用户。**
