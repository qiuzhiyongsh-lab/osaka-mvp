## 结论先行（一句话）

本次「让用户进 UI 删应用」「网页地址被换掉」两件事，**都是 AI 的判断错误，不是平台限制**。
根因只有一条：**删应用 = 子域变更的唯一触发点**，且「删应用才能更新代码」是**误判**。
已落地永久机制（v1.9.100）：发版只需「同目录重部署 + 必要时 selfrestart」，**绝不删应用、绝不动地址**。

## 二、关键证据：发布工具官方文档原文

> *"Publishing reuses the target app's recorded sandbox when available, so its **share link stays the same** and the content behind it is replaced."*

含义（逐字落实）：
- **重新部署到同一个目录** → 复用该 app 已记录的沙箱 → **分享链接（子域）保持不变**
- 背后内容（代码/数据）被替换为最新发布包
- **只有「新建 app」时平台才分配新子域**

推论：
- 子域（分享链接）是否变，**只取决于是否新建 app**，与 `domainPrefix` 无关（`domainPrefix` 仅在新建时尝试锁定，平台可无视）。
- 代码是否更新，**取决于平台是否重传了磁盘文件**；若重传成功，无需删应用即可上线。

## 三、永久避免机制（已落地 v1.9.100，暂存发布包，待发版）

在 `web/app.py` 新增两个接口，**发版不再需要用户碰 UI、不再动地址**：

### 1. `POST /api/admin/selfrestart`（主通道）
- 守卫：`X-Publish-Token`（与 `/api/ingest` 同款令牌）；已在 `_access_guard` 豁免白名单
- 行为：进程**原地 `execv` 重启**，重新加载磁盘上的最新代码与配置
- 用途：重部署后若线上进程仍在跑旧代码，调一次即刷新，**零删除、零地址变更、零 UI 操作**

### 2. `POST /api/admin/selfupdate`（极端回退）
- 守卫：同上 `X-Publish-Token`
- 行为：若平台重部署**未替换磁盘文件**，从 `publish.selfupdate_url`（或 `OSAKA_SELFUPDATE_URL`）指向的代码 zip 原地解压 + 重启
- 用途：应对「重部署成功但磁盘代码没变」的极端情况，同样不删不改地址

### 3. 版本
- `core/version.py`：`VERSION` 1.9.99 → **1.9.100**（`BUILD_AT 2026-09-27 11:10`）
- 源 `osaka-mvp` 与 `osaka-house-publish/app_local` 同步抬档
- 新 `app.py` 已 `py_compile` 通过、路由已注册、并复制进 `app_local/web/app.py`

## 四、新发版 SOP（永久 · 任何人执行都照此）

```
① 改代码（本地 osaka-mvp）
② sync_to_publish.py          # 同步 core/web/config + 种子数据到 app_local
③ deploy（同一个目录）         # 不传 appId；domainPrefix 照传（仅新建才生效，本次不会新建）
      ↓ 平台复用沙箱、子域不变
④ 必要时 POST /api/admin/selfrestart   # 若 selfcheck 显示 running_version 仍是旧的
⑤ 验证：selfcheck 版本号 + 数据通道（emp/export、ingest）
```

### ⚠️ 禁做清单（违反即记事故）
- ❌ **绝不**让用户进 UI「删除应用」来做发版
- ❌ **绝不**主动去换/回收子域（回收 = 再删一次应用，正是要永久避免的动作）
- ❌ **绝不**把不可逆/破坏性操作甩给用户（先想：有没有代码/接口能绕开）
- ❌ **绝不**在未读工具文档、未核实平台真实行为前，把"旧结论"当成铁律

### ✅ 必做清单
- ✅ deploy 后必带 `selfrestart` 兜底（防沙箱未重传代码）
- ✅ 任何 deploy 前必重跑 `sync_to_publish.py`（`accounts.seed.json` 是活的，不重跑 ⇒ 全员密码错误）
- ✅ 改完本地 `config.local.yaml::publish.endpoint` 后，同步检查 `tools/*` 里有无硬编码旧域名（本次 `_verify_release.py`/`director_audit.py` 各改 1 处）

## 五、团队铁律（贴在发版流程最前面）

1. **子域是用户的资产，AI 无权变更** — 只有用户本人在 UI 明确说"换地址"才可动。
2. **删生产 app = 最高危操作** — 仅在用户明确要"销毁并重来"时执行，且必须先在发布包打入 employee.db 快照（保员工数据）。
3. **发版靠"同目录重部署 + selfrestart"，不靠删** — 记住文档原文：重发布到同目录，链接不变、内容替换。
4. **动手前先查官方文档/工具 schema** — 不靠 session 记忆里的旧结论拍板。
5. **不可逆操作不甩给用户** — AI 应自己用接口/脚本解决，用户只需在窗口里说"发版"。
