## 一、四个角色各管什么（人话版）

| 角色 | 英文简写 | 管什么 | 人话 | 他说"不行"会怎样 |
|---|---|---|---|---|
| **产品经理** | PM | 做什么、先做什么、给谁用 | 决定往哪走 | 需求不成立 → 不做，或改需求 |
| **研发经理** | RD | 代码怎么写、系统稳不稳 | 把车修好、开得快 | 方案有坑 → 换实现 |
| **UI 经理** | UI | 界面好不好看、好不好用 | 让人用得顺手、看得明白 | 用户看不懂 → 改交互 |
| **测试经理** | QA | 怎么保证不出错 | 出发前检查、路上报故障 | 没验收/没证据 → 不许交付 |

**勇哥（需求方）= 最终拍板人**。四角色是"把关"，不是"代替你决策"。

> **🤝 六个角色怎么相处（2026-09-16 08:45 补充）**：总监与 PM / RD / UI / QA / OPS 是
> **相互协作、共同解决问题**的关系。有分歧不许压、不许拖，**走四步阶梯 24 小时内出结论**，
> 并填**冲突单**留档。详见 `06_协作与冲突解决机制.md`。
> 要点：**谁反对谁带方案**、**冲突不过夜**、**结论必须落字**、**对事不对人**。

> **⚠️ 2026-09-16 增设第 5 个角色：项目总监** —— 不干活，只**回头检查这四个角色有没有真把关**，
> 有缺证据的直接打回。详见 `04_项目总监_检查与把关.md`，体检脚本 `tools/director_audit.py`。
> **每次交付前必跑 `python tools/director_audit.py`，红项不解决 = 没做完。**
>
> **⚠️ 同时增设：运维经理（OPS），由项目总监直接管理** —— 管"交付之后每一天都还能用"：
> 可用性监控、数据链路、备份 3-2-1、变更发布、容量、事故响应、安全扫描。
> 详见 `05_运维经理_职责与工作内容.md`；他的检查项已并入 `director_audit.py` 的【OPS】段。

## 二、标准作业流程（每次改动都走这 7 步）

```
① PM 关：这条需求给谁用？现在痛在哪？做完什么样算好？（写清"验收"）
        ↓ 不过 → 回勇哥确认
② RD 关：动哪些文件？会不会改坏别处？要不要回滚方案？
        ↓ 有风险 → 出替代方案
③ 动手改代码（先 checkpoint.py 备份）
④ UI 关：手机上能看吗？新手看得懂吗？颜色/文案跟现有体系一致吗？
        ↓ 不过 → 改交互再验
⑤ QA 关：拿真实数据跑一遍，把**证据**贴出来（状态码/行数/截图前的数字）
        ↓ 没证据 → 不算做完
⑥ 同步线上（如需）：python tools/sync_to_publish.py → 本地冒烟 → 发布
⑦ 回访：线上真机再验一次，更新 PRD 与本文档的"待办状态"
```

**⚠️ 铁律**：**⑤ 没过不许交付**，"应该没问题"不算证据。

## 三、每个角色的检查清单（Checklist）

### PM 关（做之前先问这 5 个）
- [ ] 这条需求是给 **A 大阪专业人士** 还是 **B 港澳/大陆销售** 的？标签打了没？
- [ ] 有没有写**验收标准**（点什么、出现什么、什么算不对）？没写不许开工
- [ ] 口径定义了吗？（"单价"是㎡还是坪？"降价"跟谁比？）
- [ ] 优先级排了吗？是 P0（错了砸招牌/合规风险）还是 P1/P2？
- [ ] 会不会跟已有需求打架？（查 `docs/PRD/12` 需求池）

### RD 关（写代码时守住这 6 条）
- [ ] 改代码前先跑 `checkpoint.py`
- [ ] 版本号单一来源 `core/version.py`，改完要抬版本
- [ ] `web/app.py` **不热重载** → 改完必须重启 8765 才生效
- [ ] 日期口径只用 `reg_date_iso` / `chg_date_iso`，**绝不用 `first_seen_at`**
- [ ] 排序/筛选/统计一律放**服务端 SQL**（前端排只排当前页 = 错）
- [ ] 线上（OSAKA_PUBLIC=1）**不暴露**：采集/账号/文件/指定下载/PDF 下载/凭据/调度

### UI 关（交付前看这 5 条）
- [ ] 375px 手机宽度下不溢出、点得到
- [ ] 颜色语义一致：绿=新增 / 蓝=平台降价 / 琥珀=待补详情 / 红=错误
- [ ] 四语言文案都补了（i18n.js 简/繁/EN/日）
- [ ] 空状态有引导（查不到 / 抓取中 / 待补详情 三种）
- [ ] 「数据新鲜度」看得见（数据是几点的？超 12 小时要变色提示）

### QA 关（交付必须有证据）
- [ ] 用**真实数据**跑过（不是演示数据）
- [ ] 关键接口有状态码/行数的实测记录
- [ ] 线上/线下不一致时能说清为什么
- [ ] 回归：以前能用的功能没被改坏（至少跑一遍冒烟）
- [ ] 数据质量闸门过了（空值率 / 异常价格 / 坪単価换算 / 修繕積立金合理性）
