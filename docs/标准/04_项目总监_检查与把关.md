# 04 · 项目总监（检查与把关）

> 生效：2026-09-16 01:45 ｜ 应勇哥要求设立
> **定位一句话**：总监**不写代码、不画界面、不替谁决策**，他的活是**回头检查那四个角色有没有真把关**，
> 并且**发现谁没过关就打回去**。
>
> **⚠️ 2026-09-16 08:45 补充（重要）**：总监与另外五个角色（PM / RD / UI / QA / OPS）是
> **相互协作、共同解决问题**的关系，不是"查的与被查的"。
> - 他有三个身份，**最主要的是"协作伙伴"**（帮补位、协调依赖、一起想办法），打回只是最后一步
> - **打回必须同时给出"怎么改才能过"**，否则五个角色有权驳回他
> - 出现冲突走**四步阶梯**（双方沟通 → 总监协调 → 勇哥拍板 → 记录回溯），**24 小时内必有结论**
> - 详见 `06_协作与冲突解决机制.md`（含冲突单模板、决策权分配、五个高频冲突预案）

## 一、总监 vs 四角色（别搞混）

| | 四角色（PM / RD / UI / QA） | **项目总监** |
|---|---|---|
| 干什么 | 各自把事情做对 | **检查他们是不是真做对了** |
| 产出 | 需求 / 代码 / 界面 / 测试证据 | 体检报告 + 打回单 + 风险登记 |
| 权力 | 对自己那关负责 | **一票打回**（任一关缺证据就退回） |
| 不干什么 | —— | 不替他们改、不替勇哥拍板 |

**人话**：四个人是厨师，总监是**试菜的** —— 他说"这盘不行"，厨师就得回锅。

---

## 二、总监查什么（对着四个角色各查一遍）

| 查谁 | 查什么 | 机器能查的（脚本） | 只能人查的 |
|---|---|---|---|
| **PM** | 需求有没有写验收标准？优先级排了没？PRD 和代码脱节没？ | PRD 里「验收」出现次数、⏳/✅ 计数 | 需求是否真解决了用户痛点 |
| **RD** | 版本有没有漂移？**本地改了有没有同步线上**？配置对不对？ | 版本一致性、**同步漂移（md5 比对）**、调度窗口、收数令牌 | 方案有没有更好的写法 |
| **UI** | 对外模式真的收起了本机功能吗？导航/文案一致吗？ | `_public_guard` 存在性、隐藏页清单 | 手机实机观感、新手看不看得懂 |
| **QA** | 有没有真实数据证据？PDF 泄漏？凭据残留？测试呢？ | **PDF 泄漏扫描、凭据残留扫描、数据包新鲜度、用例数** | 回归是否覆盖到位 |
| **OPS**（直属） | 系统还活着吗？备份做了吗？数据推上去了吗？ | **备份新鲜度、磁盘、日志、库体积、推送水位、抓取状态、线上 ping** | 事故复盘质量、容量趋势 |

## 三、怎么查（两条腿）

### 腿 1：机器体检（每次交付前必跑）

```bat
cd C:\Users\25374\WorkBuddy\2026-09-11-09-50-22\osaka-mvp
python tools\director_audit.py
```

退出码：**0=全绿 / 1=有黄 / 2=有红（必须处理）**。

### 腿 2：人工抽检（总监自己动脑）

- 抽查一次真实操作（不是看截图，是自己点一遍）
- 问三个问题：**证据在哪？回归跑了吗？线上验了吗？**
- 三个问题有一个答不上 → 打回

## 四、打回权（总监唯一的"武器"）

| 触发 | 打回给 | 打回理由模板 |
|---|---|---|
| 没写验收标准 | PM | "这条需求做完什么样算好？先写验收" |
| 改了代码没抬版本 / 没备份 | RD | "先 checkpoint + 抬 version.py" |
| 本地改了没跑同步脚本 | RD | "线上还是旧的，跑 sync_to_publish.py" |
| 手机上看不了 / 四语文案缺 | UI | "375px 实机截图拿来" |
| 只有"应该没问题"、没实测数字 | QA | "拿真实数据跑，把状态码和行数贴出来" |
| 红线项（PDF 泄漏 / 凭据残留 / 本机功能外泄） | **立刻停工** | "红线，先修再谈别的" |
